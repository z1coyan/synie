# ADR：个人 API 密钥（不进资源目录、不透明串、密钥不能管密钥）

2026-08-21。AI 参与模式第一阶段只解决「外部程序如何以某人身份进系统」。

- **背景**：浏览器走 httpOnly cookie；`/auth/login` 的 JWT 无独立撤销、无名称、须拿密码签发。把密钥做成 Catalog 标准资源会新开权限点（fail-closed，角色不会自动获得），并被菜单白名单藏起来。长寿命 JWT 无法单钥吊销。
- **决策**：
  1. **不进资源目录**。密钥是认证凭据，不是业务主数据。全体已登录用户自助管理自己的钥，无新权限点、不进菜单目录；入口在用户菜单。
  2. **不透明随机串 + SHA-256 落库**，前缀 `synie_ak_` 在认证三轨（cookie → 个人密钥 → 登录 JWT）里分流。拒绝把登录 JWT 的 TTL 拉长当 API 密钥。
  3. **密钥不能管理密钥**。列表/创建/撤销拒绝 `authMethod=api_key`，被盗的外部凭证不能再签发新钥。
- **理由**：自助面必须对每个登录用户开放，Catalog+RBAC 做不到「人人默认可管自己的凭据」而不破坏 fail-closed；哈希点查可撤销，JWT 不能；管理面与使用面分离把失窃面限制在「当前这把钥」。
- **否决**：密钥级 scopes（第一阶段继承用户此刻授权）；管理员代管他人密钥；argon2 哈希（每请求一次过贵）；把权限快照进密钥。
- **影响面**：`sys_user_api_key` 新表；`platform/auth` 签发与三轨；前端 `/account/api-keys`。业务模块零改动。
