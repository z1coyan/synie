# 订单收发货历史：四类单据行 UNION 只读视图，订单抽屉单 tab 呈现

销售/采购订单抽屉原有的「发货历史 / 收货历史」tab（采购侧收货历史还分组带着委外入库表）合并为统一的**收发货历史**：后端新建只读视图 `scm_order_flow_item`，UNION ALL **采购入库、委外发料、委外入库、销售发货**四类单据行，统一列口径（单据类型/单号/日期/状态＋公司/订单/订单条目锚点＋物料快照/单位/数量），暴露为只读 Ash 资源 `SynieCore.Scm.OrderFlowItem`（grid 资源 `scmOrderFlowItems`），前端两个订单抽屉共用 `OrderFlowHistory` 组件单表展示——比原历史表多一列**单据类型**（入库类绿胶囊、出库类蓝胶囊），按单据日期倒序。委外发料行没有订单条目直接引用，经发料清单行（`pur_order_item_material`）桥接取订单与条目；其快照无客户料号，视图该列恒空。

## Considered Options

- **前端多查询合并**（拒）：采购侧本已堆了两块 grid（入库＋委外入库），再并委外发料就是三套查询前端拼表，排序/分页/筛选都得自造，且每加一类单据（退货）都要改前端；视图方案下加类型＝扩 UNION 臂＋枚举值，前端零改动。
- **以库存分录 `Inv.StockEntry` 当历史源**（拒）：分录是「仓×物料」数量事实，没有订单条目锚点与单据状态，委外发料这类仓间移动还会一单两行，口径对不上「订单履约流水」。
- **新设权限点 `scm.order_flow:read`**（拒）：历史行信息不超出各单据条目页已有口径，新权限点会使存量角色一律看不到历史（须逐角色补授权）；改为「持任一来源单据 read 权限即可读」——`HasPermission` 新增 `code:` 选项直给完整权限码，同 policy 多 `authorize_if` 取或，公司维度照常 CompanyScope。
- **数量带符号区分入出**（拒）：单据类型中文名（入库/发料/发货）已自明方向；正数展示与各单据条目页口径一致，避免「销售发货显示负数」的阅读困惑。退货落地后同为正数＋自明类型名。

## Consequences

- 四类单据行的结构变更（改列/改表名）需同步维护视图；视图本身无约束，靠 UNION 各臂列顺序对齐，改动时以 `SynieCore.Scm.OrderFlowItemTest` 兜底。
- 未来退货单（销售退货/采购退货）落地：扩视图 UNION 臂＋`FlowType` 枚举值＋policies 来源码三处，历史 tab 自动出现新类型，前端胶囊先落 default 灰、配色后补。
- 「发货历史/收货历史」tab 名退出，产品文档（销售订单/采购订单/委外入库）与 docs/术语表.md 术语同步为「收发货历史」。
