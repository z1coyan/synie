# ADR：退货模块——三类退货单、同池净额对账与补货需求生成

2026-08-09，拷问访谈定案。覆盖销售退货（`sal_return`）、采购退货（`pur_return`）、委外退货（`pur_outsourced_return`）三个新模块，及产品文档 [销售退货](../../业务模块/销售退货.md)、[采购退货](../../业务模块/采购退货.md)、[委外退货](../../业务模块/委外退货.md)。

- **定位：与履约单据平级的独立单据，不做「红冲发货单」**：销售退货平级于销售发货、采购退货平级于采购入库、委外退货平级于委外入库；状态机一律 草稿→已审核→（已作废），无反审核/红冲，整单草稿为唯一写边界——全套机制镜像既有履约单据先例。否决「在源单上做退货标记/负行」（破坏发货/入库单的事实性），否决「退货=作废重开」（退货是新的实物事实，不是纠错）。
- **行来源：源单行为主 + 手工行合法**：源单行必挂已审核未作废的源履约单据条目（物料/价税/订单快照随源行带入）；手工行自填物料/数量/**价税**（委外退货除外，见下）——处理系统外历史退货。否决「必挂源单行」（历史退货无锚点可挂，而这类退货恰恰需要退款/冲往来，只放行零金额等于阉割核心价值）。手工行的金额口径 = 手填含税单价+税率，与源单行同进对账池、同口径过账——快照来源从「订单条目」换成「人手」，过账机制不变。
- **对账：同池负金额净额，不开独立对账类型**：退货条目与发货/入库条目进**同一个对账条目池**，混勾在一张对账单里，退货行金额取负，合计=净额。否决「独立退货对账单+红冲发票」——红冲在系统里是发票纠错语义，正常退货冲减不该污染该通道；净额对账是月度结算的实务形态。退货条目自带 `reconciled_qty` 投影（机制照抄发货/入库条目先例），已对账与已退互不干涉。
- **允许负合计对账单与负发票**：纯退货月份可单独成单（合计 < 0），关联发票价税合计相应为负。此处访谈中曾推荐「禁止负合计、纯退货挂起待净额」（避免开启负数发票语义），**用户拍板允许负合计**——取舍：换来纯退货即时确认开票的动线，代价是发票侧需支持负价税合计过账（分录金额随之为负）。
- **已退数量投影 + 退货量上限**：发货/入库条目（含委外）冗余 `returned_qty`（默认单位），退货审核加、作废减；剩余可退 = 数量 − 已退，源单行审核硬校验，手工行不受限。否决「不设上限」（剩余可退无从查起，且对账净额可能出现退货金额 > 发货金额的荒诞形态）。已退与已对账互不干涉（已确认对账的货仍可退，冲减走后续净额）。
- **订单投影回减，需求行不反转**：挂源行的退货审核回减订单条目已发/已收数量（未发/未收缺口重现，可照常再发货/再入库，超发超收校验口径内）；但沿「订单条目→需求行」的已完成**不反转**——需求行保持已完成，退货后的补货由人工判断或补货按钮发起。否决「链路自动反转」（曾推荐），用户拍板保持投影单向：避免入库正向回写链路引入逆向分支。
- **销售占用口径修正：订购 + 已退**：需求行占用上限从「订购 base」修正为「订购 base + 该条目已审核销售退货量（挂源行部分）」——否则补货需求行在现行口径下永远撞墙（订 100 占 100 退 20，补 20 即 Σ120 > 100）。语义 = 客户仍被欠着的量；无退货时退化为现行规则。否决「补货行走手工行绕开占用」（丢订单溯源）与「补货标记豁免占用」（规则开特例）。校验时点不变（确认时），不为「退货作废导致既有需求超限」新增拦截。
- **补货需求生成：仅销售退货、整单一钮、产出草稿**：已审核销售退货单单头「生成补货需求单」按钮，把全部退货行转成一张履约需求单草稿（源单行来源=销售订单条目，手工行=无来源手工行，需求日默认=退货日期；可重复点击、单头留链接，超量由确认时占用校验兜底）。否决「行级按钮」（无场景，草稿内删行即可）与「审核时弹窗询问」（仓管不是决定补货的人，不替计划员做决定）。采购/委外退货**不放**按钮——供应商/委外商重送即可，已收回减后缺口自然重现，无需内部需求单驱动。
- **委外退货是纯数量单（本模块最大的不对称）**：无金额、无表底科目、不过总账、不进对账；审核只写成品负向库存分录 + 已退/已收回减。否决「全镜像委外入库反转」（材料回补外协仓 + 副产物退出 + 加工费冲减）——用户定调「成品退回去修好就行，材料已消耗」；且材料扣减本就只有数量口径（金额随库存估值推迟），退货侧无金额可镜像。配套**已对账拦截**：源入库条目 `reconciled_qty` > 0 禁止退货（须先撤回/作废相关采购对账单）——纯数量单无对账负行可冲，靠拦截保证同一批成品的加工费只对账一次（返修送回后照常委外入库计费）。
- **收发货历史按既有预留扩臂**：退货三类 = `scm_order_flow_item` 视图扩 UNION 臂 + `FlowType` 枚举值 + policies 来源码三处（ADR 2026-07-25 已预留此扩展点），前端零改动。
- **杂项定案**：销售退货不做装箱清单（退回实物清点直接成行）；三类退货单编号各自独立系列（镜像委外入库先例）；权限码 `sales.return` / `purchase.return` / `purchase.outsourced_return`；菜单 销售管理→交易→销售退货、采购管理→交易→采购退货、采购管理→委外→委外退货；含手工行的销售/采购退货单头带原币与汇率（默认本币）作全单换算口径。
