# ADR：预置角色放开编辑——系统保护收窄为仅 admin

2026-08-10。

- **背景**：ADR 2026-07-29 把内置角色（admin/sales）定为「不可删、不可停用、授权只读」。实践暴露两个问题：预置的授权清单跟不上业务演进（如退货模块上线后 sales 角色补不了 `sales.return`，只能绕开预置角色另建）；「不可删」让预置角色成为甩不掉的死重。
- **决策**：`sys_role.builtin` 的语义从「系统保护」收窄为「预置身份」。系统保护仅余 **admin**（`builtin AND code='admin'`）：不可改、不可删、不可停用、授权与菜单白名单只读。其余预置角色（sales）初始化后与普通角色完全同权——可改名、可停用、可删除、授权与菜单可维护。取代 ADR 2026-07-29「内置角色守卫（不可改删、授权只读）不变」一条。
- **不变量保持**：全域通配 `*` 仍仅种子可写——授权 sync 逐码校验权限目录（`allPermissionCodes()`），`*` 不在目录内，预置角色可编辑也写不出全权角色；admin 的 `grants_all` 旗标行不受影响。
- **理由**：预置角色的价值是「初始化即可用」的起步模板，不是冻结的基线；保护 admin 一个即可守住「永远存在一个全权角色」的底线（super_admin 用户旗标仍在，双保险）。数据零迁移：守卫按 `code='admin'` 判定，存量 `builtin=true` 的 sales 行自动获得可编辑性。
