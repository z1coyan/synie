# 单据编号一律系统生成：仅公司/客户/供应商保留手填编码

此前系统的编号语义是"留空按编号规则自动取号，手填原样保留"——每张单据都向用户开放手填编号。手填带来三个持续成本：编号风格随录入人漂移（下游按文本前缀解析的报表与计数分桶被污染）、唯一性靠用户在撞号报错后自行换号、以及"这张单的编号到底什么口径"在每篇功能说明书里都要单独交代。决定：**除公司、客户、供应商外，所有挂编号规则的表单编号一律由系统按启用规则生成，不接受手填**；会计科目、物料分类等无编号规则机制的主数据编码维持手填（它们的编码有外部语义，如科目编码受会计准则习惯约束，不是单据编号）。

**服务端 fail-closed**：create 链路唯一取号入口是编号服务的 `assigned/assignedInTx`——传入非空编号值一律 422（"编号由系统生成，不接受手填"），不做静默覆盖；编号创建后不可改（update 传不同值 422，传相同值容忍幂等 PATCH）。前端不在各页面分别遮挡，而是把编号字段在 meta 标 `readonly`（物料先例），meta 驱动的表单自然不再出现可输入的编号框。曾考虑过"静默忽略手填值"，被否决：悄悄吞掉用户输入在审计语义上不干净，且系统未上线、没有需要兼容的旧客户端。

**无启用规则 = 硬阻断**：停用/删除规则不加"最后一条启用规则不可动"的保护——同一资源只能启用一条规则，"停旧启新"是换规则的正常路径，禁止停用会把它堵死；保存时报错文案直接指出配置入口（"未配置启用的编号规则，请先在 系统管理 → 编号规则 配置并启用"），管理员可自助恢复。

**仓库/部门升入自动编码**：仓库此前没有编码字段（本次新增 `inv_warehouse.code`，公司内唯一），部门编码此前手填且可改。两者编码均为系统生成、公司内唯一、创建后不可改；预置规则为 `B(W)-` / `B(D)-` + 4 位补零序号、按公司分桶、不带日期段（主数据编码求稳定短小，与单据的日期段形态区分）。这两条规则由**迁移**（00022）而非 setup 向导播种——初始化向导的首张公司创建早于 setup 完成（completeBaseSeeds 才播单据规则），而公司创建同事务要种子默认三仓并取号，规则必须先于向导存在；setup 的种子清单保留同口径条目幂等兜底。计数器自增在业务事务内完成（`INSERT ... ON CONFLICT`），事务回滚即释放号码，不会因回滚断号。

**手填三例外的格式锁**：公司/客户/供应商编码会渗入系统编号机制——客户编码作为段嵌入物料编号（`F(P)77-1` 中的 `77`），公司编码是按公司计数器分桶键（`{公司编码}|{前缀}`）的组成。手填编码若含分隔符或空白，两个不同主数据组合可能渲染出相同分桶前缀而静默共享序号序列。因此客户/供应商编码限 `^[A-Za-z0-9]+$`（422 拒绝），公司编码维持既有"恰好两位英文字母"校验。

**公司级单据单号放宽为公司内唯一**（迁移 00023）：实施中发现存量设计的一个本质冲突——计数器按 `{公司编码}|{渲染前缀}` 分桶，但渲染出的单号不含公司码，而 16 张公司级单据表的单号列挂着全局唯一索引；两家公司同日开同种单会渲染出同一个号，第二张必撞 23505（手填时代靠人工换号规避，系统生成后此路不通）。唯一索引一律放宽为 `(company_id, 单号)`，对齐 `acc_*` 四表既有先例；备选"编号嵌入公司段"（格式变长、读感差）与"规则改全局计数"（放弃按公司计数的既定默认、公司间互见开单节奏）均被否决。一并修复的存量键名错配：履约/发票/承兑交易/费用报销的取号 `values` 键与预置规则引用的字段名不一致（如服务传 `document_date`/`posting_date`，规则段引用 `delivery_date`/`invoice_date`），导致日期段静默渲染为空（`S(D)--0001`）——空前缀进一步放大了撞号面。

员工编号随大流转系统生成不受影响面：考勤机匹配走独立字段 `attendance_no`（考勤设备编号），不依赖员工编号；考勤导入自动建档本就走自动取号。系统未上线，无存量数据迁移负担（开发库 reset 即可）。
