# ADR：权限判定收束为封闭谓词代数

2026-08-04。规格见原 `.scratch/authz-rewrite/spec.md`（已删除，见 git 历史；grill-with-docs 定案；取代同日作废的 data-scope-ladder 方案）。

- **背景**：授权维度只有「权限码（含通配）× 公司集合」，行级能力（部门/本人）无处安放；约 498 处检查散布服务层，「能否碰这家公司」有 4 种写法 2 种 HTTP 语义；全部散布检查可折叠为 9 种判定形态。系统在开发期，不做兼容。
- **决策**：授权判定词汇表收束为**封闭集，未来一切权限需求不得新增谓词**：
  1. **三层词汇**：主体（user/system/superAdmin）× 码级组合子（one/anyOf/allOf）× 行级范围（all/company/deptTree/dept/self/granted + via 组合子）。
  2. **有效行集 = 公司边界 ∧ 授予范围并集**；范围格 `self ⊆ dept ⊆ deptTree ⊆ all`，granted 正交并联；授权粒度为「角色 × 权限码 × 范围」三元组（表达力优先，UI 后深化）。
  3. **封闭性靠三个泄压口**：新需求只落进主体侧计算（岗位/代理人改 Actor 装配）、对象侧显式授权（granted + `sys_record_grant`，设计定案实现缓行）、派生资源（via 声明递归宿主判定），不产生新谓词。
  4. **部门维度**：部门挂公司、用户单部门（兼任再演进）；dept 谓词单列绑定、两形态——归属部门（创建盖章缺省）/ 指派部门（业务列，如需求单下发车间；填写不受操作者部门约束）。定案场景：需求单头级下发冲压车间，车间生产经理 scope=dept 排产。
  5. **通配符全部取消**：精确码匹配 + 内置 admin 全域授权旗标；三份 candidates 实现删除。
  6. **划界**：状态前置条件（~60 处 conflict）、内置角色冻结、目录闭包、字段敏感性均**不属于**权限系统。
  7. **错误语义唯一规则**：码不满足=forbidden；行级不命中（公司/部门/本人）=not_found（不泄露存在性）。
  8. **元数据化**：资源在 `ResourceMeta.authz` 声明公司域/全局/派生与 owner/dept 绑定列，注册期强制、seal 校验、目录投影 supportedScopes——授权矩阵按声明渲染，行级列按需生长不做全库加列。
- **理由**：9 种现存形态在该代数下全部有归宿（含文件三套语义、todo 注册表析取、打印动态动作码等 14 处裁量守卫）；封闭词汇表使前后端可用同一份 decide fixtures 对拍、行级 UI 判定可本地求值；通配取消后匹配退化为精确查找，矩阵无半覆盖态。
- **不变量**：公司授权维持用户级、fail-closed，恒为行级范围的外层边界；超级管理员语义不变；菜单权限（纯呈现层）不受影响。
- **影响面**：`sys_role_permission` 加 scope、`sys_role` 加全域旗标、新建 `sys_department`、`sys_user` 加部门列；全部业务模块按批次扫荡迁移（工单原见 `.scratch/authz-rewrite/issues/`，已删除）。
