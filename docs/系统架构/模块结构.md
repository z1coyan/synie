# 后端架构模块

产品后端是 Bun + Hono + Kysely（`server/`）。分层意图仍是 platform / engines / 业务域分离：平台不 import 业务域，事实引擎不 import 业务域，单据经引擎写事实表。目录与命令以 `server/README.md` 为准。历史 Go 树见 git tag `server-go-final`。

术语定义仍以 `docs/术语表.md` 为准。

## 设计原则

- 模块的 Interface 同时是调用面和测试面；HTTP handler 不承载领域规则。
- 平台模块不 import 业务域或事实引擎；事实引擎不 import 业务域。
- 跨域读取只有确有生产、测试两个 Adapter 时才建显式 Seam。
- `engines/gl` 与 `engines/inventory` 是写事实表的唯一入口；单据在同一事务中调用引擎并更新受控投影。
- Resource Catalog：未知资源、未知字段、未知动作均 fail-closed；Grid 与基础 Form 从同一份按 Actor 投影的 ResourceDocument 派生。目录不执行领域写入，已接受取舍见 [`2026-07-30-resource-catalog.md`](adr/2026-07-30-resource-catalog.md)。
- 动态列表只由 Meta 白名单驱动的参数化 predicate builder 生成。

## 目录与依赖

```text
server/
├── src/
│   ├── index.ts                 # 入口：env、DB、装配、Bun.serve
│   ├── composition.ts           # 服务图组合根（生产与测试共用）
│   ├── app.ts                   # Hono 装配 + ApiType（hono/client 事实源）
│   ├── platform/                # 横切：不 import modules/*
│   │   ├── http / auth / authz
│   │   ├── meta                 # Resource Catalog / Registry
│   │   ├── standard             # 标准动作 + 聚合草稿
│   │   ├── posting              # 跨域单据共享基元
│   │   ├── audit / numbering / settings / files / printing / todo / setup / menu
│   ├── engines/                 # gl / inventory
│   ├── modules/                 # 业务域
│   │   ├── base / party / iam / accounting / finance
│   │   ├── inventory / trading / scm / manufacturing / hr / setup
│   ├── db/                      # Kysely、事务、filterbuild、生成类型
│   └── jobs/                    # 后台作业（行情调度、文件对账等）
└── db/
    ├── migrations/              # SQL 迁移
    └── migrate.ts
```

允许的依赖方向：

```text
index / composition / app → modules → engines → platform / db
                              └───────────────→ platform / db
                       └──────────────────────→ platform
```

禁止：

- `platform → modules|engines`
- `engines → modules`
- `modules/A → modules/B` 的环；跨域协作经显式参数、组合根编排或已证明需要的 Seam
- HTTP handler 直接写业务表、总账分录或库存分录
- 单据绕过引擎直接写入总账分录或库存分录

## 核心横切

### Auth / Authz

输入用户名、密码和登录桶，输出 JWT 与会话用户。密码不存在与密码错误走相同 argon2id 校验路径；同一用户名+IP 在 5 分钟窗口内失败 10 次限流。JWT 使用 HS256，有效期 7 天；密钥只来自 `AUTH_SECRET`。

请求认证解析 JWT 后，每次从数据库构建 Actor；不把权限和公司范围固化进长期 Token。

`Actor` 含用户、超级管理员、全公司、权限与公司范围。`HasPermission` 按具体码、资源通配、域通配、全域通配依次匹配；nil Actor 与未知权限 fail-closed。服务层只收 Permit 凭证。

### Resource Catalog

> ResourceDocument、ResourceBinding、基础 Form、Presentation Extension、聚合草稿 Adapter 与 CommandAdapter 已落地；基线由 `server/scripts/resource-catalog-baseline.ts` 维护。

所有业务模块的资源定义只在组合根显式注册一次；注册完成后 Catalog 必须 seal。Catalog 从权威 `ResourceDefinition` 投影带版本的 `ResourceDocument`，按 Actor 裁剪字段与 capabilities。

前端单独获取并缓存完整 ResourceDocument。HTTP 只暴露实际存在的 query/get/create/update/delete；聚合草稿和领域命令分别绑定 Adapter，不提供万能 fallback。新增资源接入点见 [资源接入.md](./资源接入.md)。

### 标准动作与聚合单据

定案：[`adr/2026-08-06-standard-actions-kernel.md`](adr/2026-08-06-standard-actions-kernel.md)、[`adr/2026-08-07-aggregate-document-kernel.md`](adr/2026-08-07-aggregate-document-kernel.md)。

- 平坦主数据：`createStandardService`（+ 可选 tree/workflow）。
- 聚合单据：头 + 子行经 `createAggregateService` 派生整单草稿三连；跨资源效果进 workflow transition，不进聚合钩子。
- `platform/standard` **禁止** import `modules/*`。

### platform/posting（跨域单据共享）

原过账骨架已删除，活编排吸收进各域 workflow transition effect。领域基元落此目录，**不**新建 `platform/domain-primitives/`：

| 文件 | 职责 |
|------|------|
| `material-qty.ts` | 物料口径：base_qty 折算 + 物料快照 |
| `warehouse.ts` | 仓库校验：叶子/同司/启用/外协绑定 |
| `controlled-projection.ts` | 受控投影增量累加器 |
| `text.ts` | 杂项文本/字段辅助 |
| `account-currency.ts` | 借贷科目币种解析 |

铁律：`platform` **不** import `modules/*`；基元 SQL 自持，领域副作用由调用方注入。

## 业务域（`modules/`）

| 域 | 职责 |
|----|------|
| `base` | 公司、币种、单位、科目、行情 |
| `party` | 客户、供应商、员工、地址 |
| `iam` | 用户、角色、部门、授权与菜单 |
| `accounting` | 手工凭证、总账分录查询、应收应付报表与往来明细 |
| `finance` | 发票、承兑、银行、报销、财务设置、OCR |
| `inventory` | 物料/分类/仓库、其他库存单、库存分录与余额 |
| `trading` | 销/采报价与订单、发货/入库、对账、退货、委外三单 |
| `scm` | 订单收发货历史等跨销采只读投影 |
| `manufacturing` | BOM、履约需求、工单、生产入库、模具、生产设置 |
| `hr` | 考勤、工资、借款 |
| `setup` | 初始化向导与示例数据 |

公司创建时默认三仓种子由库存仓库模块在同一事务内完成。
