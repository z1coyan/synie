# 装箱箱实体与重量口径

销售发货的装箱清单原先只有平铺装箱行（行上自由文本 `box_no`），装箱单所需的净重/毛重无处安放。定案：**箱升格为实体**（`sal_delivery_pack_box`：单内系统自增箱号不可手改＋箱净重只读＋箱毛重手填＋重量单位），装箱行挂箱并新增**行净重**（该行总净重）；行净重默认按「数量 × 物料重量类单位转换行」推导、可手改实测，有推导来源时数量变化即无条件重算；重量全部可空、审核不拦。单位净重知识**复用现有单位转换机制**（`inv_material_unit` 跨类型换算，如「1 件 = 2.5 kg」），不设专设字段。配套否定性决策：**不建皮重概念**（毛净差隐含为包装）、**实测重量不回写物料换算**（单次实测 ≠ 标准单位净重，且仓管无物料主数据权限；建/改换算走主数据维护动线）、**行级重量单位不可手改**（随推导来源或重量基准单位，仅箱级单位可改）。打印侧发货单保留 `pack_lines` 平铺循环区、箱字段走 belongs_to 一层展开，另加 `pack_boxes` 独立循环区，打印引擎不升级为嵌套循环。

## Considered Options

- **箱保持平铺、毛重冗余存同箱各行**（拒）：箱有了自己的字段（毛重）、动作（添加箱子/删箱）与校验规则时已是实体；冗余存储需处处加「同箱毛重一致」防御校验，本质是用校验模拟没建的实体。
- **物料主数据专设「单位净重」字段**（拒）：与单位转换并存会使同一事实两处各说各话；复用转换行则按重量成交的物料（铜材/线材）同一条换算可直接用于交易单位，一套事实两处用。多条重量转换行并存时不猜、行净重默认空手填。
- **保存时提示把实测净重回写为物料换算（含无换算时反推系数新建）**（拒）：单次过磅含包装/批次/秤误差，不等于标准单位净重，回写制造主数据噪音；录装箱的仓管通常无物料主数据权限，提示是死按钮。
- **行净重手改后钉住、数量变化不重算**（拒）：行净重是该行**总**净重，数量变了总量几乎必然变，重算覆盖反而是救用户；实测手改的作业纪律是数量定稿后再录。无推导来源时无重算依据，手填值保持不动。
- **打印引擎升级支持嵌套循环**（拒）：发货单→箱→行的嵌套版式用「行平铺＋箱字段 belongs_to 展开＋独立 `pack_boxes` 循环区」即可在 Excel 模板内排出，符合「版式归 Excel、引擎不发明格式化」既定哲学；为单箱单版式升级横切打印设施成本不成比例。

## Consequences

- 原装箱行 `box_no` 自由文本列退出，行改挂箱实体；系统仍在开发阶段未上线，直接 reset 重建，不做存量迁移。
- 「从装箱清单获取」发货条目的按物料汇总/FIFO 分摊逻辑不受影响（口径仍是装箱行 base 汇总）。
- 审核的「全有或全无」数量校验口径不变，重量不参与审核硬校验。
- 按重量成交的物料报价/开单能力随重量转换行自然获得，无需另行设计。
- 将来若需箱级页眉页脚版式（每箱一节），再议打印引擎嵌套循环升级，届时纯加能力不破坏本期口径。
