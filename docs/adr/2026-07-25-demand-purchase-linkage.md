# ADR：履约需求与采购/委外串联（勾选带入 + 入库回写闭环）

2026-07-25，拷问访谈定案（grill-with-docs）。偿还 ADR 2026-07-24「外购/委外自动建单留作纯增量」的债。

- **采购侧拉，拒绝需求侧推**：采购/委外订单编辑表单内「从需求单勾选」带入条目，条目挂**来源履约需求行**（可空，手工行不受影响）。拒绝需求行上一键生成——采购的天然动作是按供应商合并、选对手、谈价勾报价，需求行上无供应商信息，推出来的是空头碎单；拉的模式与「销售发货勾订单条目」「委外发料挂发料清单行」先例同构。
- **一条目挂一需求行，同需求行可分次被引**：行级引用是投影与勾稽的唯一锚点；拒绝多需求行合并成一条目（m-n 锚点），拒绝「一需求行至多一张未作废订单条目」（采购分批下单太常见，拆批语义属计划层，不该打扰）。
- **草稿不占量，确认/审核才占量（全系统统一口径）**：需求行「已下单数量」投影只认已审核未作废订单（审核加、作废减）；**销售占用同步改为「草稿不占、确认占量、作废释放」**（推翻 ADR 2026-07-24 的含草稿占量）。哲学统一：草稿是私有工作区，不产生系统级效应。
- **草稿引用不锁上游，审核复核**：草稿采购订单引用需求行不挡需求单作废/改履约方式；下游约束（需求单不可作废、行不可改履约方式）只认**已审核未作废**的采购/委外订单条目。订单审核时复核来源需求行存在、所属单已确认未作废未关闭、行未完成、履约方式匹配、超下单容差——同销售发货审核复核订单状态先例。
- **履约方式严格匹配**：普通采购订单只勾「外购」行、委外订单只勾「委外」行；拒绝勾选时跨界自动改方式——需求行确认后锁口径是 ADR 2026-07-24 定案，采购侧不开后门。
- **完成靠入库削量回写，不靠点完成**：采购入库/委外入库审核沿「入库条目→订单条目→需求行」回写需求行**已收数量**，累计已收 ≥ 需求数量则需求行自动已完成——对称生产入库完工回写先例，四条履约方式完成语义统一为「实物（或计划放弃）闭环」。手工点完成保留但仅限尚无已下单量的行；已下单后想放弃走作废/关闭采购订单。拒绝「下单即完成」（实物未回就断链）与「维持纯手工点完成」（串联只剩半功能）。
- **需求超下单比例**：新全局容差（默认 0 禁超、0～100%，落 `sal_setting`，供应链设置采购 Tab），审核硬拦、草稿不卡——同超发/超收/超入三兄弟，为供应商起订量超计划需求留受控出口。
- **需求日落条目可空字段**：带入自需求行，纯展示不驱动逻辑、不校验早晚；拒绝拼进行备注（无先例、污染备注语义）。
- **委外 BOM/清单不自动代入**：带入只落物料+数量+需求日+来源，BOM 由采购员按现有机制手选——一物料可多张 BOM，「唯一一张就自动选」会制造隐蔽行为分叉。
- **权限不新增资源码**：勾选池查询挂 `purchase.order` 自身权限、只暴露带入所需字段，采购员不开需求单读权限。需求行列表加派生「已下单」徽标（不落库，同报价「已过期」先例）。
- **明确不动**：库存履约方式维持手工点完成；委外发料/委外入库的材料扣减与副产物机制原样；常规/零星订单类型与价格机制原样。
