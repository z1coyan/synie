# 履约需求单：指派路由放单头（指派类型），不放行级

履约需求单从"生产待办"演进为公司内部物料需求路由后，需要一个"这张单由谁消化"的分派口径。决定：单头新增必填**指派类型**（采购/生产/库存/关闭，委外归采购侧），类型=生产时下发车间必填、其余类型必须为空；审核后随下发车间走 dispatch 动作改派。指派类型是纯**意图层**路由声明——不占量、不约束行级**安排**（行仍可混用生产/采购/委外/库存/关闭五类），类型=关闭不联动状态机。

备选方案是行级指派（每行各自指派类型+目标车间，单头下发车间删除）。被否决的原因：下发车间（`assigned_dept_id`）是该资源的部门数据范围绑定列，"车间只能看到下发给本车间的需求单"现成成立；行级指派需要重写为"行里有指派给本车间的行即可见整单"，还要在抽屉内按行裁剪可见性（半张单可见），机制成本远大于收益。混去向场景用拆单解决——系统本就支持同一销售条目拆多行多单。

附带的刻意保留：需求行快照复制物料图纸挂接**仅作行内展示**，生产工单创建时图纸仍从物料主数据取、不回需求行取——快照冻结链在图纸这一环是断开的，这是有意取舍而非遗漏。
