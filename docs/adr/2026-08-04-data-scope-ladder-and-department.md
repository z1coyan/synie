# ADR：数据范围阶梯与部门主数据（行级权限地基）

2026-08-04。

- **背景**：履约需求单需要支持「委派」——计划员把需求行委派给车间（金具/冲压）或采购，且委派给采购的需求单对其他采购员、车间等**不可见**（参与人之外互盲）。现状权限体系只有两层：扁平权限码 + 公司级数据范围（`companyScopeWhere` / `requireCompanyAccess`），**没有任何记录级可见性机制**；系统也无任何组织实体（`sys_user` 与 `hr_employees` 互不关联，员工表无部门字段）。定案：需求单改造暂停，先打权限地基（本篇），委派业务随后单独立项。规格见 `.scratch/data-scope-foundation/spec.md`（grill 定案）。
- **决策**：
  1. **行级可见性收口平台层**：新建范围策略注册表（`platform/authz/scope.ts`）——策略是纯函数 `(actor) => WHERE 片段`，按资源注册、按维度 AND 组合；所有列表查询经 `listFromSource.extraWhere` 走注册表，所有单条读取经统一 `requireRowAccess`（fail-closed，不可见 = not_found，对齐公司闸门先例）。业务代码对策略零感知，只调用闸门。**不走 Postgres RLS**（actor 上下文与 Kysely 参数化查询全在应用层，RLS 是另一个量级的迁移）。
  2. **现有公司范围迁入注册表**，成为第一个策略维度——注册表自交付起即有真消费者，全部调用点改道属行为不变的纯重构，由现有测试网兜底。
  3. **权限语言保持扁平码，条件永远留在领域数据**：可见性条件（类型、车间、采购……）是委派等业务动作产生的普通数据，策略函数翻译成 SQL；**拒绝** ABAC 策略语言（Cedar/OPA 类：策略即配置失去类型检查与单测，此规模下杀鸡用牛刀）与把条件编码进权限码字符串（码空间爆炸、腐蚀通配匹配）。
  4. **读权限三档阶梯**：`read`（参与人范围：我创建的/指派给我的）< `read_dept`（部门范围：本部门**及下级**部门成员）< `read_all`（全范围，即现状语义）。判定取已授予码中**最宽一档**；通配（`资源:*`、`域.*`、`*`）蕴含 `read_all`，与 `candidates()` 现有逻辑兼容。条件不进码，码只选档。
  5. **`read` 重定义为最窄档**（光杆 `read` = 参与人，非全范围）：阶梯按资源**逐个生效**——未注册阶梯策略的资源 `:read` 行为与今天完全一致；某资源接入阶梯的那一刻其 `read` 才收窄。系统未上线、无存量包袱：不写数据迁移，内置角色种子的 `read_all` 补授跟随第一个接入阶梯的资源（需求单改造）同窗完成。
  6. **部门主数据**：`sys_department`（code 唯一 + name + `parent_id` 可空自引用成树，保存防环）；范围语义「部门」**恒含下级**（递归 CTE，部门表极小），不做「仅本部门」档——有平级保密需要的资源应使用参与人范围而非部门范围。有下级部门或有成员的部门**禁止删除**；本期不做停用/启停状态机。
  7. **部门挂用户**：`sys_user.department_id` 可空**单列**（一人单一部门）；无部门用户的部门范围**退化为参与人范围**（fail-closed 方向，非报错非全量）。用户↔员工档案打通后置（车间工人无账号，对权限系统本就不存在）。
  8. **本期交付边界**：部门主数据 + 维护界面（`sys.department` 权限码 + `menu.system.departments`）、用户表单挂部门、范围策略注册表落地（公司范围迁入）、三码约定与目录派生机制；**不接任何业务资源上阶梯**（第一个真消费者是随后的需求单委派改造，策略形状由真实需求校验，不凭空猜错）。
- **理由**：收口注册表使「新维度 = 新策略函数」而非「每张表散写过滤」，将来换规则引擎（策略即配置）也只动这一间屋子；三档阶梯让角色配置界面保持现状形态（勾码），复杂度关在策略函数里（可测试、可 review）；`read` 重定义 + 按资源逐个生效把破坏性降为按需发生；部门恒含下级用一条规则覆盖「上级统管」场景而无需第四档；单一部门可空列以最小模型覆盖组织现实，升级成员表是纯增量迁移不推翻结构。
- **不变量**：本期交付后业务行为**零变化**（无资源接入阶梯）；权限码通配语义、`candidates()`、公司数据闸门 fail-closed 口径全部不变；菜单权限（白名单）与数据范围继续正交——一个管导航入口，一个管数据行。
- **影响面**：新表 `sys_department` + `sys_user` 加列；`platform/authz/scope.ts` 新建、`db/list.ts` 公司闸门调用点收口；资源目录支持按资源派生阶梯三码；系统管理新增部门页与用户表单字段；`CONTEXT.md` 新增「部门」「数据范围阶梯」词条并更新「菜单权限」词条中「行级权限保留」的指向（实现落地时同步）。
- **演进路径**：需求单委派改造（行级委派、单级可见性派生、委派目标形态——部门/人——届时定）为阶梯第一个消费者；更远的多维度组合（区域/产品线）= 注册表加策略函数，业务调用点不动；「金额超 X 需审批」类是流程规则，**不进**本层。
