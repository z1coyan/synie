# 物料列统一富单元格：快照文本严格、图纸可回退的不对称口径

全系统用到物料的只读表格此前各行其是：编号/名称/规格/客户方编码分散为多列，图纸靠 `attachmentImages` 虚拟列另起一列，列多且辨认物料靠脑内拼合。定案：**所有只读/半只读表格的物料收敛为单个「物料」富单元格列**（`web/app/components/synie-material-cell/MaterialCell`）——左 40px 图纸缩略图，右侧「编号 名称 / 规格 / 客编」三行（空值整行省略），编号点击开物料全局速览抽屉（复用 FkPreviewProvider），缩略图点击全屏预览；撤掉的规格/客编列在 meta 保持 `filterable` 使表格全局搜索框仍覆盖四字段，列排序映射 `materialCode`。物料选择器/挑选对话框不适用（选择场景重检索密度）。

数据口径是有意的不对称：**文本四字段（编号/名称/规格/客编）严格取行上快照值，空值不回退物料主数据**（与 CONTEXT.md 快照语义一致，防历史单展示被主数据变更篡改）；**唯独缩略图允许回退**——行有快照图纸挂接（`sys_attachment`）优先用挂接首图，无挂接（报价/库存/制造类行）回退物料主数据当前第一张图纸，仍无图显示占位图标。图纸只是「认出这是什么料」的识别辅助而非单据事实，且报价/库存类行本无图纸挂接，不回退则这些表的缩略图位永远空白、组件形同虚设。

取数选**前端行级查询**而非后端投影：复用 `AttachmentImagesCell` 的附件 queryKey 缓存（同物料跨行去重、30s staleTime、与附件面板联动刷新），零服务端改动；代价是每页多若干去重后的小请求。逐页接入为机械操作（撤列 + override + extraFields），约定已写入 `web/AGENTS.md`。

## Considered Options

- **保留多列、只富化物料编号列**（拒）：信息重复展示，表格依旧过宽，与移动端卡片模式冲突。
- **文本字段空值也回退主数据**（拒）：与编号/名称必须严格快照的口径自相矛盾，历史单展示随主数据漂移，审计视角不可接受。
- **图纸也不回退（严格快照到底）**（拒）：报价/库存/制造类行永远无缩略图，识别辅助价值归零；图纸挂接本就是快照的一部分，回退仅发生在无挂接的行。
- **后端投影 thumbnailFileId / 新增批量首图接口**（拒）：前者要逐资源改服务端查询与 meta 且新资源易漏，后者引入与现有附件缓存平行的第二套体系；行级查询在现有缓存机制下成本已够低。

## Consequences

- 各条目网格的 `attachmentImages` 图纸虚拟列随之撤销（缩略图点击即预览当前来源全部图片，能力被物料单元格吸收）；抽屉内附件面板仍是图纸管理入口。
- 合并列后规格/客编不再有独立列筛选/排序（全局搜索覆盖）；物料列排序=物料编号，列筛选经 DataGrid `filterField` 代理改按 `materialId` 外键（fk 选择器），快照行的筛选口径仍是物料本身而非编号文本。
- 新接含物料的只读表格须遵守 `web/AGENTS.md` 物料列约定；行无 `materialId` 时编号退化为纯文本（不开速览）。
- 无图纸挂接的行展示的是物料**当前**图纸而非历史图纸——审核历史单时图纸可能与当时不同，属已接受的取舍。
