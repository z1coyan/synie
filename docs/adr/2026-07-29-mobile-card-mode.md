# 移动端卡片模式：SynieDataGrid 小屏切换为 Meta 驱动卡片流

SynieDataGrid 此前对移动端的支持仅是横向滚动（`contentClassName="min-w-[720px]"`），手机上 10+ 列的 ERP 列表基本不可用。定案：**视口 < 1024px（Tailwind lg 以下）时 SynieDataGrid 自动切换为「卡片模式」**——同一 GridMeta 驱动的卡片流，替代小屏 DataGrid。移动端定位为**读为主 + 轻操作**：列表浏览/搜索/筛选、详情查看、审批/确认类行内动作；建单/编辑/批量/导入导出/打印回桌面。机制全部收敛在 `synie-data-grid` 组件内，30+ 资源页面零改动。断点用 `useMediaQuery('(max-width: 1023px)')` JS 分支（两形态结构差异大，纯 CSS 做不到；断点对齐仓库统一的移动断点 `lg`——实现时发现 `web/AGENTS.md` 约定「桌面/移动断点统一为 lg(1024px)」，故从原定的 md(768px) 改为 lg，竖屏平板一并进卡片模式，与详情抽屉 `lg:w-[480px]` 的小屏全屏同断点），page/filters/sort/search 状态两形态共享，切换不丢上下文。

关键子决策：

- **卡片字段约定优先**：第 1 列=标题、第 2 列=副标题、第 3–5 列=摘要行（enum 自动胶囊、datetime 短格式）；`ColumnOverride.mobileRole`（`'title'|'summary'|'hide'`）作逃生口，零配置时 80% 列表可用。
- **筛选/排序入口**：工具栏变「搜索 + 筛选按钮 + 排序按钮」；筛选开底部 Sheet 按列配置（控件复用现有 filter-popover 输入组件），排序为列+方向 Select；已生效筛选 Chips 行两形态共用。
- **翻页**：「加载更多」按钮按 offset append（显示 N/共 M 条），不做自动无限滚动；筛选/搜索/排序变更重置回第 1 页。
- **动作面**：卡片模式默认隐藏全部 toolbar 动作（新增/导入/导出/打印）、关闭勾选与批量条；行内 ⋯ 菜单完整保留（审批/确认/查看触屏友好）；动作级 `mobile: true/false` 标记微调。
- **树形 grid**：移动端常驻「退回平铺 + 搜索」，复用现有「筛选即平铺」回退逻辑，不建多层导航栈。
- **详情抽屉**：已天然移动端友好（`w-full lg:w-[480px]`，小屏全屏），无需改动。

## Considered Options

- **保留表格 + 列折叠**（拒）：小屏只显前 2–3 列、其余收进行内展开区。单元格交互（列头筛选、排序、fk 链接）在触屏上依然难用，且 HeroUI Pro DataGrid 无内置行展开，需自造；数据密度优势在手机上兑现不了。
- **按资源手工定制移动端视图**（拒）：效果最精确但违背 meta 驱动架构，30+ 资源逐个写移动端配置，长期不可维护；约定优先方案下个别资源用 `mobileRole` 精调即可覆盖。
- **全功能响应式**（拒）：手机也要建单/编辑/批量。工程量最大且不符合 ERP 手机端主流定位——重录入在手机上本身就是反体验，明确切出功能面子集。
- **独立移动端壳（PWA/原生）**（拒）：最自由但维护两套视图；meta 驱动卡片流已能复用全部现有页面装配，收益抵不过双视图成本。
- **移动端只留搜索/完全只读**（拒）：「只看待我审的单」这类筛选与「手机上审批」是核心场景，砍掉即违背功能面定位。

## Consequences

- 第一期范围：卡片流渲染 + 字段约定/override + 筛选 Sheet + 排序 Select + 加载更多 + 动作面默认策略 + 树形常驻平铺，全部在 `synie-data-grid` 内。**不做**：`synie-editable-table` 移动适配（建单回桌面）、扫码查物料、PWA/离线。
- `ColumnOverride` 与动作类型各增 `mobile` 语义字段，属组件 API 面扩张；后续新增动作时须考虑其移动端归属。
- 卡片模式下无列表格式的 CSV 导出/打印/批量入口，报表类重操作必须回桌面——属有意切割，勿作为「缺失功能」回补。
- 卡片字段约定与列顺序强耦合：页面调整 `columns` 顺序会改变卡片标题/副标题，调整时需顺带检查移动端呈现。
