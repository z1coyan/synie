# 委外采购：订单委外标记 + 外协仓结存 + 独立委外发料/入库单，并取消 BOM 物料唯一键

委外加工（发自家料给协作方、收回成品、只付加工费）建模为：采购订单头加**委外标记**（与常规/零星类型正交，保存后锁死），条目＝委外回来的成品、条目单价＝加工费；条目下挂**发料清单**与**副产物清单**两个可空子表，由条目物料自身的 BOM 按理论耗用/单位产出量 × 条目数量代入，**快照复制**、代入后与 BOM 脱钩可自由删改。执行层新增两张单据：**委外发料单**（无金额不过总账，审核把材料从调出仓移入外协仓）与**委外入库单**（成品入仓＋按发料清单快照比例扣外协仓材料＋副产物入仓，扣减/副产物均可手改；财务行为完整镜像采购入库——未开票应付、已收数量、超收容差、已对账数量全量接入，加工费照常走对账→发票链）。**外协仓**由占位标记升级为实义：我方仓、必挂**协作方**（供应商/内部公司，一仓绑一方），其结存即协作方处我方材料结存。同时**取消「一物料至多一张 BOM」**（推翻 2026-07-22 BOM 模块 ADR 的该项定案）：委外订单条目是第一个需要指名 BOM 的下游引用，「版本管理待有下游引用时再议」的时刻到达；BOM 改为独立编号（挂编号规则）＋可空方案名称，一物料可多张配方。

## Considered Options

- **委外入库并入采购入库单**（拒）：财务链零成本复用，但单据裂成「普通/委外」两种形态，行结构、审核副作用、对账口径全部分叉，长期复杂度更高；独立单据镜像财务行为符合生产入库单独立先例。
- **发料直接核销、不过外协仓**（拒）：材料所有权仍是我方，直接核销让「协作方处还压着多少料」无账可查，这是委外管理最常见的失控点。
- **内部公司对手镜像写双方库存账**（一度选定后推翻）：系统无任何跨公司分录先例，且与采购入库「只记单方账、不自动镜像」冲突；统一为内部公司也进「绑定该内部公司的我方外协仓」，对方自行手工记账。
- **履约需求行（履约方式=委外）自动生成委外订单**（缓）：需求行上没有加工方与价格，且「外购」至今不自动生成采购订单，委外不搞特殊化；将来需要再加生成入口，属纯增量。
- **超发料设容差硬拦**（拒）：发料清单只是基准，多给料是常见业务现实，已发料量投影只展示不拦截。

## Consequences

- BOM 放开一物料多张的代码改造（去唯一键、加独立编号与方案名称）随委外采购一并落地；既有 BOM 数据需补编号。
- 库存 v1 只记数量：委外材料扣减物化进成品的成本、副产物估值，全部随库存金额账（估值方法）一并设计，届时纯加列。
- 委外订单条目的委外配置全部可选，系统不做「审核时必须有 BOM/清单」的硬校验——无清单的条目在委外发料取行时自然卡住。
