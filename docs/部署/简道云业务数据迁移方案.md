# 简道云业务数据迁移方案（2026-08-11 定稿）

承接《[简道云数据迁移](./简道云数据迁移.md)》（主数据+销售报价已完成），本文是**业务单据与财务数据**的迁移总方案。制定依据：目标侧全模块承接能力勘察（`docs/业务模块/` 各篇 + ADR）与简道云侧 48 表单全量盘点（2026-08-11，方法见 §3）。

## 1. 总体策略：三轨并行，不搞全量重放

简道云老数据的根本问题不是"脏"，而是**模型不同构**——简道云是"余额推导式"（客户欠款 = 发票 + 期初 − 流水 − 承兑 ± 其他收付款），无凭证、无单据链勾稽；synie 是"单据链式"（订单→发货→对账→发票→收款凭证，应收是往来角色科目按对手聚合）。因此：

| 轨道 | 范围 | 落点 |
|---|---|---|
| **A. 在途链迁移** | cutoff 时点未结清的业务链（未发完订单、已发未对账、已对账未开票、已开票未收款、在手持承兑） | 走 API 建草稿→审核，**完整复刻单据链**，让 synie 的链从真实在途状态转起来 |
| **B. 期初凭证找平** | cutoff 之前已结清历史（票账两清部分）、期初欠款、GL 各科目余额 | 期初手工凭证（过账日期 = cutoff 前一天，往来科目行强制带对手） |
| **C. 归档留档** | 已结清历史中**不对账要用**的单据、空表、辅助表 | 导出 JSON 存 OSS/本地归档；**2026-08-13 修订**：销售订单/出库因对账需要改为进业务表（台账、不过账），不再只留 JSON |

**否决"AI 清洗后全量重放"的理由**（勘察证实）：

1. synie 发票强制「一票挂一张确认态对账单、金额相等、一票一单」，历史"一票多单/部分开票/金额不齐"是合法业务现实，AI 无法在不丢失事实的前提下洗成一对一；
2. 简道云各表单间**无可靠关联键**（对账条目标识只有客户编号、出库条目标识大量同值重复），订单→出库→对账→发票的链路只能靠"客户+金额+日期"启发式猜测——拿猜测的链生成真实 GL 分录，比不迁更危险；
3. 超发/超收比例（默认 0%）、负库存校验会大面积拦截历史事实，放宽设置等于为历史脏数据污染现行规则。

**老公式的正式用途：验收基准**。简道云的欠款公式虽不合理，但它是公司与客户多年对账的唯一口径。迁移完成时逐户核对「synie 应收余额 vs 简道云公式结果」，差异进人工核查队列——基准不是真理，是与客户重新对账前的核查清单（见 §6）。

### 2.1 应收两科目终态口径（D11，2026-08-18）

简道云仪表盘**没有未开票应收**：欠款 = 发票 + 期初 − 流水 − 承兑。synie 发货过账进 1124、开票才把 1124 重分类到 1122。迁移把两套账拆开对齐，不合成一列：

| 科目 | 终态口径 | 权威来源 | 找平 |
|---|---|---|---|
| **1122 应收账款** | 已开票欠款 | 简道云仪表盘逐户（京泰/东方拆分） | align5，`A(J)-20200101-0007`；见实录 §24 |
| **1124 未开票应收** | 尚未对账的出库金额 | 已审核发货 `(qty − reconciled_qty) × order_price`；业务数量与冻结终版《未对账销售出库明细》（`~/未对账销售出库明细_20260817200931.xlsx`）对拍 | align6，`A(J)-20200101-0008`；见实录 §26 |

要点：

- **不是报表算错**。1122 对上仪表盘，是因为后来按仪表盘单独找平；1124 在 §24 曾被定为「迁移在途发货全量」（华采 3,151,242.28），§25 对账重建只改 `reconciled_qty`、历史对账单/发票都不过账，已对账发货的 1124 从未冲回。
- **华采拆账**（对齐前）：446 张过账发货 = 3,151,242.28，其中 436 张已全对账仍挂 3,105,540.88（应冲掉）、10 张仍未对账 45,701.40（应留）；另有 9 行补迁未过账剩余 30,847.40（应补进 1124）。45,701.40 + 30,847.40 = 76,548.80。xlsx 同 26 行合计 76,516.80，差 32 元来自 8/17 `F(P)95-24`（简道云单价 7.5 / 订单快照 7.7）——**GL 按系统单价**。
- **全库同一结构**：对齐前 1124 = 29,043,401.44，剩余未对账 ≈ 222 万（大连第一 / 上益 / 华采各挂 300 万级「已对账未冲」）。align6 一次收到，1122 不动。
- 七往来净额**不等于**仪表盘（1124 与预收等独立存在）。看仪表盘对 1122；看未开票对 1124。日后新开票走正常冲回组（贷 1124 / 借 1122）。
- 单价法与快照金额比例法逐户差 ≤ 0.01（全库合计差 2 分）；东方 1124=0 且无剩余，无凭证。

### 3.2 数据质量七大问题（清洗对象）

1. **createTime 全部不可信**：各表在 2025-03-30/04-01/04-15 有同毫秒批量导入批次（上线 Excel 导入），排序一律以业务日期字段为准；
2. **银行流水重复 6~11 倍**，去重是迁移前提；
3. **承兑两表疑似双写**，须对账后取一；
4. **期初欠款含测试/0/负数行**，负数行须人工定性（预收？红冲？）；
5. **委外供应商名称混乱**，须归一并补主档；
6. **条目物料/单位写法不规范**，发票明细规格是自由文本（如 `8TKH.365.0756`），须映射物料 code；
7. **表间无关联键**，单据链只在在途范围内按"客户+单号+金额+日期"重建，且重建结果须人工抽样核验。

## 4. 清洗分工：规则为主，AI 打长尾，人工兜底线

原则：**财务数据清洗宁可留档不导入，不可编造**。AI 不做金额修补、不补造单据；每条 AI 判断带置信度与理由落盘，低置信度进人工队列。

| 层 | 任务 | 说明 |
|---|---|---|
| **确定性规则**（主力，约 80%） | 流水去重（日期+账号+金额+对方户名业务键）；承兑票号去空格/跨表匹配；期初欠款剔测试/0 行；物料编码完全匹配与客户方编码对照；日期/币种/税率格式归一 | 可审计、可重跑，全部脚本化 |
| **AI 语义判断**（dsv4flash 级便宜模型，约 20%） | ① 委外供应商名称归一 → 供应商主档；② 发票/出库条目规格自由文本 → 物料 code 兜底映射；③ 流水对方户名 → 客户/供应商归类 + 收支性质判断（生成收付款凭证候选）；④ 异常清单生成（重复票号、金额勾稽差异、一户多名） | 粗估 1.5万~2.5万条过 AI、千万级 token，成本数十~一两百元量级，可忽略；**关键是人工复核队列设计** |
| **人工队列**（兜底线） | AI 低置信度项；期初欠款负数行定性；验收差异户；23 张冲突报价单同类个案 | 每项留痕处理人+结论 |

## 5. 分层迁移计划

统一执行管线（沿用报价迁移模式）：**MCP 抽取（原始 JSON 落 `.scratch/jdy-migration/`）→ 画像与清洗（规则脚本 + AI + 人工队列）→ 生成 payloads → 小批量试导入 → 放量 → 失败留档**。幂等键沿用 code 体系 + state 文件记录 jdy→synie ID 映射；历史单号写单据备注，单号由系统生成。每个模块设「决定不导入仅留档」桶（报价迁移先例）。

### 阶段 0：配置补齐（一切单据迁移的前置）

| 项 | 内容 |
|---|---|
| 采购报价 | 仅 4 条，API 直接迁（采购订单的强制前置） |
| 公司默认过账科目 | 发货/入库四槽逐公司配好（发货借方强制未开票应收角色、入库贷方强制未开票应付角色） |
| 银行账户 | 6 个我方账号建档 + 绑定非汇总科目（流水/票据/快速建凭证前提） |
| 外协仓 | 按 D8 归一后的协作方逐家建外协仓（叶子仓 + is_outsourced + 绑定供应商） |
| 供应商补建 | 委外归一后发现的新供应商先入主档 |
| 容差设置 | 按 D5 调超发/超收/超入比例 |
| 部门 | 履约需求/工单需要（若迁在途工单） |
| 客户地址 | 348 条去重后按客户编号挂接 |

### 阶段 1：资金台账（最顺，先立起来）

1. **银行流水去重后全量导入**：规则去重 → 按导入模板拼 xlsx → `POST /finance/bank-imports` → 解析 → 修正暂存行 → `/import` 转正（≤5000 行/批，同文件防重传）。流水是台账不记账，无 GL 风险。
2. **其他收付款 48 条**：**2026-08-16 已执行**——不并入银行流水，按经济实质做成 **46 张已审核手工凭证**（2 对承兑互转各并一张）。见[实录 §19](./简道云业务数据迁移实录.md)。
3. 本阶段**不做**流水对账（依赖凭证，放阶段 6）。

### 阶段 2：期初（轨道 B）

1. **期初欠款清洗**：296 条剔测试/0 行，负数行人工定性 → 按客户逐户拆。
2. **期初凭证**：一批手工凭证，过账日期 = cutoff 前一天；应收/应付/预收/预付等往来科目行**强制带对手**；借贷配平校验天然防错。
3. GL 其余科目期初余额（库存金额、银行、票据等）同批凭证承载，与阶段 1 流水余额、阶段 5 票据、阶段 6 库存互相勾稽。

### 阶段 3：销售在途链（轨道 A 主线）

按业务日期时序，逐客户推进：

1. **销售订单**：在途走 API 建草稿→审核；**2026-08-13（D10）**历史已结清单也进业务表（订购数量用简道云原数量），关闭后仍可查收发货历史。
2. **销售发货**：已发未对账走 API 审核过账（过账日期=历史发货日）；**2026-08-13（D10）**其余出库（含已对账、Excel 老出库）SQL 直插 AUDITED **不过账**，挂真实订单；挂不上的行快照保留简道云原编码/名称/规格。
3. **历史销售退货**：优先手工行（为系统外历史退货设计），源单行要求源发货已审核且剩余可退>0。
4. **销售对账单**：勾选在途发货/退货条目 → 确认（客户已确认）。常规单禁样品来源与零金额行；分次对账尾差用赠送/样品对账单核销。**2026-08-17 已执行**：简道云对账单全量镜像（1302 张，全部已结单、不过账）+ 期初兜底 376 张，冻结周新发货 58 张补迁；验收=简道云未对账导出 535/535 键零差异。见[实录](./简道云业务数据迁移实录.md) §25。
5. **未开票→已开票**：对已确认对账单开出发票（审核带 postingDate=历史开票日期，价税合计须等于对账单合计、一票一单）。已对账未收款的停留应收账款；已收款部分见阶段 6 凭证。**2026-08-18 修订**：历史发票仍不过账；1124 已按发货剩余未对账一次性收到（align6，见实录 §26），不再保留「在途发货全量」。新开票走正常冲回组。

### 阶段 4：采购与委外在途链

1. 采购订单 17 条全量审入（依赖阶段 0 采购报价/零星上限评估）；
2. 已收未对账采购入库（610 头中筛在途）；采购退货手工行；
3. **委外**：委外订单配发料清单（委外发料无手工行，发料清单是唯一取行来源）→ 在途委外发料/入库；注意委外退货必须先于其源入库的对账确认；
4. 采购对账（三来源恰一：采购入库/委外入库/采购退货条目）→ 确认 → 开入发票。

### 阶段 5：票据

1. 按 D9 对账两表取一，票号规范化去重；
2. **在手持承兑**：逐票建「接收」交易（发生日期=原收票日，允许补录历史）→ 审核（自动建档+入持有段+生凭证）；子票区间按（止−起+1)/100 折算；接收段不得与系统现有持有段重叠；
3. 已转让/已兑付历史票：归档留档（轨道 C），不补全链；
4. 内部互转票注意先审转让后审接收。

### 阶段 6：库存与收付款收尾

1. **库存期初**：cutoff 日实盘 → 入库方向手工出入库单建账；
2. **收付款凭证**：AI 归类的流水候选 → 手工凭证（借/贷银行科目，对侧往来科目带对手）→ **流水对账勾稽**（放最后：已被对账引用的凭证不可取消）；
3. **期末盘点**：全部单据导完后做盘点单拉平账实（兜底校验"快照后该仓有分录变动则拒审"，故必须最后做）→ 关闭各仓「允许负数库存」。

## 7. 风险与注意事项

1. **GL/库存分录只追加、无反审核**：审错只能作废重开（留作废痕）；放量前每模块先小批量试点（建议先跑通一条完整链：订单→发货→对账→发票→收款凭证→流水对账）。
2. **过账日期口径已查证**：发货/入库/退货头部有过账日期字段（默认业务日期）、发票审核带 postingDate——历史单据 GL 可落历史期间；仍须在试点时以 V6 实测确认。
3. **编号计数器**：API 路线自动正确；若有表被迫 SQL 直插（物料先例），须事后 upsert `sys_numbering_counter` 且该批无审计日志——**有过账后果的单据一律走 API，不直插**。
4. **作废闸顺序**：已对账条目不可作废源单、已对账>0 的委外入库条目禁止退货、已被流水对账引用凭证不可取消——导入顺序按阶段执行即天然规避，倒序纠错成本极高。
5. **上传限流** ~30 次/分/用户，发票/承兑图片附件迁移按 ~2s pacing；附件按 URL/内容判重（报价迁移同名文件坑）。
6. **MCP 抽取注意**：jiandaoyun MCP **并发限制 3 次/秒**——抽取脚本按此 pacing；全应用数万条 ≈ 数百页，含重试约 10~30 分钟量级，可断点续跑；偶发空包 + 未转义控制字符，客户端重试 + `strict=False` 宽松解析；游标分页 limit≤100。
7. **迁移期间并行作业**：D1 确定前简道云仍有新增（盘点当日 2026-08-11 仍在录单），切换日前所有阶段按"快照日数据"执行，切换当日补一轮增量。
