# 生产环境（Dokploy · erp.tzjingtai.com）

本文记录当前生产实例的部署事实（拓扑、端口、密钥存放位置、运维要点）。通用部署工件与步骤见根 README「生产环境提示」与 `compose.deploy.yaml` 头部注释；本文只记**这个实例**特有的状态。Dokploy 管理员 API Key 等凭证不落入仓库；本地运维/AI 工具用的 `DOKPLOY_URL`、`DOKPLOY_API_KEY` 与项目资源 ID 存放在仓库根 `.env`（已 gitignore）。

## 实例概览

- 上线日期：2026-08-09
- Dokploy 实例：`https://dokploy.tzjingtai.com`，项目 **SynieERP**（environment: `production`）
- 站点：`https://erp.tzjingtai.com`（Let's Encrypt 证书，Dokploy/Traefik 自动签发续期）
- 源码：`github.com/z1coyan/synie`，分支 `main`，compose 路径 `./compose.deploy.yaml`

## 服务构成

| 服务 | 形态 | 说明 |
|---|---|---|
| `synie`（compose，appName `synie-pyagrm`） | docker-compose | `web`（SSR，:3000）+ `server`（API，:8080）+ `migrate`（一次性迁移，跑完退出） |
| `postgres`（Dokploy 托管，appName `synie-postgres-r3a11f`） | swarm 服务 | `postgres:17-alpine`，库/用户均为 `synie`；内网 DSN 注入 compose 的 `DATABASE_URL` |

域名路由（同一域名两条规则，同源反代为必需，原因见根 README）：

- `erp.tzjingtai.com/` → `web:3000`
- `erp.tzjingtai.com/api/v1` → `server:8080`

## 端口分配

遵循服务器端口块惯例（Git 23000、ERPNext 24000、www 25000–25001），本项目占 **26000 段**：

| 端口 | 用途 |
|---|---|
| 26000 | web 直连（绕过 Traefik 的备用入口） |
| 26001 | server 直连 |
| 26002 | PostgreSQL 外网端口（供内网 DB 工具连接） |

直连端口被云安全组过滤，**仅内网可达**；公网唯一入口是 443 域名反代。

## Git 源与自动部署

- 克隆走 **SSH**（`git@github.com:z1coyan/synie.git`）：服务器 HTTPS 访问 github.com 不稳定（部署时连续出现 `GnuTLS recv error (-110)`），SSH 通道稳定。
- 凭据：GitHub 仓库只读 deploy key `dokploy-server-deploy` + Dokploy SSH 密钥 `github-synie-deploy`，私钥只存于 Dokploy。
- **手动部署**（2026-08-09 起）：push 到 `main` **不会**触发部署——GitHub webhook 已摘除、Dokploy `autoDeploy` 已关闭。部署入口二选一：Dokploy 面板 → SynieERP → synie → Deploy；或 API `POST /api/compose.deploy`（参数为 compose ID，见根 `.env`）。
- 若需恢复自动部署：Dokploy 面板开启 Auto Deploy + 在 GitHub 仓库重挂 webhook（Dokploy 通用部署端点含触发令牌，从面板/服务 refreshToken 取得，不记录于此）。

## 环境变量（值均在 Dokploy compose 服务 Environment，不进仓库）

必配：`DATABASE_URL`（托管 PG 内网 DSN）、`AUTH_SECRET`（随机 64 hex）、`BETTER_AUTH_URL=https://erp.tzjingtai.com`、`HEROUI_AUTH_TOKEN`（构建 secret）。可选与调优项见 `compose.deploy.yaml` 头部注释与 `server/.env.example`。

## 运维要点

- **托管 PG 网络**：Dokploy 托管数据库是 swarm 服务，只挂 `dokploy-network`；Dokploy 仅自动给绑了域名的 compose 服务注入该网络，`migrate` 这类无域名服务须在 compose 文件中显式接入（已落实于 `compose.deploy.yaml`，否则 migrate 解析不到数据库主机名、退出码 1）。
- **迁移**：每次部署 `migrate` 随栈自动执行，成功后 server/web 才启动；迁移失败则整栈不启动，部署状态置 error。
- **初始化**：空库首启浏览器打开站点进入 `/setup` 初始化向导（建首个超管与公司）；旗标落库后入口关闭。
- **备份**：托管 PG 平台不自动备份。任选其一：Dokploy 面板为 postgres 服务配置 Backups（S3 目的地）；或宿主机 crontab 挂 `scripts/backup-db.sh`（连内网 26002，见根 README「备份与恢复」）。**定期恢复演练**。
- **排障入口**：Dokploy 面板部署日志（宿主机 `/etc/dokploy/logs/synie-pyagrm/`）；容器日志 `docker logs synie-pyagrm-server-1` 等；健康检查 `https://erp.tzjingtai.com/api/v1/healthz`。
- **上传文件**：`synie-uploads` 命名卷持久化；对象存储在系统设置中配置。前端预览/下载经 `fetch` 跟随 302 到对象存储直链，属于跨域请求——**对象存储 bucket 必须配置 CORS**（AllowedOrigin=`https://erp.tzjingtai.com`，Method GET/HEAD），否则浏览器报 "Failed to fetch"（2026-08-11 阿里云 OSS synie-erp 已配置）。
