## 落点与映射规则

**匹配键一律是 code（编号）**——两边编号同源同值，唯一索引兜底，增量同步按 code 判存即可，无需维护第三方 ID 对照表。

- 供应商/客户：`code`+`name` → `pur_supplier` / `sal_customers`。
- 物料分类：两遍建树（先 4 个根 F/P/E/M，再 27 个叶子），`parentId` 按父 code 解析；「是否允许添加物料=是」→ `is_leaf=true`。
- 物料：`code` 显式保留（`F(P)190-2` 这类），`materialType='STOCK'`、`active=true`；分类按「分类编号」挂叶子分类；单位按名称映射 `bas_unit`（斤/组/袋已补齐，共 31 个）。
- **客户物料推导**：物料编号匹配 `^F\(P\)(\d+)-` 即视为客户物料——中段是客户编号（如 `F(P)22-1` = 22 号客户的 1 号产品），`is_customer_material=true`、`customer_id` 按客户编号关联、`customer_part_no`=客户方编码（`-`/`无` 等占位值归一为 NULL）。不匹配该模式的 61 条 F(P) 物料（如 `F(P)-3200`）按非客户物料导入。
- 附件：图纸 → `ownerType=inv_material` + `category=drawing`；其他文件 → `category=default`。OSS 走系统设置的默认存储（aliyun）。

## 销售报价迁移（2026-08-11）

- **范围**：4066 头 / 4735 条目 → 导入 2625 单 / 2788 条目。跳过空报价单 1414 张（1206 无条目 + 208 条目全部无效；synie 不允许审核空单）；丢弃条目标记「无效」的 346 条；4 条引用简道云侧已删物料的条目随之丢弃。

- **业务决策（颜智豪确认）**：报价截止日简道云无字段，统一占位 **2099-12-31**（时效策略待后续决定）；单价按**含税价**导入、税率标注 13%（仅口径标注不参与计算）；0 元样品报价按固定价 0 正常导入（653 条）；成本六要素丢弃；条目图纸/文件不随报价迁移（报价条目无附件位，图纸已在物料主档）。

## 关键决策与坑（复用方法时注意）

1. **物料 API 拒手填编号**（「编号由系统生成,不接受手填」），保留原编号只能 SQL 直插 `inv_material`。直插前须在本地复刻服务层校验（分类须启用叶子、单位/客户存在、`customer_material_pair` CHECK）。代价：这批数据无审计日志。
2. **编号计数器必须事后修正**：直插不走取号，`sys_numbering_counter` 不落桶。规则为 `category.code + customer.code + '-' + seq`（padding=0），须按每个 `scope_key`（如 `F(P)22-`、`F(TJ)-`）upsert 为已导入的最大序号，否则 UI 新建物料取号会从 1 开始撞唯一索引。本次共 338 个桶。
3. **附件去重不能按文件名**：简道云存在同物料多个同名 `image.png`（实为不同图片），按「物料+分类+文件名」去重会漏传（本次漏 5 个后补传）。应以文件 URL/内容判重。
4. **OSS bucket 必须配 CORS**（2026-08-11 已配 `synie-erp`）：前端预览经 fetch 跟随 302 到 OSS 直链，无 CORS 则浏览器报 "Failed to fetch"。换存储（如天翼云）时需同样配置。
5. 上传限流 `RATE_LIMIT_UPLOAD_PER_MIN` 默认 30 次/分/用户，批量传附件按 ~2s 间隔 pacing。

## 增量同步指引（简道云新增数据）

1. 用 `member_data_list` 拉对应表单（可按 `createTime` 过滤或全量拉取后按 code 与线上对比，5006 条物料全量约 45 秒）。
2. **供应商/分类/单位/客户是物料的前置**：新物料若引用新分类/单位/客户，先迁前置数据（客户目前已全量，一般只需补分类/单位）。
3. 物料走 SQL 直插（同本次脚本化流程），插入后**同步 upsert 对应编号桶**（已有桶取 GREATEST，新桶插入）。
4. 附件按 URL 判重、按物料 code 挂接；同名文件直接传，系统允许同名附件。
5. 简道云侧删除/修改不会自动同步——本系统上线后为主库，简道云只读快照，新增单向流入即可。
