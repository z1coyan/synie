# Synie ERP

面向中小企业的多公司财务 ERP。本文件是领域术语的唯一定义处（ubiquitous language）；实现细节与功能说明书见 `docs/业务模块/`，架构取舍见 `docs/系统架构/adr/`。

## Language

- **资源目录**（Resource Catalog）：系统内可寻址资源的类型安全声明集合，是字段身份与类型、枚举、外键、可筛选/排序能力、权限动作和基础表单布局的权威来源；它不执行领域校验、事务、审核、库存、总账、外部调用或任意脚本，也不根据声明生成万能 SQL 写入。
- **资源文档**（ResourceDocument）：资源目录按当前操作者权限投影给前端的稳定 wire 契约；包含可见字段、查询能力、动作能力与基础表单声明。Grid 与基础 Form 都从同一资源文档派生，不再各自维护字段事实。
- **资源事实清单**（Resource Manifest）：资源目录中 **actor 无关**静态事实（显示标签 label、选择器 lookup、写体 wire 编码 decimal/date/decimalZero）的构建期派生物——由 server sealed Registry 生成 `packages/shared/src/generated/resource-manifest.ts` 入库，漂移测试与 Registry 逐字节对拍；前端同步消费点（transport 写编码、RemoteSelect 预取回落、requireWriter/toast 资源名）一律读它，不再手抄第二份。actor 投影事实仍由**资源文档**运行时唯一承载，二者边界即「随不随操作者变」。权威定案见 [ADR 2026-08-07 资源事实清单](系统架构/adr/2026-08-07-resource-manifest.md)。
- **基础资源表单**（Basic Resource Form）：仅由资源文档中的静态、可序列化声明生成的普通单记录 CRUD 表单；支持字段顺序、分区/分页、栅格宽度、占位与静态选择器提示，不承载跨字段计算、领域规则或副作用。
- **呈现扩展**（Presentation Extension）：按资源显式绑定、与对应业务模块共置的前端扩展，用于基础资源表单无法表达的动态可见性、联动控件、附件/OCR、子表、审核呈现和文档速览；全局 registry 只装配资源与扩展，不拥有业务 JSX 或配置事实。其存在不改变后端领域模块仍是写入权威边界。
- **资源能力 Adapter**：前端按能力绑定后端领域 API 的类型化端口总称——ResourceReader 只负责列表/单条读取，RecordWriter 只暴露该资源实际支持的单记录 create/update/delete 子集，CommandAdapter 执行带明确 collection/row/bulk target 的领域命令；命令与成功后受影响的资源共置声明，由统一失效模块自动包含当前资源并精确刷新。ResourceBinding 同时拥有 Reader 对应的列表/单条缓存身份与精确失效动作，页面不传具体 client、拼 transport id 或全局清空所有资源。这些 Adapter 只翻译 transport，不拥有领域规则。
- **单据抽屉骨架**（`useDocumentDrawer` / `createDocumentDrawerOpenBridge`，`web/app/lib/use-document-drawer.ts`）：单据抽屉共享的管道层——记录抽屉开/关/模式（列表页 URL 寻址与内嵌宿主本地态双态收在内部）、URL 身份→整单草稿装载（开抽屉占号、回填前比对的竞态协议、深链/前进后退按 recordId 补拉、关闭作废在途请求）、装载失败与非法 id 的统一呈现（文案从资源文档中文标签派生，可覆盖）、以及共享抽屉 open 桥（createContext + useOpen + Provider 工厂）；核心是无 React 的纯状态机 DocumentDetailLoader（bun:test 直测竞态），hook 只做 React 接线。骨架只收管道不收条目：条目状态、条目编辑 UI、科目联动、快照回填与提交仍属各呈现扩展与聚合草稿 Adapter；hook 返回 draft，各抽屉用一个派生 effect 初始化自己的条目集合。
- **聚合单据描述符**（Aggregate Document Descriptor）：后端声明一个有明确聚合边界的单据写资源如何由标准动作内核派生整单草稿能力——头 `createStandardService`、各级子行 `createStandardChildService`（可孙级，链深 ≤ 2）、再经 `createAggregateService`（`platform/standard/aggregate.ts`）组合为 `loadDraft` / `createDraft` / `replaceDraft`；子树键、校验文案、编号与 workflow 转移在描述符与钩子中声明，跨资源效果不进草稿钩子。合同套件以 CASES 一行描述符摊销断言。权威定案见 [ADR 2026-08-07 聚合单据内核](系统架构/adr/2026-08-07-aggregate-document-kernel.md)。
- **聚合草稿 Adapter**（Aggregate Draft Adapter）：前端对一个有明确聚合边界的完整草稿执行一致快照读取、创建与整体替换的类型化端口；后端权威实现由**聚合单据描述符**经 `createAggregateService` 派生（`loadDraft` / `createDraft` / `replaceDraft` 与领域钩子在单一事务内完成），完整替换必须显式提交全部集合，并保留该业务原有的 create/update/delete 授权语义。编辑态只有在权威子树完整加载后才允许整体替换，加载中的暂态空集合不能表示删除。前端对标准草稿三连（GET `:id/draft` / POST / PUT `:id`）经 `aggregateDraftTransport` 工厂生成本 Adapter。聚合不由资源目录解释或保存，客户端顺序循环保存表头/子条目不等价于聚合草稿保存。

- **BOM**（物料清单）：挂在物料上的单层配方主数据，跟随物料全局共享不分公司；一物料可多张，以**独立编号**为唯一键——编号挂编号规则（系统生成、全局唯一、创建后不可改），另加可空**方案名称**辅助区分同物料的多张配方；状态机 **草稿 → 启用 ⇄ 停用**（启用与停用可互转）；**仅启用**可被新生产工单/新委外订单选入；**仅草稿可物理删除**，启用过之后只停用不删；启用后配料/路线仍可改，已快照到工单的配方不追溯；配料为子物料行，多级结构靠半成品物料各自挂 BOM 嵌套形成，系统不建 BOM 树实体，树展开只是查询视图；配料子物料不能是母物料自身（保存校验），多级间接成环不硬校验、树展开检测环并截断提示。菜单生产管理「计划」组（履约需求单/BOM/工序/工艺模板），权限码 `mfg.bom` / `mfg.operation` / `mfg.route_template`。
- **工艺路线**（生产工艺单）：挂在 BOM 上的工序子表（每 BOM 私有，逐行添加，行=工序引用+工艺要求文本+外协标记），描述「怎么做」（工序顺序与要求），不带生产数量、不驱动执行、不派生库存/财务后果；执行层见履约需求单/生产工单/生产入库，第一期执行不建工序报工；工单选 BOM 时随配料/副产品一并快照到工单私有子表。
- **工序**（Operation）：全局共享的工序主数据（如冲网/分切/焊接成筒/CNC），不分公司，编号挂编号规则；工艺路线行引用工序，行内工艺参数/要求走自由文本；被路线引用后不可删除。
- **工艺模板**：独立可维护的工艺路线模板主数据；建 BOM 路线时选模板**复制带入**为 BOM 私行，此后模板再改不影响已建 BOM（快照语义，同系统改默认不追溯惯例）。
- **配料行**：BOM 的子物料行——子物料+单位（限默认单位或其转换单位）+单位净用量（每 1 默认单位母物料的净消耗）+可空损耗率（理论耗用=净用量×(1+损耗率)，空即无损耗）；平铺清单，不记录投料工序（投料时点待执行层需要时再补列）。
- **副产品行**：BOM 上声明的联产出行——物料（如铜屑/网屑，须为可入库存的物料）+单位产出量（每 1 默认单位母物料）；本期仅作声明，是将来执行层扣料/完工入库/成本分摊的锚点。
- **外协标记**：工艺路线行上的布尔标记，表示该**工序**通常外发加工；不指定供应商（发哪家是执行时决定），不产生任何单据；与需求**安排类型=委外**（整批外协意图）及采购订单的**委外标记**（整单委外加工执行）均不同层，勿混——工序级外协的执行单据流（按工序发料/报工/加工费）仍不在本期范围，整单委外走委外订单。
- **履约需求单**：销售承诺与车间/采购执行之间的**内部需求中间层**——计划将多张销售订单条目（可跨单）勾入，或**手工建单/增行**（参展样品等无客户、无销售来源的独立需求）；头含必填**指派类型**（见同名词条）与可空**需求日**（新增需求行的行需求日默认值，另有显式「批量带入」动作把头值刷到全部既有行，改头本身不追溯）；头状态 草稿→已确认→已关闭（+作废，仅已确认且无未作废下游可作废——下游含生产工单与已审核未作废采购/委外订单条目及手工安排，草稿走删除）；审核即执行确认，成功后锁行物料/数量等口径；录入时基本信息与需求行同屏，需求行视图也可直接新建整单并「保存并审核」，新建业务日期默认当天。车间不直接碰销售订单/客户。界面可称「需求单」；**避免**称「物料需求单」（易与领料混淆）。权限资源独立（与生产工单、生产入库拆分），计划维护、车间不建。
- **履约需求行**：履约需求单的行——物料+数量+需求日（必填，草稿保存即校验）+可选来源销售订单条目（**不再有行级履约方式**）；来源销售条目/来源生产工单**创建时定型、编辑只读**，手工行不可事后补挂来源（换来源=删行重勾）；行快照含物料**图纸挂接复制**（同订单条目先例、仅行内展示，工单图纸仍取物料主数据、不回需求行取）；有销售来源时数量硬校验不超该条目可占用，占用口径=已确认未作废需求单（草稿不占、确认占量、作废释放），可占用上限=订购 base + 该条目已审核销售退货量（挂源行部分——客户退回后仍欠客户的量，无退货时退化为订购 base；校验时点仍为确认时，不为「退货作废导致既有需求超限」新增拦截）；出口靠**安排**子表（可混用生产/采购/委外/库存/关闭）；冗余受控投影——**已安排数量**与**已完成数量**（见同名词条），采购分量另可展示**已下单数量**/**已收数量**细分；行自动已完成当「可安排剩余≤0（受**需求超安排比例**）且已完成数量≥需求数量」；**取消**行上手工「点完成」（放弃走关闭安排、现货走库存安排）；拆批既可拆需求行，也可在同一行上多条安排/多张工单分批。
- **指派类型**（`assign_type`，履约需求单头）：计划员对整单「由谁消化」的路由声明——**采购**（含委外，委外执行归采购侧）/ **生产** / **库存** / **关闭**四值，草稿保存即必填；纯**意图层**——不占量、不替代行级**安排**事实（行仍可混用安排类型），类型=关闭只是路由标记、不联动状态机；类型=**生产**时**下发车间**必填，其余类型下发车间必须为空；审核后与下发车间一并经 dispatch 动作改派；无行级指派字段，混去向拆单。决策见 [ADR 2026-08-06](系统架构/adr/2026-08-06-demand-assign-type.md)。
- **物料需求派生**（生成物料需求）：生产工单上的动作——按工单 BOM 快照展开配料，逐行选定去向（某车间/采购/不需要）后按去向拆成多张履约需求单**草稿**（车间向头已填下发车间、采购向下发为空），派生行来源=生产工单（只读链接）、无销售占用；数量口径=理论耗用（净用量×(1+损耗率)×工单数量），带出本公司全部仓库现有库存合计的**参考库存**快照（不锁不扣不预留），默认净需求=毛需求−参考库存、人可改；需求日默认=工单需求日。车间角色仅经此动作入口获得需求单创建+审核权限（不可手工建单/勾销售条目）。轻联动：工单作废级联删未删除的派生草稿、已确认派生单只警告，改数量不回溯；多级不限深度递归派生；不做齐套检查，父需求行完成与子级链无联动。决策见 [ADR 2026-08-06](系统架构/adr/2026-08-06-work-order-material-demand.md)。
- **安排**（履约安排）：履约需求行上「如何消化该行数量」的事实行，类型五选一——**生产** / **采购** / **委外** / **库存** / **关闭**；前三类由执行单据**倒写**（生产工单**创建**、采购/委外订单条目**审核**时写入，草稿采购不写）；库存与关闭为需求侧**手工**安排。保存/生效即占**已安排数量**；库存与关闭保存同时计入**已完成数量**（不扣库存、无下游单）；生产/采购/委外的已完成靠入库回写。关闭数量硬卡≤剩余可安排（不吃超安排容差）。删除/作废安排：倒写类随工单作废或订单作废回滚；手工类在业务锁允许时可删改并释放占量。
- **已安排数量**：履约需求行上按物料默认单位累计的已占坑量——Σ 未作废生产工单数量 + Σ 已审核未作废采购/委外订单条目（挂本行）数量 + Σ 库存安排 + Σ 关闭安排；剩余可安排 = 需求数量 − 已安排数量（超安排受**需求超安排比例**）；列表主投影，取代「仅看履约方式+是否有工单」的旧待办口径。
- **已完成数量**（需求行）：履约需求行上按物料默认单位累计的已履行量——Σ 已审核未作废生产入库（经工单挂本行）+ Σ 采购/委外入库回写（经订单条目挂本行）+ Σ 库存安排 + Σ 关闭安排；与已安排数量并列展示，避免「排了但没收」与「收了但未排满」混淆。
- **生产工单**：自制执行容器，由车间从**已确认未关闭**的需求行生成（行上不再要求「履约方式=自制」）；**必挂一条来源需求行**，**同一需求行可多张未作废工单**并行；数量**可手填**（默认=剩余可安排、不含容差超额），须过需求超安排比例闸门；选定来源后公司、来源需求单、物料、单位、需求日及物料/单位快照由需求行只读带入，**不存客户**；创建时复制物料**图纸**挂接到工单；可空挂**启用中**的本物料 BOM，选后将配料/工艺路线/副产品**快照**为工单私有子表（与 BOM 脱钩，手改不回写主数据；尚无已审核生产入库前可换选/改快照/清空，有入库后锁死）；工单表单内可**嵌套完整 BOM 创建**（母物料锁=工单物料，保存即建正式 BOM 并选入快照）；本质是**未完成数量**容器（未完成=工单数量−累计生产入库）；改数量/作废仅进行中且无已审核未作废生产入库，作废释放已安排；累计入库≥工单数量则工单完工并累加需求行已完成数量。第一期不建工序报工、不按快照扣料。权限与需求单、生产入库拆分。
- **生产入库单**：对生产工单的**成品入账**单据——行必挂生产工单、物料须与工单一致；可分次入库；审核写正向库存分录并累加工单已入数量与需求行已完成数量，作废回滚；对齐采购入库/销售发货的分次与容差模型。默认仓管操作。第一期只做数量账（不过生产总账/成本），不做副产品行、不扣料。列表双 tab（**入库条目**默认 / **入库单**），与销/采履约入库列表同形；权限码 `mfg.output`。
- **生产入库条目**（亦称**生产入库行**）：生产入库单的商品行——必挂生产工单、物料须与工单一致，单位/数量折默认单位，行仓为本公司启用叶子仓；行保存冻结物料快照（无行图纸挂接）。页面列表与抽屉可简称「入库条目」（与采购侧「入库条目」同形但实体不同，勿跨模块混读）。
- **生产入库超入比例**：生产设置（生产管理→「生产设置」页）中的全局容差（小数，如 0.05=5%），默认 0（禁超入），合法范围 0～100%；生产入库审核时要求该工单「累计已入（含本单）≤ 工单数量 × (1 + 比例)」；草稿不硬卡、审核硬拦；语义同发货超发比例、采购入库超收比例。
- **已下单数量**：履约需求行上采购分量的细分投影——已审核未作废、引用该行的采购/委外订单条目数量合计（默认单位）；是**已安排数量**的采购/委外部分，草稿不占；超安排受**需求超安排比例**（取代旧「仅采购侧」的超下单闸门为行级统一闸门，见同名词条）。
- **需求超安排比例**：采购设置（采购管理→「采购设置」页）中的全局容差（小数，如 0.05=5%），默认 0（禁超安排），合法范围 0～100%；工单创建、采购/委外订单审核、库存/关闭安排保存时要求所涉需求行「累计已安排（含本笔）≤ 需求 base × (1 + 比例)」；草稿采购不卡；关闭安排额外硬卡不超剩余可安排（不吃本容差）。语义升级并覆盖旧「需求超下单比例」（安排层统一闸门，不再只拦采购下单）。
- **已收数量**（需求行）：采购/委外入库审核沿「入库条目→订单条目→需求行」回写的收货投影（作废减）；计入需求行**已完成数量**的采购/委外分量。
- **物料分类**（MaterialCategory，`inv_material_category`）：物料的树形分类学，全局共享不分公司。
- **物料**（Material，`inv_material`）：全局共享的物料主数据（不分公司），只能挂叶子分类；名称必填不唯一，防重靠录入前搜索；被库存分录引用（含已作废分录）后不可删除。按**物料类型**分库存/虚拟/资产三类。
- **物料类型**（`material_type`）：物料三分——**库存**（STOCK，默认，唯一可发生库存数量账的类型；存量物料全部归入）、**虚拟**（VIRTUAL，服务等无实物物料，可进购销单据但不进库存）、**资产**（ASSET，模具/设备等，按资产台账管理，可采购但不进库存数量账）。准入矩阵：销售报价/订单收库存+虚拟，采购报价/普通采购订单收三类，销售发货收库存+虚拟，采购入库收三类，委外全链、BOM、生产工单/入库、其他库存单（手工出入库/调拨/盘点）仅库存类；履约需求行不限（安排落单据时各自校验）。发货/入库的虚拟与资产行行仓可空、审核不写库存分录，已发/已收数量投影、金额链、总账、对账与发票照常。类型创建后可改，存在库存分录（含已作废）后锁定（同默认单位先例）。
- **模具设计**（MoldDesign，`mfg_mold_design`）：生产域的模具档案实体，与物料 **1:1**（`material_id` 唯一外键）——名称/规格/单位落在物料上，模具设计自身只挂**模具类型**；创建模具时用户只填名称/规格/模具类型/单位（+图纸/附件），系统在同一事务内自动创建一个**资产类物料**（分类取**模具物料分类**设置、编号走物料既有规则）并挂上模具设计记录；编辑同步物料名称/规格/单位（有单位转换行时单位不可改，同物料保护先例）；删除模具设计级联删除其物料（物料被库存分录或业务引用时拦截）。图纸/附件挂在物料槽位上。权限码 `mfg.mold_design`，菜单「生产管理 → 模具管理」。本期不与工单/BOM 联动、不跟踪模次寿命。
- **模具类型**（`mold_type`）：模具设计的工艺分类枚举——**冲压**（STAMPING）/ **变形**（FORMING）/ **定位**（POSITIONING）/ **其他**（OTHER）；枚举写死，新增类别=加枚举值。
- **模具物料分类**（`mfg_setting.mold_category_id`）：生产设置中的全局配置（可空引用一个物料分类）——创建模具时自动建的资产物料归入该分类；未配置时建模具直接报错；须为启用的叶子分类，建议挂 `E 设备工量具` 下自建叶子（分类种子不预置）。首例单行设置表存引用列。
- **客户物料**（`is_customer_material`）：物料是否专属某一客户；为真时必挂一个客户（v1 一料一客），为假时客户为空（通用料）。销侧单据（报价/销售订单/销售发货）只能使用通用料或本客户料；内部公司对手只能用通用料。采购/库存本期不校验。
- **物料编号**（`inv_material.code`）：物料唯一标识，仅按编号规则自动取号（初始化完成时预置：分类编号 + 可选客户编号 + `-` + 不补零序号；字段空则省略，故通用料与客户料共用一条规则、按前缀分桶计数；例：分类 `F(P)` 下通用料 `F(P)-1`、客户 77 料 `F(P)77-1`），不接受手填、创建后不可修改；改挂分类/客户不追溯改号。
- **默认单位**（`default_unit_id`）：物料计量与单位转换的基准单位，必填、类型不限；存在转换行时不可修改；存在库存分录后亦不可修改（分录只存数量，改单位等于篡改历史）。
- **单位转换**（MaterialUnit，`inv_material_unit`）：物料级换算事实，一行＝「1 默认单位 = x 该单位」；（物料, 单位）唯一，单位不限类型但不能是默认单位，与全局单位 ratio 互不交叉校验。
- **图纸**：物料的图片附件槽位（`drawing`，仅图片、可多张）；其他文件走默认槽位。
- **叶子分类**（`is_leaf`）：可挂物料的末级分类；叶子不能再有子分类。与科目的 `is_group` 语义相反。
- **分类编号**（`code`）：人工定义、全局唯一的分类学编码，作为物料编号前缀；初始化向导完成时种子两级：大类单字母（`F` 产品 / `P` 包材 / `E` 设备工量具 / `M` 劳保耗材 / `S` 服务，非叶子），叶子为 `大类(子类)` 形态（如 `F(P)` 客户产品成品、`P(W)` 木箱；已有分类则跳过）；可改，已生成的物料编号不追溯。
- **仓库**（Warehouse，`inv_warehouse`）：按公司的树形仓库主数据；**仓库编码**挂编号规则（系统生成、公司内唯一、创建后不可改，初始化预置 `B(W)-` + 4 位补零序号按公司分桶），名称必填且公司内唯一；新建公司（含初始化向导首个公司）时与公司同一事务自动种子三仓——`{公司编号} - 所有仓库`（非叶子根）、`{公司编号} - 默认仓库`（叶子）、`{公司编号} - 在途`（叶子），任一步失败整体回滚；种子仓无特殊保护，可改可停可删（受常规约束）。
- **叶子仓库**（`is_leaf`）：树语义照搬物料分类先例——非叶子仓只做层级归集、不持有库存，只有叶子仓能发生库存；上级只能选非叶子仓、可空（多根并列，「所有仓库」非强制总根）、不能选自身（多级成环留跟进）；新仓默认叶子、默认启用；有下级的不能改叶子/不能删；存在库存分录（含已作废）的仓不可删除、不能改为非叶子（分录只落叶子仓，改则历史与树语义矛盾）。
- **仓库关联科目**（`account_id`）：仓库指向本公司存货科目的可空引用，为将来出入库记账找科目用；限本公司、非汇总（叶子）、本币（币种为空）科目；多仓可共用一科目；随时可改不追溯（库存金额账落地后改科目的估值口径问题留跟进）；被引用的科目不可删除；种子三仓一律留空。库存 v1 只记数量，此字段继续空转。
- **仓库启停**（`active`）：默认启用；停用**拦新不拦旧**——新单据用仓（手工出入库单头仓、调拨三仓）保存时校验必须启用，已发货调拨单的收货不再校验（在途必须能收尾）；不级联下级；列表行操作切换，不进编辑表单。
- **外协仓**（`is_outsourced`）：仓库标记（默认否），语义为货物存放在协作方处的**我方**仓；为是时必挂**协作方**（一仓绑一方）；委外发料审核把材料从调出仓移入外协仓、委外入库审核按消耗从外协仓扣减，外协仓结存＝协作方处结存的我方材料；委外单据选外协仓时只列绑定当前对手的仓；账目不跨公司——协作方是内部公司时同样进我方外协仓，对方要在自己账上反映自行录手工出入库单（同采购入库不镜像先例）。（由占位标记升级为实义，随委外采购一并落地。）
- **允许负数库存**（`allow_negative`）：仓库标记，默认否（最严方向）；库存分录落地后生效——审核与作废按（叶子仓×物料）校验「Σ 未作废分录 + 本单变动 ≥ 0」，任一行不过则整单拒（草稿不校验）；打开此标记的仓跳过校验；仓级口径、不跨仓相抵；只校验当前总余额，补录历史单的逐时点穿零留跟进；作废会致负同样禁止作废。
- **其他库存单**：库存管理菜单下的 IA 分组入口（非领域实体、无独立资源/权限码），承载无业务上游的库存来源单据——页内三 tab：出入库 / 调拨 / 盘点，分别对应手工出入库单、手工调拨单、库存盘点单；列表公司为首列可筛（无顶部全局公司），建单时公司在表单头选择。相对将来采购入库/销售出库等业务线单据而言的「其他」。
- **手工出入库单**（StockDoc，`inv_stock_doc`）：仓管无上游单据直接录入的库存来源单据，入库/出库一体——`direction` 字段区分、创建后锁死，编号单一系列；头=公司（创建后不可换）+单头一仓+业务日期（默认当天，可改即补录）+摘要（带入库存分录 remarks）+备注（内部长文本）；行=物料+单位（限默认单位或转换单位）+录入数量+折算数量（系统折算默认单位、6 位小数、不可手改）+行备注，随行冻结物料/单位快照；状态机 草稿→已审核→（已作废），仅草稿可改可删、无反审核、无关闭态（审核即履行完毕）；审核派生分录（入库为正、出库为负），作废过负库存校验；期初建账走入库方向，不开专用通道。菜单入口在「其他库存单 → 出入库」。
- **库存余额**：分录的只读聚合视图——按（仓×物料）`Σ 未作废分录`，支持截至日回溯（业务日期 ≤ 某日）；纯查询聚合直连分录表，无投影表。呈现为两个只读界面：**库存余额表**（公司下仓×物料，仓树/物料筛选、隐藏零行，在途仓自然呈现）与**库存分录流水**（按仓/物料/日期/来源单据筛选，可跳来源单据）；物料视角=余额表排序筛选，不单设界面；报表复用分录 read 权限码。
- **手工调拨单**（StockTransfer，`inv_stock_transfer`）：同公司两仓间移货的单据，头=调出仓+调入仓+在途仓（默认带种子在途仓，可改，限本公司叶子仓）；状态机 草稿→已发货→已收货——发货审核写「调出仓负+在途仓正」分录，收货确认写「在途仓负+调入仓正」；收货按行确认实收（默认=已发，可改小不可改大），差额留在在途仓由手工出入库单（出库）清理；一次收讫不分批；已发货不可作废（纠错走反向调拨）；限同公司，跨公司调货是买卖，走销售/采购线。菜单入口在「其他库存单 → 调拨」。
- **库存盘点单**（StockCount，`inv_stock_count`）：核对账实并校正库存的来源单据；单头一仓（公司创建后不可换+启用叶子仓+业务日期默认当天可改+摘要带入分录+备注，同手工出入库单先例），行=本次要盘的物料清单（物料+账面数量+实盘数量+行备注，行保存冻结物料/单位快照），允许部分盘点——未列入的物料不受影响，盘点单只对其列出的行负责。账面数量=取数时刻的库存余额快照（创建/整仓带出时落行，可整单刷新，刷新只更新账面数量列、已填实盘数保留）；整仓带出口径=账面非零行（同余额视图默认），账面零的物料手工加行（实物有账面无的盘盈场景）。实盘数限默认单位或转换单位录入、系统折算双份落库（同手工出入库单行先例），必填且≥0。差异=实盘−账面，审核时差异非零的行派生一条带符号库存分录（盘盈正、盘亏负），零行不落；审核要求至少一行、逐行实盘数已填，有空行整单拒（补数或删行），不做静默跳过。审核兜底校验：快照后该仓分录有新增或作废（按分录创建/作废时间判定，补录的历史单照样命中）则拒绝审核，须刷新重取；不做冻结，取快照到审核之间该仓尽量不动货、取快照前确认单据已录齐（作业纪律）。单头仓限本公司启用叶子仓（在途仓不另设禁令，作业上盘点前先收尾相关在途调拨，否则物理已到货未收货会盘出假盘盈）；不做同仓并发盘点硬约束——兜底校验天然串行化审核，后到者刷新即收敛。状态机 草稿→已审核→（已作废），仅草稿可改可删、无反审核、无关闭态；差异分录永不致负（校验通过时审核时点余额恒等于快照、调整后恒等于实盘≥0），作废照常过负库存校验。编号挂编号规则（系统生成），权限码 `inv.stock_count`。菜单入口在「其他库存单 → 盘点」。
- **库存分录**（StockLedgerEntry）：库存领域唯一事实表，只追加不可改；由来源单据审核时派生，用户无直接写入口（同 GL 分录先例）；库存余额=分录聚合，报表只查分录不查单据；作废=标记不删行；**不做红冲**——更正=作废（过负库存校验）+重开，待采购/销售线单据有下游勾稽再议红冲。一行=一次「叶子仓×物料」的数量变动（一单据行派生一条，不合并），数量带符号（入正出负、非零），恒为物料默认单位口径（表上无单位字段，6 位小数）；字段含公司、叶子仓、物料、数量、来源单据多态引用（voucher_type/voucher_id/voucher_no，同 GL poly-ref）、业务日期、seq、is_cancelled；不做批次/序列号/保质期/库位维度，客户料不设独立维度（物料主数据已区分）。数量账来源含手工出入库/调拨/盘点、**销售发货**（发货审核写负向分录）、**采购入库**（入库审核写正向分录）、**生产入库**（入库审核写正向分录，上游生产工单；执行层落地后生效）与**委外发料/委外入库**（发料审核写「调出仓负＋外协仓正」，入库审核写「外协仓负＋成品/副产物入仓正」；随委外采购落地），退货三类随退货模块落地——**销售退货**（审核写正向回库分录）、**采购退货/委外退货**（审核写负向出仓分录，委外退货不动外协仓）；v1 分录本身只记数量不记金额——销售发货的应收、采购入库的应付过账走总账分录，不在库存分录写金额；生产入库第一期亦只数量不过生产成本总账；采购线已落地但估值方法仍未定案（见采购线 ADR 重申推迟：记金额须连同出库计价/发货成本/盘点差异一起设计），届时纯加列，历史行金额空=未估值）。
- **来源单据速览**：从库存分录的来源单据列进入的只读核对界面；展示来源单据的单号、状态、关键头信息和库存相关行，不提供编辑或审核入口。查看范围始终受来源单据查看权限与公司数据权限约束，能查看库存分录不代表能穿透查看来源明细。
- **打卡记录**（AttendancePunch，`hr_attendance_punch`）：考勤机原始打卡事实（员工+时刻），导入是唯一入口，不可改；(员工, 时刻) 唯一。
- **考勤导入批次**（AttendanceImport，`hr_attendance_import`）：一次 .dat 导入的留痕单据，只存解析摘要不存暂存行；destroy 即撤销（级联删其打卡）。
- **考勤机编号**（`attendance_no`）：员工在考勤机上的编号，非空时全局唯一；.dat 行凭它匹配员工。
- **[未知] 员工**：导入勾选自动创建的占位员工（name=[未知]，attendance_no 回填），身份落实后直接改名，无合并动线。
- **日考勤**（AttendanceDay，`hr_attendance_day`）：按 (员工, 自然日) 派生的考勤结果行（四段时刻+工时+加班+奖励工日），随打卡/补卡自动重算，人工不可直改。
- **补卡单**（AttendanceCorrection，`hr_attendance_correction`）：计算层的虚拟打卡单据（一单一人一天多卡），重算时与真实打卡合并取值；原始打卡永不修改。
- **缺卡**：某半天桶内只有一张卡，该段计 0 工时并标异常；桶内无卡是「无出勤」不是缺卡。
- **加班工时**：下午段（取整后）超 4 小时的部分；上午封顶 4 小时，不产生加班。
- **奖励工日**：单日加班 ≥3.5 小时额外奖励 0.5 工日（日封顶 0.5），与月末加班补贴并行，不是小时折算。
- **工日**：8 正常工时=1 工日；月工日 = Σ正常工时÷8 + Σ奖励工日，在月层核算。
- **工资单**（Payroll，`hr_payroll`）：(员工, 月) 唯一的薪资快照单据；应发 = 工日×日薪+补贴+奖金−罚款−借款抵扣。待发放可改可删，已发放锁死。
- **发放记录**（PayrollPayment，`hr_payroll_payment`）：一次实际发钱的留痕，一张工资单可多条；首笔翻转工资单为已发放，后续为补发；金额可负（冲回）。
- **补发**：工资单已发放后追加的发放记录（考勤漏算等差额），不回头改单。
- **借款台账**（EmployeeLoan，`hr_employee_loan`）：员工借款/归还流水，余额=Σ借款−Σ归还（员工级，不做单笔核销）；工资单发放时按借款抵扣自动生成归还行。
- **会计科目**（Account，`bas_account`）：每个公司独立维护的一棵借贷方向科目树，编码在公司内唯一；父科目必须同公司且不可选择自身或任意深度的下级。汇总科目仅归集、叶子科目可入账；创建后公司不可变，有下级或已被业务引用时不可删除。
- **科目角色**（AccountRole，`bas_account.role`）：标记科目用途的可空标记，分两族——**往来角色**圈定应收应付报表口径，**费用角色**（即报销类型）供报销类单据带出费用科目；只能挂叶子（非汇总）科目，外币科目不可挂；同公司多科目可挂同一角色，报表自动合并。
- **往来角色**：应收应付报表口径的七个角色——未开票应收 / 应收账款 / 预收账款 / 未开票应付 / 应付账款 / 预付账款 / 其他应付款；枚举写死在代码里，新增角色即加枚举值。挂往来角色科目的分录必须填对手（红字行豁免）。应收账款避免称「已开票应收」。
- **应收应付报表**：纯 GL 时点余额视图——截至日前（含）未作废分录按对手×往来角色轧差；没过账就不存在，不区分币种。列表按当前 tab 展示未开票/应收账款（应付侧再加其他应付款）与净额；预收/预付列不展示但仍计入净额。
- **净应收/净应付**：净应收 = 未开票应收 + 应收账款 − 预收账款；净应付 = 未开票应付 + 应付账款 + 其他应付款 − 预付账款；各角色按自然方向轧差，反向余额显示负数不搬列。避免称「欠款金额」。
- **往来明细**：应收应付报表按对手打开的只读流水——截至日前未作废、当前 tab 展示列对应往来角色的分录，按来源单据压行（销售发货/退货、采购入库/退货、委外入库按条目拆），倒排展示、顺跑累计。避免称「往来凭证记录」。
- **未指定对手**：挂往来角色科目上无对手的存量分录在报表中的兜底行；新过账已强制往来角色科目分录必须填对手。
- **对手**（Party）：单据上交易对手的多态引用（类型+ID，无真外键），取值供应商/客户/内部公司/员工四类（员工 = `hr_employee` 主数据）；类型与对手同填同空，保存时校验存在。挂往来角色科目的分录必须填对手。
- **地址**（PartyAddress，`bas_party_address`）：挂在客户 / 供应商 / 内部公司上的地点主数据（从属单方，一址一方；员工现住址不在此列）；一主体可多条；无独立菜单，主要在主体抽屉「地址」tab 维护；省/市/区取中国行政区划级联（存中文名），另加**街道门牌**自由文本；不做跨主体共享同一行，不设独立区划主数据表。
- **地址用途**（`purpose`）：地址的业务分类——**收发货**（`SHIPPING`）/ **通信办公**（`OFFICE`）/ **其他**（`OTHER`）；履约取货送货优先收发货用途，通信与抬头类用通信办公；发票票面「地址电话」仍是票面自由文本，不在此用途内。
- **默认地址**：同主体同用途下至多一条默认标记；新建/改默认时顶替旧默认；将来单据选址可回落默认（本期主数据不挂单据字段）。
- **计量单位**（Unit，`bas_unit`）：按长度、面积、重量、数量四类维护的全局共享计量主数据；名称必填，符号全局唯一，换算比例必须大于 0；已被物料、行情或业务单据引用后不可删除。
- **基准单位**：某单位类型下换算比例恒为 1 的单位，每类型至多一个；同类型其余单位按换算比例折算到它。
- **换算比例**（ratio）：单位折算到同类型基准单位的比例，必须大于 0（如 kg 为基准时 g=0.001）。
- **总账分录**（GLEntry，`acc_gl_entry`）：全系统唯一财务事实表，只追加不可改；由来源单据审核时派生，报表只查分录不查单据。作废=标记 `is_cancelled`，不删行。
- **手工会计凭证**（GLJournal，`acc_gl_journal`）：财务人员直接录入的凭证头与凭证行；状态机为草稿→已审核→已取消。仅草稿可改删，审核在同一事务内锁定头行、复检配平并经 GL 追加总账分录，取消同事务标记来源分录作废；已取消是终态。
- **红冲**（红字冲销）：对已入账分录组的更正方式——原分录逐条金额取负生成红字分录组对冲，原组标记「已被红冲」；不删不改，名下分录合计归零。
- **汇总科目**（`is_group`）：科目树中只做层级归集、不可入账的节点；与物料「叶子分类」语义相反。
- **银行账户**（BankAccount，`acc_bank_account`）：公司自有银行资金账户主数据；别名/账号同公司唯一，可绑定一个会计科目；退出方式为停用而非删除。流水上的对方户名/账号只是文本，对手方不是主数据。
- **银行流水**（BankTransaction，`acc_bank_transaction`）：银行对账单的电子档案行，数据以银行为准（余额取银行快照不推算）；收/支恰一项大于零；不参与记账，不直接派生分录。
- **流水导入模板**（BankImportTemplate，`acc_bank_import_template`）：某银行账户导出文件的列布局解析配置（列号+格式+起始行）；一个账户可配多份。
- **流水导入批次**（BankImport，`acc_bank_import`）：一次上传解析的留痕单据，状态已解析/解析失败/已导入；已导入只读不可删，暂存行随批次级联清除。
- **银行对账记录**（BankReconciliation，`acc_bank_reconciliation`）：流水与已审核凭证的 m-n 金额勾稽；同一对流水-凭证仅一条，调整=解除后重建。流水的**对账状态**（未对账/部分对账/已对账）按已对账合计自动推出。
- **承兑票据**（Bill，`acc_bill`）：承兑汇票票面主档，票号全局唯一、跨公司共享；建档随接收交易，无独立新建入口。
- **子票段**：等分化票据包的金额区间 [子票起, 子票止]，1 元=100 子票；交易与持有均精确到段，段金额=（止−起+1）÷100。
- **承兑交易**（BillTransaction，`acc_bill_transaction`）：接收/转让/兑付/贴现/调拨五类单据，草稿→已审核→已作废，是 GL 凭证来源；调拨为同公司跨银行账户的持有段迁移，不生凭证。
- **持有承兑**（BillHolding，`acc_bill_holding`）：「公司—银行账户」粒度的段级库存只读投影，由已审核交易按票全链重放、整删整建；无手工入口。
- **库存重放**（BillLedger）：按票把全部已审核交易按（发生日期, 审核时间）折叠重建持有段的机制；「后续动过不可作废」由此成立。
- **开票方向**：发票的开入（进项）/开出（销项）属性，决定过账分录的借贷安排。
- **对向发票**：内部公司互开发票时，同一张纸面发票在双方公司台账中互链的记录（一方开出↔另一方开入）；保存后可一键生成对方草稿。
- **待办**：从源单据状态推导的物化提醒设施（横切、不引流程引擎）——随源状态自动出现/关闭/复活，用户侧只有已读与个人忽略；不反向驱动单据状态机，无指派/截止/优先级/催办。第一期生产者为对账确认→开票/收票。见 ADR 2026-07-25 与 [待办](业务模块/待办.md)。
- **开票待办**：常规销售对账单客户确认时产生的销项提醒；对「可见该公司 + 持发票创建权限」的用户可见；关联开出发票审核结单关闭，撤回确认消失，发票作废/红冲退回确认态时新建复活。
- **收票待办**：常规采购对账单供应商确认时产生的进项提醒；可见性与关闭/复活语义镜像开票待办。
- **个人忽略**：用户对待办的个人痕迹（仅影响本人列表）；忽略时记录复位基准，源单状态变化产生新待办后自动失效，避免永久漏掉。
- **半天桶**：以 12:00 把一天切成上午/下午两桶；桶内最早卡=上班、最晚卡=下班，段工时按 30 分钟向下取整。
- **财务设置**（`acc_setting`）：财务域全局配置单行表（种子行恒存在、只改不增删，配置统一加字段不另建表）；菜单入口「财务 → 财务设置」；当前字段为阿里云 OCR 凭证（发票/承兑票面识别用），AccessKey Secret 只写不回读。
- **系统设置**（`sys_setting`）：系统级全局配置单行表（同 `acc_setting`/`sal_setting` 先例，种子行恒存在、只改不增删，配置统一加字段不另建表）；含初始化完成时刻（空即未初始化、向导开放），以及**行情拉取**定时开关/最新价间隔/结算自动补与上次运行摘要。
- **权限码**（权限点）：按「域.资源:动作」组织的操作能力，由代码派生不入库；**无通配**——授权一律写具体码，内置 admin 经全域授权旗标覆盖全部权限码（新权限点自动覆盖）。见 ADR 2026-08-04（封闭谓词代数）。
- **权限目录**（permission catalog）：全部权限码的代码派生清单，按「域 → 资源（prefix + 中文标签 + 动作集）」组织并标注每资源支持的数据范围，是角色权限配置界面与授权 sync 的共同基准。
- **数据范围**（范围）：授权三元组「角色 × 权限码 × 范围」的行级维度，取值为封闭集——全部 / 本部门及以下 / 本部门 / 仅本人 /（预留）记录级授权；多角色取并集，公司授权恒为外层边界；范围词汇表封闭不再增长。
- **部门**（Department，`sys_department`）：挂公司的组织树主数据，系统管理维护；用户至多属一个部门（兼任场景将来演进）。停用只拦新挂接（存量挂接保留）；移动节点连同整棵子树搬迁。
- **归属部门**：行级数据的部门盖章——创建时按创建人部门固化、不可手填、人员调动不追溯存量行；资源按元数据声明是否启用。
- **指派部门**：行级数据的业务指派部门（如需求单的下发车间），由业务动作填写、不受操作者部门约束；与归属部门二选一作为资源的部门范围绑定列。
- **记录级授权**：对单条记录的显式授权（共享/委派给用户/部门/角色），数据范围代数的预留泄压阀；首个消费者出现前不实现。
- **授权凭证**（Permit）：一次授权判定的通过凭证，服务层的唯一入场券——只能由判定内核签发，携带该次动作允许触达的行集描述。
- **系统主体**：非用户身份的内部调用主体（调度器/种子等），显式取授权凭证并旁路行级范围；取代匿名「受信任调用」约定。
- **标准动作**：权限动作的常规十件套（create/read/update/delete/print/import/export/batch_delete/batch_update/batch_print），角色权限矩阵中平铺为列。
- **工作流动作**：标准动作之外的资源特有动作（审核/关闭/作废/发货/收货/对账等），矩阵中收进行内「更多」展开区。
- **菜单权限**（菜单白名单）：角色级**菜单可见性**配置，纯导航呈现层，与权限码正交——管「看不看得到入口」，不管「做不做得了事」，**不拦 URL 直达**，不是数据范围（行级数据权限见「数据范围」词条）。角色存「可见菜单集合」（`sys_role_menu`，形态对齐角色权限行）：**空集合 = 未启用限制 = 全可见**；多角色取白名单**并集**（所有角色均未配置才不限制，停用角色不参与）；只配**叶子菜单项**，组/模块可见性由子项派生；超管恒不限制。每个叶子菜单项有稳定 **菜单 code**（`menu.<模块>.<路径末段>`，发布后不可改，改名=删旧增新）；菜单事实源为前端静态声明，后端菜单目录仅供写入校验（目录外 code 拒绝）与已失效项判定，两侧契约测试对拍。孤儿行（菜单删除/改名后的存量白名单行）保留不自动删，配置界面提示可一键清理；新菜单项对已限制角色默认不可见。配置入口为角色列表「权限与菜单」统一抽屉的「菜单可见性」页签（与「功能权限」页签同容器、强隔离；菜单项旁标注关联权限资源，点击切页签跳转权限矩阵对应行，关联声明在前端菜单声明上并与权限目录契约对拍），管理操作由 `sys.role_menu`（read/update）权限码门控。见 ADR 2026-08-01。
- **初始化向导**（Setup）：全新部署首启时的一次性业务初始化——建首个超级管理员（含其首选语言）、建首个公司（从预置的约 20 种常用货币选本币、必选一套科目表模板；三套模板均为当前单据、报销自动带出和应收应付报表预置完整且唯一的 12 个科目角色；预置货币默认全部停用，选定本币后仅本币启用，其余须事后手动启用）、落初始化完成旗标并幂等种子内置存储接入、编号规则、物料两级分类、机加工常用计量单位与内置角色。可选**示例数据**起步：完成时为首个公司写入覆盖全业务链的示例数据——客商/物料/员工等主数据、销售与采购全链单据（报价→订单→发货/入库→对账→发票，各一条链走到发票结单）、委外全链单据（委外 BOM/外协仓→委外订单→委外发料→委外入库→加工费对账）、库存出入库/调拨/盘点、工序/工艺模板/BOM，以及银行账户与流水、手工凭证、报销单、工资单与销/进项发票（电气/机加工演示场景，近 3 个月日期分布；以客户编号 `C01` 幂等）。空库只需迁移即可启动，无需再跑 seeds；旗标落库后入口永久关闭。常用货币与内置角色只随初始化出现，老环境不强塞。开发复位到未 setup：`bun run db:reset`（仅本地/dev DSN）。
- **内置角色**：随初始化向导完成动作统一种子的预置角色（ADR 2026-07-29），`builtin` 标记仅为「预置」身份，分配给用户照常。系统保护仅余 **admin**（持全域授权旗标，新权限码自动覆盖；菜单白名单恒空=不限制）——不可改、不可删、不可停用、授权与菜单只读；**其余预置角色初始化后与普通角色同权**——可改名、可停用、可删、授权与菜单可维护（ADR 2026-08-10 预置角色放开编辑）。当前预置两个：admin 与 **sales**（销售业务员，逐码授权销售链、附件（sys.file:*，不配附件管理菜单）与只读主数据（含物料分类、公司、部门）+ 销售链菜单白名单，授权与菜单清单见 `server/src/platform/setup/service.ts`）。
- **Setup API**：`/api/v1/setup/*` 的初始化切片（产品后端 `server/`）；首用户创建、货币预置/选本币、完成动作均受同一 PostgreSQL 事务级 Setup 锁保护。首用户并发只允许一个成功，同时置 `super_admin=true`、`all_companies=true` 并返回 JWT；完成动作先写首选语言与幂等基础种子，再（可选）调用领域服务写入全业务链示例数据（`server/src/modules/setup/sampledata`，客户 `C01` 幂等），最后写 `setup_completed_at`；示例失败不落完成旗标。Web 向导可选空白/示例起步，`seedSampleData` 按路径提交。
- **超级管理员**：用户级旗标，绕过一切功能与数据权限检查；仅初始化向导设置，常态界面无入口。
- **首选语言**（`sys_user.preferred_language`）：用户级界面语言偏好，由初始化向导为首个用户设置一次；i18n 落地前纯占位、无任何界面效果。
- **外观模式**（Appearance）：本机界面色阶偏好（仅浏览器本地持久化，不落用户表、不跨设备同步），三选一——**白天**（强制浅色）、**黑夜**（强制深色）、**系统**（跟随操作系统 `prefers-color-scheme`，OS 变更时即时跟随）；默认未选时为系统。首屏在 hydrate 前按本机键解析并挂到文档根，避免反色闪烁；同源多标签页经本机存储变更即时同步。**品牌仪式面**（启动幕布、App Shell 左侧模块图标栏、登录页左栏品牌区、向导同类品牌块）恒定深色不跟随；**业务/表单面**（内容区、二级菜单、顶栏、登录右栏、业务页）跟随色阶。切换入口为三选一控件（白天 / 系统 / 黑夜），置于用户菜单；登录页与初始化向导提供同款弱化入口。打印走独立浅色文档窗，不在外观模式范围内。纯外观色阶，不是品牌皮肤，不按公司/角色分主题。
- **公司授权**：用户级数据权限，显式授权、默认不可见（fail-closed）；挂用户不挂角色。
- **审计日志**（AuditLog，`sys_audit_log`）：数据写操作的字段级留痕（旧值→新值），只增不改不删；敏感字段不落值。
- **编号规则**（NumberingRule，`sys_numbering_rule`）：绑定单据类型的自动取号规则，内容为固定文本/记录字段/序号的有序段组合，每单据至多一条启用；序号按段渲染结果（及公司）隐含的范围独立计数，无独立重置周期。字段段取值为空时省略该段（不报错）；序号 `padding` 为 0 表示不补零，1..12 为补零位数。 **编号计数器**（NumberingCounter，`sys_numbering_counter`）由取号自动按规则与范围生成；管理员可校正当前值且必须留审计，删除规则级联删除计数器。
- **单据编号 vs 业务编码**：系统内两类"号码"分治——**单据编号**（订单号/单号/凭证号/员工编号/BOM 编号/仓库编码/部门编码等挂编号规则的字段）一律由系统按启用规则生成，**不接受手填**（create 传值 422，创建后不可改）；唯一性口径跟着计数方式走——按公司计数的（全部公司级单据）**公司内唯一**，不按公司计数的（物料/员工/工序/工艺模板/BOM 等全局主数据）**全局唯一**。未配置启用规则时保存直接报错（"未配置启用的编号规则，请先在 系统管理 → 编号规则 配置"），停用/删除规则不拦（管理员的自由度，报错文案可自助恢复）。**业务编码**（公司/客户/供应商/会计科目/物料分类的 code）是有人工语义的助记码，维持手填——公司/客户/供应商编码会作为段嵌入其他单据编号（物料编号含客户编号段、按公司计数用公司编码分桶），故客户/供应商编码限字母数字（防分隔符污染组合编号与计数分桶键），公司编码限恰好两位英文字母。决策见 [ADR 2026-08-06](系统架构/adr/2026-08-06-system-generated-numbering.md)。
- **文件**（File，`sys_file`）：一个不可变的已上传文件对象；单文件上限 50MB，元数据记录原始文件名、存储接入名、对象键、大小与 SHA-256，有业务挂接或打印模板引用时不可删除。
- **存储接入点**（StorageEndpoint，`sys_storage`）：文件字节的存放位置（本地/S3 兼容对象存储/OSS）；全局恰有一个默认接入点，默认切换串行化，新上传落默认点；访问密钥只写不回读。
- **文件挂接**（Attachment，`sys_attachment`）：文件与业务记录的关联；宿主类型使用显式白名单且未知类型 fail-closed，公司型宿主把公司归属固化到挂接；有挂接的文件不可删，列表与下载同时按公司范围和宿主读权限判定。
- **打印模板**（PrintTemplate，`sys_print_template`）：某资源类型的单据版式模板主数据——名称+资源类型（取权限资源码，如 `sales.order`）+模板文件（.xlsx，复用文件挂接机制）+默认标记（同资源至多一份默认）+备注；全局共享不分公司，公司抬头等由占位符取单据公司字段渲染；可改（换文件）可删；模板始终有且仅有一个 `sys_print_template`/`template` 文件挂接，换文件同步换挂接，删模板只清挂接不删文件；无引用约束（打印是瞬时动作，不留痕不追溯）；上传即校验——只收 .xlsx，提取全部占位符对照该资源字段清单，有未知字段拒绝保存并逐个点名；纸张大小/方向/页边距/打印区域由 Excel 页面设置承载，系统不建字段、渲染不覆盖不自行添加。可挂模板的资源覆盖权限目录全部资源——字段清单由打印模块统一目录提供，自 meta.Registry 单一事实源派生（迁移期 Ash 机械快照已在逐字段对拍证明等价后删除），新资源接入 meta 即自动进入目录；打印/导出/批量打印入口仍随标准动作逐资源启用。菜单「系统管理」组，权限资源 `sys.print_template`；资源模板与字段清单的使用权限为该资源 `print`/`export`/`batch_print` 或 `sys.print_template:read` 任一命中。
- **模板占位符**（`${field}`）：打印模板单元格内的取值槽位，可与普通文本混排于同一单元格；一律「关系.字段」路径式——头字段直写属性名（如 `${order_no}`、`${gross_total}`），belongs_to/has_one 关联展开一层（如 `${company.name}`、`${warehouse.code}`，不再下钻），带对手（Party）约定的单据另有 `${party.name}` 取对手名称；枚举值统一渲染为枚举类型的中文标签，布尔显示 是/否，空值填空字符串；字段清单由打印模块统一目录提供（自 meta.Registry 派生：资源标量与计算/投影字段 + belongs_to 一层关联展开 + 封闭枚举多态的 `party.name`，排除主键/外键 `*_id`/时间戳/敏感字段；子表多态外键只暴露原始 `party_id` 列），可用字段以模板管理页《字段清单》为准，字段标签即路径名本身；显示格式靠单元格自身的 Excel 格式设置，引擎不发明格式化语法；不支持图片类内容（图纸/Logo 留跟进）。
- **循环区**（明细模板行）：打印模板中含 `${关系.字段}` 且关系为某 has_many 的行——每个 has_many 都是一个循环区、按关系名寻址（如订单 `${items.*}`、BOM `${components.*}`/`${routes.*}`/`${byproducts.*}`）；引擎按该关系数据行数向下复制该行、下方内容自动下移，同一模板允许多个循环区顺序各占一段；行序号给 `${关系._seq}`；某循环区 0 行时其模板行整行删除；循环区字段派生规则同头字段（含其 belongs_to 一层路径）；嵌套循环（循环区目标资源自身的 has_many，如报价条目内套价格档）不支持、上传即拒；模板无循环区合法（纯表头版式）；合计等由用户在模板写 Excel 公式。
- **模板打印/模板导出**：单据版式输出动作，同一填充引擎两个产物——**打印**=模板填充后转 PDF 交浏览器（预览/打印/另存 PDF 皆为浏览器能力，系统不设"下载 PDF"），**导出**=填充后的 .xlsx 直接下载，两者版式恒一致；入口为单据行内按钮+列表批量按钮（先弹模板选择、预选默认模板），无可用模板时提示先去上传、不回退列表行打印；**批量打印**=N 份模板块顺序铺进一个 xlsx（块间分页符）一次转 PDF，**批量导出**=单 xlsx 多 sheet（sheet 名=单号），上限 100 条同步处理；与列表工具栏的 CSV 导出（列=grid 列的列表数据导出）语义切割、并存互不干扰。权限用标准动作 `print`/`export`/`batch_print`（批量导出不新增 `batch_export`，由 `export` 门控）。执行面走 REST 端点 `POST /api/v1/printing/render`（模板+单据→PDF/xlsx 文件流；Bun 渲染引擎 + soffice 哑转换，无 soffice 时打印报明确错误、导出不受影响）；单据装配逐资源接入，本期已接入销售订单，其余资源陆续接入（未接入资源报明确错误）。
- **销售订单**（SalesOrder，`sal_order`）：公司向客户承诺供货的订货单据，纯业务承诺——审核不派生任何会计或库存后果；实物出库与未开票应收由**销售发货单**承载，开票仍由发票模块承载；对手限客户/内部公司两类（多态引用，同 Party 机制）；一单一币：货币与汇率挂订单头，默认公司本币，全部条目跟随换算；状态机 草稿→已审核→（已关闭/已作废），仅草稿可改可删，已审核锁死无反审核，关闭不可逆。已关闭订单不可再发货；存在已审核未作废发货引用其条目时订单不可作废（须先作废相关发货）。
- **订单条目**（SalesOrderItem，`sal_order_item`）：销售订单的商品行（物料、单位、数量、原币含税单价、税率、行备注）；行单位限该物料默认单位或其单位转换单位，金额四列全部系统算不可手改（金额链，见「汇率」），随单级联删除；默认单位订购数量由系统折算，另冗余**已发数量**（默认单位）并由销售发货审核/作废同步加减，未发数量再由两者计算；这三项均不是条目新增/编辑时的用户录入字段。
- **订单类型**（`order_type`）：销售订单的分类——常规/样品两类，必填，保存后锁死不可改（换类型只能作废重开）；两类共用状态机、编号规则与权限码，系统层面不区别对待。
- **常规订单**（regular）：条目逐行强制引用**有效报价条目**（`quotation_item_id` 非空）；单价与单位随报价锁定——固定价直接带入，数量梯度按行数量自动套档（低于首档起订量视为无报价、保存报错），税率带入后仍可手改；客户/公司/日期/币种有存量条目时不可改（前端改即清空条目），审核时逐行复核报价引用与价格。
- **样品订单**（sample）：条目任选物料、手填单价，不带报价引用（`quotation_item_id` 必空）；单行数量 ≤ 供应链设置的样品上限（按行录入数量直接比，不做单位换算），审核复核。
- **本币**（`bas_company.base_currency_id`）：公司（记账主体）的记账货币，公司必填属性；单据双币换算的目标口径，报表聚合一律读本币口径。须为启用中的货币；被引用为本币的货币不可停用。
- **原币**（交易货币）：单据对交易对手报价所用的货币，一单一币挂单据头，默认取单据公司本币；原币即本币的单据照常落双套金额（汇率 1、两套同值），仅展示层简化。新建单据仅可选启用中的货币。
- **货币启停**（`bas_currency.active`）：币种主数据的启用状态；新建默认启用。停用**拦新不拦旧**——新单据币种与公司本币只能选启用币种，历史引用不受影响；被任一家公司引用为本币的不可停用。初始化向导预置常用货币时全部停用，选定本币后仅本币启用，其余须在货币管理页手动启用。
- **汇率**：单据头上原币→本币的换算率，手工填写（无汇率主数据表）；原币即本币时强制为 1，外币必填且大于零。金额链：原币金额=数量×原币单价（2 位）→本币金额=原币金额×汇率（2 位）；本币单价=原币单价×汇率（4 位）仅展示参考，不参与金额计算。
- **订单条目快照**（`material_code/material_name/material_spec/customer_part_no/unit_name`＋图纸挂接）：行保存时冻结的物料/单位口径，随审核锁死；主数据后续变更不回溯，订单上下文展示一律以快照为准。图纸为挂接复制（共享不可变文件），非字节复制。
- **已关闭**（closed）：销售订单的终止态——单据曾生效、经人工标记不再履行剩余（含部分已发后关单）；与已作废之别在于作废表示单据不该存在（有已审核发货时不可作废），关闭表示生效后提前终止剩余。关闭后不可再开销售发货；关闭不改已发数量与历史发货，已关闭订单上的发货仍可作废纠错。
- **销售报价单**（SalesQuotation，`sal_quotation`）：公司向客户/内部公司承诺价格的单据——纯价格承诺清单，条目只报单价没有数量，不构成数量/供货承诺（那是销售订单），不派生会计或库存后果；对手同 Party 机制限客户/内部公司；一单一币挂头默认公司本币，无汇率无双币（报价无金额可换算）；状态机 草稿→已审核→已作废（无「已关闭」，无反审核），作废兼承担录错与提前撤回。
- **报价条目**（SalesQuotationItem，`sal_quotation_item`）：报价单的价格行（物料、单位、定价模式、含税单价、税率、行备注），同一报价单内（物料, 单位）唯一（同物料不同单位是两种成交口径，允许并存）；行单位限物料默认单位或其单位转换单位；物料信息快照口径同订单条目（无图纸挂接）。
- **定价模式**（`pricing_mode`）：报价条目的计价形态，逐条目选择——固定价（行上一口含税价）、数量梯度（价在价格档上，行单价空置），以及**行情挂钩**（承诺计价公式，行上不含死价）；枚举可扩，新模式=加值+必要的子表/字段。
- **行情挂钩**（定价模式）：报价条目承诺「按某行情品种某价类 ± 调整项」的计价规则，不在报价单上冻结金属基价；销售订单（及采购订单）引用该条目时，按点价日取行情价点算出含税单价并冻在订单行。与固定价/数量梯度互斥（同行只选一种模式）。该模式尚未实现，两侧报价均在数据模型预留。
- **点价**：将行情挂钩公式结算为具体含税单价的动作；v1 默认在成单时（订单日期）发生，单价一旦写入订单行即冻结，盘面后续变动不回溯。
- **价格档**（QuotationTier，`sal_quotation_tier`）：数量梯度条目的起量价阶梯——每档 =（起订量, 含税档价），订购量 ≥ 起订量即适用该档价，档间上界由下一档隐含，低于首档起订量视为无报价；起订量同条目内唯一，档价不强制随量递减。
- **供应链设置**：供应链配置的统称，按模块拆为三个独立设置页（销售管理→「销售设置」、采购管理→「采购设置」、生产管理→「生产设置」）。**全局标量**落 `sal_setting` 单行表（种子行恒存在，只读改不增删，同 `acc_setting` 先例）——销售：样品订单单行数量上限、**发货超发比例**；采购：零星订单单行数量上限、**入库超收比例**、**需求超安排比例**（行级安排占量总闸门，覆盖旧「需求超下单比例」语义）。生产设置页维护 `mfg_setting` 单行表（生产入库超入比例，权限资源 `mfg.setting`，不落 `sal_setting`）。**按公司的默认过账科目**落独立资源**公司默认过账科目**（不塞进 `sal_setting` / 公司主数据）。权限资源码仍为 `sales.setting`。
- **公司默认过账科目**（CompanyAccountDefault，一公司一行）：各公司在发货/入库表头预填用的借贷科目默认值——四槽均可空：发货借方、发货贷方、入库借方、入库贷方；校验口径与对应单据头科目完全一致（发货借强制「未开票应收」角色、入库贷强制「未开票应付」角色，另一侧本公司启用非汇总、角色不限）。设置页先选公司再编：销售 Tab 只维护发货两槽、采购 Tab 只维护入库两槽（本 Tab 保存 upsert 本侧两槽，不覆盖对侧）。无默认不挡建单；改默认不追溯已有单据。被引用的科目不可删除（同其它科目引用）。
- **已发数量**（`shipped_qty`）：订单条目上按物料**默认单位**累计的已履约出库量；事实来源为已审核未作废的销售发货行与销售退货源单行，条目列是受控投影——发货审核加、作废减、销售退货（挂源行）审核回减；剩余可发 = 订购数量（折默认单位）− 已发数量（容差内超发时可负；退货回减后缺口重现，可照常再发货）。
- **发货超发比例**（`delivery_overship_ratio`）：供应链设置中的全局容差（小数，如 0.05=5%），默认 0（禁超发），合法范围 0～100%；发货审核时要求该订单条目「累计已发（含本单）≤ 订购 base × (1 + 比例)」。
- **销售发货单**（SalesDelivery，`sal_delivery`）：对客户/内部公司的**履约出库**单据——审核同一事务内写负向库存分录、按行累加订单已发数量，并在本币过账金额大于零时按头上借贷科目生成总账分录（借方强制「未开票应收」角色科目、贷方自选；金额按订单条目快照本币含税金额 × 本行 base 占订购 base 比例汇总）；金额为零（赠品等）则**跳过总账**，但仍要求头上借贷科目已填（录入纪律，不造零金额名义分录）。头=公司+对手（客户/内部公司）+发货日期+过账日期（有金额审核时必填，默认发货日期）+头仓（可空，仅新建行预填）+备注+单号+**借贷科目（草稿保存即必填，表单位于条目表下方；新建/换公司时按该公司默认过账科目整组覆盖代入，无默认则清空；打开已有草稿且未改公司则保留单上科目）**；行=必挂订单条目+物料（须与条目一致）+单位/数量/base_qty+行仓（必填，本公司启用叶子）+行备注+物料快照+订单条目快照。**草稿保存以整单为原子边界**：表头、发货条目、装箱箱及其装箱行同事务全成全败；编辑提交保存后的完整快照，缺失的既有子记录视为删除；「保存并审核」先保存完整草稿再独立审核，审核失败保留已保存草稿。可跨多张订单，但全部行订单的公司、对手、原币必须一致；同一订单条目可在一单多行（如分仓）。状态机 草稿→已审核→（已作废），仅草稿可改可删，无反审核、无红冲、无关闭态；作废回滚库存分录、总账分录与已发数量（作废仍过负库存校验）；任一条目存在非零**已对账数量**（被生效中销售对账单消耗）则整单不可作废，须先撤回/作废相关对账单。只记卖方公司账，不向内部公司对手自动镜像入库。菜单在销售管理「交易」组（业务线履约出库，相对「其他库存单」）；列表双 tab（发货条目默认 / 发货单）。权限码 `sales.delivery`。
- **发货条目**（SalesDeliveryItem，`sal_delivery_item`）：销售发货单的商品行；单位限物料默认单位或其转换单位，系统折算默认单位 `base_qty`（6 位）供库存与已发累计；行保存冻结物料快照（编号/名称/规格/客户料号/本行单位名，并复制物料 `drawing` 图纸挂接到行）与订单条目快照（订单号、订购量与订购 base、价税与本币金额、税率、币种代码、订单行单位名等），过账与展示以快照为准。图纸为挂接复制（共享不可变文件），非字节复制；行/发货单删除时挂接一并清理。另冗余**已对账数量**（`reconciled_qty`，见同名词条），由销售对账单生效/回退同步加减。
- **装箱箱**（PackBox，`sal_delivery_pack_box`）：销售发货单下「一只实箱」的箱级实体——**箱号**（单内系统自增整数，生成后不可手改）＋**箱净重**（Σ 箱内装箱行行净重按单位换算比例折算到箱重量单位，系统算只读）＋**箱毛重**（手填，整箱过磅实测；不建皮重概念，毛净差隐含为包装）＋**重量单位**（限重量类单位，默认重量类基准单位，可改）；随单级联删除、删箱级联其装箱行、审核后随单锁死；不落库存/总账/投影、无账面后果。无独立权限码，随 `sales.delivery` 各动作。（箱由装箱行上的自由文本箱号升格为实体，见 ADR 2026-07-29 装箱箱实体与重量口径。）
- **装箱清单（行）**（PackLine，`sal_delivery_pack_line`）：销售发货单下「本票货的装箱明细」子表——行＝**所属箱**（必挂装箱箱）＋物料＋单位＋数量＋**行净重**＋行备注；同箱多行、一行一物料，一物料可拆多箱（分挂多箱多行）；单位限默认单位或转换单位，系统折算 `base_qty`（6 位），数量 > 0；行保存冻结物料文本快照（编号/名称/规格/客户料号/单位名，同发货条目口径但**不复制图纸挂接**）。随单级联删除、审核后随单锁死；不落库存/总账/投影、无账面后果，不进收发货历史。**整表可不填**；填了则审核时按物料汇总硬校验「Σ 装箱行 base ＝ Σ 该物料全部发货条目 base」逐物料相等——**全有或全无**：含发货外物料、任一物料不等、漏装任一物料均拒审；草稿不校验（同容差先例）。装箱行不挂发货条目（实物复核层，与金额/订单勾稽解耦）。无独立权限码，随 `sales.delivery` 各动作（同发料清单随父单先例）；作为发货单 has_many 循环区进入打印字段目录（`pack_lines`，平铺直挂发货单、箱字段走 belongs_to 箱一层展开），装箱箱另以独立循环区 `pack_boxes` 进入字段目录。
- **行净重**（`net_weight`，装箱行字段）：该行物料的**总净重**——默认按「行数量 × 重量换算」推导（规则见**行净重推导**），可手改为实测值；**有推导来源时数量/单位/物料变化即无条件重算**（总净重随数量必变，实测手改应在数量定稿后录入），无推导来源时手填值不动；行净重单位随推导来源或重量类基准单位、**不可手改**。重量字段全部可空、审核不拦；落库后随审核冻结，主数据换算后改不回溯；**不回写物料换算**（单次实测 ≠ 标准单位净重，建/改换算走物料主数据维护动线）。
- **行净重推导**：装箱行行净重的默认取值规则——行单位本身是重量类单位则直接用行换算折算；否则物料恰有一条**重量类**单位转换行则经它折算；物料有多条重量类转换行则不猜、默认空、手填。
- **箱净重 / 箱毛重**：装箱箱上的两个重量字段——箱净重＝Σ 箱内行净重按单位换算比例折算到箱重量单位（系统算、只读）；箱毛重＝整箱过磅实测（手填）；不设「毛重 ≥ 净重」硬校验。不建皮重概念。
- **装箱单**：装箱清单打印件的口语称呼（随货给客户那张纸）——不是独立单据，无独立编号、状态机与权限码；数据口径见「装箱清单（行）」。
- **销售退货单**（SalesReturn，`sal_return`）：对客户/内部公司的**退货回库**单据，与销售发货单平级——审核同一事务内写正向库存分录（回库）、挂源行的行累加发货条目**已退数量**并回减订单条目**已发数量**，有金额时按头上借贷科目生成总账分录（贷方强制「未开票应收」角色科目、借方自选，方向为销售发货反转；源单行金额随发货条目快照口径、手工行按手填价税×单头汇率）；金额为零**跳过总账**（科目仍必填，同发货先例）。头=公司+对手（客户/内部公司）+退货日期+过账日期（有金额审核时必填，默认退货日期）+原币与汇率（默认公司本币，含手工行时为全单换算口径）+头仓（可空，仅新建行预填）+备注+单号（挂编号规则，独立系列）+借贷科目（草稿保存即必填，按公司默认过账科目发货槽整组代入）。行两类可混、可跨多张发货单，但公司、对手、原币须一致。整单草稿为唯一写边界（同销售发货先例）；无装箱清单。状态机 草稿→已审核→（已作废），无反审核、无红冲、无关闭态；作废回滚库存/总账分录与已退/已发数量；任一条目存在非零**已对账数量**则整单不可作废，须先撤回/作废相关销售对账单。退货条目进销售对账条目池（金额取负、同池净额），自带**已对账数量**投影。已审核单单头「**生成补货需求单**」按钮把全部退货行转成一张履约需求单草稿（指派类型默认=库存、需求日默认=退货日期；可重复点击，需求单头以 `source_return_id` 留痕可反查）。只记卖方公司账，不自动镜像买方入库。菜单在销售管理「交易」组；列表双 tab（退货条目默认 / 退货单）。权限码 `sales.return`。
- **销售退货条目**（SalesReturnItem，`sal_return_item`）：销售退货单的商品行，两类——**源单行**必挂已审核未作废且剩余可退 > 0 的销售发货条目（数量 ≤ 剩余可退，物料/价税/订单快照随源行带入），**手工行**自填物料/单位/数量/含税单价/税率（无源单可挂的历史退货）；行保存冻结物料快照（含图纸挂接复制），口径同发货条目；另冗余**已对账数量**，由销售对账单生效/回退同步加减（对账时行金额取负）。
- **报价截止**（`valid_until`）：报价单有效期终点，截止当日仍有效；**已过期**是派生展示态（已审核 且 当前日期 > 截止日），不落库不跑定时任务翻状态。报价延期不改截止日，复制重报一张新单。
- **有效报价条目**：对某张销售订单而言可选的报价条目——报价单已审核，且订单日期落在 [报价日期, 截止日] 区间内，且报价单公司、对手（客户/内部公司一视同仁）、币种均与订单一致；有效区间起点即报价日期，无独立生效日。采购侧对称：有效采购报价条目对采购订单的同口径定义（对手换供应商/内部公司）。
- **采购报价单**（PurchaseQuotation，`pur_quotation`）：供应商/内部公司向本公司承诺价格的单据——全镜像销售报价单：纯价格承诺清单，条目只报单价没有数量，不构成数量/供货承诺（那是采购订单），不派生会计或库存后果；对手限供应商/内部公司（Party 机制，不能是单据公司自身）；一单一币挂头默认公司本币，无汇率无双币；状态机 草稿→已审核→已作废（无「已关闭」，无反审核）；报价截止/已过期口径同销售报价。条目结构（(物料, 单位) 唯一、定价模式、价格档、行快照）与销侧一致；行情挂钩模式同步预留未实现。采购侧不校验客户物料约束，任何物料均可报价。权限码 `purchase.quotation`。
- **购销单据公司首列**：采购报价、采购订单、销售报价、销售订单的条目与整单列表均以单据所属公司为第一列；条目直接使用随父单冗余的公司字段，便于跨内部公司浏览与筛选。
- **采购订单**（PurchaseOrder，`pur_order`）：公司向供应商承诺采购的订货单据，纯业务承诺——审核不派生任何会计或库存后果；实物入库与未开票应付由**采购入库单**承载，进项发票仍由发票模块承载；对手限供应商/内部公司两类（多态引用，同 Party 机制，不能是单据公司自身）；一单一币：货币与汇率挂订单头，默认公司本币，全部条目跟随换算（双币金额链同销售订单）；状态机 草稿→已审核→（已关闭/已作废），仅草稿可改可删，已审核锁死无反审核，关闭不可逆。已关闭订单不可再入库；存在已审核未作废入库（采购入库或委外入库）引用其条目时订单不可作废（须先作废相关入库，草稿入库则须先删除）。权限码 `purchase.order`。
- **采购订单类型**（`order_type`）：采购订单的分类——常规/零星两类，必填，保存后锁死不可改（换类型只能作废重开）；两类共用状态机、编号规则与权限码，系统层面不区别对待。
- **常规采购订单**（regular）：条目逐行强制引用**有效采购报价条目**（`quotation_item_id` 非空）；单价与单位随报价锁定——固定价直接带入，数量梯度按行数量自动套档（低于首档起订量视为无报价、保存报错），税率带入后仍可手改；对手/公司/日期/币种有存量条目时不可改（前端改即清空条目），审核时逐行复核报价引用与价格。
- **零星订单**（spot）：采购订单的自由录价类型——条目任选物料、手填单价，不带报价引用（`quotation_item_id` 必空）；单行数量 ≤ 供应链设置的零星上限（`spot_item_max_qty`，默认 100，按行录入数量直接比，不做单位换算），审核复核。采购侧不校验客户物料约束。
- **采购订单条目**（PurchaseOrderItem，`pur_order_item`）：采购订单的商品行（物料、单位、数量、原币含税单价、税率、行备注）；行单位限该物料默认单位或其单位转换单位，金额四列全部系统算不可手改（金额链，见「汇率」），随单级联删除；行保存冻结物料快照（编号/名称/规格/客户料号/单位名＋图纸挂接复制，机制同订单条目快照）；另冗余**已收数量**（默认单位），由采购入库审核/作废同步加减；可空挂**来源履约需求行**（勾选带入，一条目挂一需求行、同一需求行可分次被引；不再要求行级履约方式——需求行已无该字段；普通采购审核倒写**采购**安排、委外订单审核倒写**委外**安排；审核时累加已安排/已下单并复核行仍有效、过需求超安排比例）与可空**需求日**（带入自需求行，纯展示不驱动逻辑、不校验早晚）；手工行两者皆空，不受影响。
- **已收数量**（`received_qty`）：采购订单条目上按物料**默认单位**累计的已履约入库量；事实来源为已审核未作废的采购入库行、委外入库行与采购/委外退货源单行，条目列是受控投影——入库审核加、作废减、退货（挂源行）审核回减；剩余可收 = 订购数量（折默认单位）− 已收数量（容差内超收时可负；退货回减后缺口重现，供应商/协作方重送后照常入库）。沿「订单条目→需求行」的已完成回写**不随退货反转**（需求行保持已完成，补货由人工或销售退货的补货按钮发起）。
- **入库超收比例**（`receipt_overreceive_ratio`）：供应链设置中的全局容差（小数，如 0.05=5%），默认 0（禁超收），合法范围 0～100%；入库审核时要求该订单条目「累计已收（含本单）≤ 订购 base × (1 + 比例)」。
- **采购入库单**（PurchaseReceipt，`pur_receipt`）：对供应商/内部公司的**履约入库**单据——审核同一事务内写正向库存分录、按行累加订单条目已收数量，并在本币过账金额大于零时按头上借贷科目生成总账分录（贷方强制「未开票应付」角色科目、借方自选；金额按订单条目快照本币含税金额 × 本行 base 占订购 base 比例汇总）；金额为零（赠品等）则**跳过总账**，但仍要求头上借贷科目已填（录入纪律，不造零金额名义分录），仍出库存与已收。头=公司+对手（供应商/内部公司）+入库日期+过账日期（有金额审核时必填，默认入库日期）+头仓（可空，仅新建行预填）+备注+单号+**借贷科目（草稿保存即必填，表单位于条目表下方；新建/换公司时按该公司默认过账科目整组覆盖代入，无默认则清空；打开已有草稿且未改公司则保留单上科目）**；行=必挂订单条目+物料（须与条目一致）+单位/数量/base_qty+行仓（必填，本公司启用叶子）+行备注+物料快照+订单条目快照。可跨多张订单，但全部行订单的公司、对手、原币必须一致；同一订单条目可在一单多行（如分仓）。状态机 草稿→已审核→（已作废），仅草稿可改可删，无反审核、无红冲、无关闭态；作废回滚库存分录、总账分录与已收数量（作废减库存，仍过负库存校验）。只记买方公司账，不向内部公司对手自动镜像出库。菜单在采购管理「交易」组；列表双 tab（入库条目默认 / 入库单）。权限码 `purchase.receipt`。
- **入库条目**（PurchaseReceiptItem，`pur_receipt_item`）：采购入库单的商品行；单位限物料默认单位或其转换单位，系统折算默认单位 `base_qty`（6 位）供库存与已收累计；行保存冻结物料快照（编号/名称/规格/客户料号/本行单位名，并复制物料 `drawing` 图纸挂接到行）与订单条目快照（订单号、订购量与订购 base、价税与本币金额、税率、币种代码、订单行单位名等），过账与展示以快照为准。图纸为挂接复制（共享不可变文件），非字节复制；行/入库单删除时挂接一并清理。另冗余**已对账数量**（`reconciled_qty`，见同名词条），由采购对账单生效/回退同步加减。
- **采购退货单**（PurchaseReturn，`pur_return`）：对供应商/内部公司的**退货出库**单据，与采购入库单平级、全镜像销售退货单反转——审核同一事务内写负向库存分录（出仓）、挂源行的行累加入库条目**已退数量**并回减订单条目**已收数量**（**需求行已完成不随退货反转**，退货后补货由供应商重送、已收回减后未收缺口重现照常入库，故无补货需求单按钮），有金额时总账 借未开票应付（带对手）/贷选定科目（方向为采购入库反转，源单行随入库条目快照、手工行按手填价税×单头汇率），金额为零跳过总账（科目仍必填）。行两类可混（源单行挂已审核未作废且剩余可退 > 0 的采购入库条目、手工行自填价税），可跨多张入库单，公司/对手/原币须一致。整单草稿为唯一写边界；状态机 草稿→已审核→（已作废）；作废回滚；任一条目存在非零已对账数量则整单不可作废。退货条目进采购对账条目池（金额取负、同池净额）。菜单在采购管理「交易」组；列表双 tab（退货条目默认 / 退货单）。权限码 `purchase.return`。
- **委外标记**（`is_outsourced`，采购订单头）：布尔标记，为是即**委外订单**——条目＝委外加工回来的成品、条目含税单价＝加工费单价；与订单类型（常规/零星）正交：常规委外条目照常强制有效采购报价引用（供应商对成品的报价即加工费报价），零星委外手填加工费；新建期可勾选，**保存后锁死**（换标记只能删草稿/作废重开）。（见 ADR 2026-07-24 委外采购。）
- **委外订单**：勾选委外标记的采购订单；状态机、双币金额链、条目快照、关闭/作废规则与普通采购订单一致；条目下多出可选的委外配置——**成品 BOM 引用**（可空，限选条目物料自身的**启用中** BOM，仅作来源留痕——BOM 停用后新单不可再选、已有引用保留展示）、**发料清单**、**副产物清单**；配置可选不配不挡开单，但条目无发料清单则委外发料无行可挂、自然卡住。选 BOM 后按 理论耗用＝净用量×(1＋损耗率，空按 0)×条目数量 代入发料清单、按 单位产出量×条目数量 代入副产物清单，均为**快照复制**——代入后与 BOM 脱钩、可自由增删改；改条目数量不自动重算，BOM 后续变更不回溯（同系统「改默认不追溯」惯例）。审核挂来源需求行时倒写**委外**安排并占已安排（同普通采购条目倒写采购安排）。
- **发料清单**（行）：委外订单条目下「需发给协作方的材料」子表——材料＋单位＋数量＋行备注，随条目级联删除；是委外发料单的唯一取行来源（发料行必挂发料清单行）。
- **副产物清单**（行）：委外订单条目下「预期随成品一起回来的副产物」子表——材料＋单位＋数量＋行备注；是委外入库副产物入库行的带出来源。
- **已发料量**：发料清单行上按材料**默认单位**累计的已发出量；事实来源为已审核未作废的委外发料行，清单行列是受控投影——发料审核加、作废减；剩余可发＝清单数量−已发料量；**超发不硬拦**（无容差设置），超额仅展示。
- **委外发料单**（OutsourcedIssue，`pur_outsourced_issue`）：对协作方的**委外材料发出**单据——无金额、不过总账（仓间移动、所有权不变，同手工调拨不生凭证先例）。头＝公司＋对手（供应商/内部公司，须与所引委外订单一致）＋发料日期＋头调出仓/头外协仓（可空，仅新建行预填）＋备注＋单号（挂编号规则独立系列）；行＝必挂发料清单行（带出材料与单位快照）＋数量＋行调出仓（必填，本公司启用叶子仓，与外协仓不能同仓）＋行外协仓（必填，限绑定当前对手的外协仓）＋行备注；可跨多张委外订单，全部行订单的公司、对手须一致（无金额，无币种约束）。状态机 草稿→已审核→（已作废），仅草稿可改可删、无反审核、无关闭态；审核同一事务写「调出仓负＋外协仓正」库存分录并累加发料清单行已发料量；作废回滚，照常过负库存校验。菜单在采购管理「委外」组，列表双 tab（发料条目默认/发料单）。权限码 `purchase.outsourced_issue`。
- **委外入库单**（OutsourcedReceipt，`pur_outsourced_receipt`）：委外成品回库的**履约入库**单据——财务行为完整镜像采购入库（借贷科目槽草稿保存即必填、按公司默认过账科目整组代入、贷方强制「未开票应付」角色、本币金额为零跳过总账、双币金额链按订单条目快照折算）；头另含**默认入仓**/**默认外协仓**（均可空，仅成品行/副产物行/材料扣减行的新建与带出预填）。行必挂委外订单条目（可跨多张委外订单，但全部行订单的公司、对手、原币须一致，同采购入库口径），审核累加条目**已收数量**并复用**入库超收比例**容差，行冗余**已对账数量**进采购对账条目池（加工费照常对账→开票；有非零已对账数量的行其入库单不可作废）。审核同一事务同时：成品入本公司仓（正向库存分录）＋**材料扣减**（按发料清单快照×（本次成品入库量÷条目需求数量）比例带出、可手改，写外协仓负向分录、不过总账——材料物化进成品成本的金额账随库存估值一并推迟）＋**副产物入库**（按副产物清单同比例带出、可手改，写本公司仓正向数量分录、无金额，同生产入库第一期先例）；带出是入库条目保存时的一次性代入，改入库数量不自动重算；带出/手增的扣减行外协仓与副产物行入仓草稿可空、审核锁内复检必填。状态机 草稿→已审核→（已作废），仅草稿可改可删；作废回滚全部库存分录、总账分录与投影，照常过负库存校验。菜单在采购管理「委外」组，列表双 tab（入库条目默认/入库单）。权限码 `purchase.outsourced_receipt`。
- **委外退货单**（OutsourcedReturn，`pur_outsourced_return`）：委外成品退回协作方返修的**纯数量**单据——无金额、无过账日期、无表底科目、不过总账、**不进对账**（加工费只对最终验收合格的收货付一次：返修送回后照常委外入库计费进采购对账）。审核同一事务写负向库存分录（成品出本公司仓）、挂源行的行累加委外入库条目**已退数量**并回减委外订单条目**已收数量**；**不回补外协仓材料、不退副产物**（材料已消耗物化、金额账随库存估值推迟的同口径延伸）。行两类可混——**源单行**挂已审核未作废且剩余可退 > 0 的委外入库条目，**源行已对账数量 > 0 禁止退货**（须先撤回/作废相关采购对账单，保证同批成品加工费只对账一次）；**手工行**仅物料+数量+行仓（无金额字段）。可跨多张委外入库单，公司/对手须一致（无金额无币种约束）。状态机 草稿→已审核→（已作废）；作废回滚库存分录与已退/已收数量。菜单在采购管理「委外」组，列表双 tab（退货条目默认/退货单）。权限码 `purchase.outsourced_return`。
- **协作方**：外协仓上绑定的存放方引用（Party 多态，限供应商/内部公司），`is_outsourced=true` 时必填、一仓绑一方，`is_outsourced=false` 时必须为空；协作方为内部公司时不能是仓库所属公司自身；委外发料/委外入库选外协仓时按当前对手过滤。
- **收发货历史**（`scm_order_flow_item` 只读视图）：销售/采购订单抽屉的统一履约流水视角——UNION ALL 采购入库、委外发料、委外入库、销售发货四类单据行（单据类型/单号/日期/状态＋物料快照/单位/数量，按单据日期倒序），取代原先分单据的「发货历史/收货历史」tab；委外发料行经发料清单行桥接取订单，其客户料号恒空。纯读模型不落库、不设独立权限点（持任一来源单据 read 权限即可读，公司数据权限照常）；退货单据（销售/采购/委外退货）落地＝扩视图 UNION 臂＋扩 `FlowType` 枚举＋policies 来源码（见 ADR 2026-07-25 订单收发货历史、ADR 2026-08-09 退货模块）。
- **参保类型**（InsuranceType，`hr_employees.insurance_types`）：员工参加的原子险种多选，任意组合不设互斥；当前状态快照（变更靠审计日志追溯），纯档案字段不参与工资计算，列表可按「包含/不包含某险种」筛选。
- **原子险种**：参保类型的八个固定枚举值——社保工伤/社保失业/社保医疗/社保养老/社保生育/公积金/商保工伤/商保医疗；「五险一金」「三险」不是系统概念只是勾选组合，商保值不区分保司与保单。
- **行情品种**（MarketInstrument）：可被业务引用的一条**稳定参考价序列**主数据（如「沪铜」「长江电解铜」），全局共享不分公司；不随交易所换月而新建主数据；覆盖交易所序列、现货指数等。必填口径：币种、计量单位、默认价类、来源类型；可选合约代码等仅作补充，不作主数据拆分维度。菜单口语可叫「期货管理」，领域与文档以「行情」为准。
- **行情管理**（模块边界）：基础数据下的行情主数据、时序价与盯盘工作台——只观测、落库、被引用，不持仓、不交割、不记账；报价挂钩与未来库存估值均只读行情。录入通道含手工补录与自动/手动拉取，采集周期不作品种业务必填项；界面入口见**行情页**。
- **行情价点**（MarketPricePoint）：某行情品种在某一观测时刻的一条不可变价格事实——（品种, 观测时刻, 价格, 币种, 计量单位, 价类, 来源）；币种与计量单位继承自品种且不可与品种口径不一致；只追加不覆盖。有效价点在（品种, 观测时刻, 价类）上唯一；录错则作废后重录（或作废+新点一气呵成的更正），已作废不参与取价。录入通道含手工补录与拉取，同模型落库。
- **价类**（`price_kind`）：价点语义分类（如结算价、均价、最新价），枚举可扩；品种钉默认价类，价点可覆盖；同一品种多价类并存时，业务引用须指定价类（或显式用默认）。交易所序列自动拉取时：盘中写**最新价**，日终写**结算价**。
- **来源类型**（行情品种）：外部价源分类——交易所序列 / 现货指数 / 其他；只描述价从哪类市场来，不引入持仓或交易语义。
- **取价**：按（品种, 价类, 时点）从有效价点中解析出一个价格的只读规则；默认语义为「≤ 目标时点的最近一条有效价点」。具体业务（点价日、估值日）指定目标时点与价类（可回落到品种默认价类）。
- **行情菜单**：基础数据下「行情」分组，唯一入口为**行情页**（`/base/market`）；口语「期货管理」可作描述，不以「期货交易」建模。
- **行情页**：行情工作台——上图（勾选同币种+同计量单位的启用品种做多序列对比，附 KPI）+ 下表（价点明细 / 品种维护双 Tab）；图与表弱联动。图与 KPI 走价点时序只读查询；权限仍分 `base.market_instrument` 与 `base.market_price` 两套按能力拼装，不另建合并资源码。
- **行情品种停用**：品种退出主路径的方式——停用后不可再被新业务选为挂钩目标、不作为默认定价源，历史价点与既有引用保留；无任何价点时允许物理删除。编码创建后宜锁死，名称可改。
- **行情拉取**（MarketFetch）：按品种配置从外部价源写入行情价点的通道（`source=fetch`）。**启用拉取**（`fetch_enabled`）的品种才参与定时/手动刷新；映射字段挂品种主数据——**外部最新价代码**（如主连 `CU0`）、**外部品种组**（如上期所日数据 `cu`）。系统级节奏在 `sys_setting`（界面：基础数据→基础设置→行情拉取）：**定时总开关**、**最新价间隔**（仅 30/60/120 分钟）、**结算自动补拉**开关；交易时段按间隔拉最新价，工作日日盘收市后补持仓量最大合约的结算价。手动刷新：立即拉最新价，若已过结算窗口且配置允许则顺带补结算。运行后写**上次拉取摘要**供界面展示。现货指数（如长江铜）默不启用，继续手工。
- **销售对账单**（SalesReconciliation，`sal_reconciliation`）：公司就发货事实与客户/内部公司核对应收的勾稽单据，是「未开票应收 → 应收账款」迁移的业务枢纽——自身确认/结单不过往来重分类，常规单的重分类由发票审核关联触发（见对账类型与 ADR 2026-07-21）。头=公司+对手（客户/内部公司，Party 机制）+对账类型（必填、保存后锁死）+借贷科目槽（建单按「公司默认过账科目」的发货借方/发货贷方整组代入，可改；贷方强制「未开票应收」角色，借方校验口径随类型见对账类型）+单号+备注；条目=必挂发货条目或销售退货条目（双来源恰一）+对账数量（行单位，≤ 该条目剩余可对账量）+行备注，物料/价税口径沿用来源条目快照。行金额=对账数量×快照原币含税单价（2 位）→本币金额=×源订单汇率（2 位），**退货条目行金额取负**；单头不设汇率、合计=Σ 行（净额，**允许负合计**——纯退货月份可单独成单，关联发票价税合计相应为负）。条目池=同公司同对手、已审核未作废发货/销售退货、剩余可对账量>0 的条目，单内同币种；不做发货日期强约束（列表给筛选）。草稿不占量；消耗发生在生效时点（常规单确认时、赠送/样品单结单时逐行校验剩余可对账量并累加已对账数量，撤回/作废回滚）。编号挂编号规则（系统生成），两类共用一条系列；权限码 `sales.reconciliation`；菜单在销售管理「交易」组，列表仅对账单（不设条目视角；条目录入与核对在抽屉/确认弹窗内完成）。分次部分对账的 2 位舍入尾差不强行配平，残留由赠送/样品单核销通道兜底。
- **对账类型**（`reconciliation_type`）：销售对账单的分类——常规/赠送样品两类，手选必填、保存后锁死（换类型只能作废重开），共用编号规则与权限码，状态机与条目约束不同。**常规对账单**：状态机 草稿→客户已确认→已结单；草稿可改可删（客户确认前的多轮修改都在草稿内完成），确认锁死、未关联发票前可撤回回草稿；条目禁勾样品订单来源与零金额行；「已结单」由开票触发——开出方向发票在草稿上选关联对账单，审核时校验（对账单=客户已确认、公司/对手一致、发票价税合计=对账单合计，一对一），过账=发票正常三行（借应收账款/贷金额科目/贷税额科目）+冲回组（借单头借方科目=发货贷方口径/贷单头贷方科目=未开票应收，金额=价税合计），发票作废/红冲自动解除关联并把对账单退回客户已确认；已结单无独立作废入口，纠错走发票侧（红冲/作废→退回已确认→撤回→回草稿改）。**赠送/样品对账单**：状态机 草稿→已结单（审核即结单）；条目不限来源——样品订单来源、任意订单零金额行、正常金额行均可（典型场景：超发尾差核销，发 1020 客户只认 1000，余 20 走此单结清）；结单过账 借单头借方科目（费用/损失类，手选，本公司启用非汇总）/贷单头贷方科目（未开票应收角色），金额=勾选条目价税合计，为零跳过分录（同销售发货先例）；已结单可作废，作废回滚分录组与已对账数量。
- **客户确认**（confirmed）：常规对账单的中间生效态——客户线下认可账单后由内部人员手工翻入，是发票关联的前置闸门；数量消耗（已对账数量累加）在此时点发生，未关联发票前可撤回。
- **已对账数量**（`reconciled_qty`）：发货条目/入库条目（含委外入库条目）与销售/采购退货条目上按物料默认单位累计的已对账量；事实来源为生效中的对账单行（常规单自客户/供应商确认起、赠送/样品单自结单起），条目列是受控投影——确认/结单加、撤回/作废减；剩余可对账 = 发货/入库/退货 base − 已对账数量。退货条目与发货/入库条目**同池混勾**，退货行对账金额取负（对账单合计=净额，允许负合计，关联发票价税合计相应为负）。存在非零已对账数量的发货/入库/退货条目（含委外入库条目），其单据不可作废（须先撤回/作废相关对账单），同「有已审核发货订单不可作废」先例；委外入库条目反向亦成立——已对账 > 0 的条目禁止委外退货（见委外退货单）。
- **已退数量**（`returned_qty`）：发货条目/采购入库条目/委外入库条目上按物料默认单位累计的已退回量；事实来源为已审核未作废退货单的**源单行**，条目列是受控投影——退货审核加、作废减；剩余可退 = 发货/入库数量 − 已退数量；挂源行的退货审核硬校验不超剩余可退，手工行无锚点不受限。已退与**已对账数量**互不干涉（已确认对账的货仍可退，金额冲减走后续对账单同池净额）；委外入库条目例外——已对账 > 0 即禁止退货（纯数量单不对账，靠拦截保证加工费只付一次，见委外退货单）。
- **采购对账单**（PurchaseReconciliation，`pur_reconciliation`）：公司就入库事实与供应商/内部公司核对应付的勾稽单据，是「未开票应付 → 应付账款」迁移的业务枢纽——自身确认/结单不过往来重分类，常规单的重分类由开入发票审核关联触发（全镜像销售对账单，见 ADR 2026-07-21 采购对账单）。头=公司+对手（供应商/内部公司，Party 机制）+对账类型（必填、保存后锁死）+借贷科目槽（建单按「公司默认过账科目」的入库贷方/入库借方整组代入，可改；借方强制「未开票应付」角色，贷方=入库借方口径（常规）/收益类（赠送样品））+单号+备注；条目=必挂入库/退货条目（采购入库、委外入库或采购退货条目，三来源恰一；委外退货为纯数量单、不进池）+对账数量（行单位，≤ 该条目剩余可对账量）+行备注，物料/价税口径沿用来源条目快照。行金额=对账数量×快照原币含税单价（2 位）→本币金额=×源订单汇率（2 位），**退货条目行金额取负**；单头不设汇率、合计=Σ 行（净额，**允许负合计**，关联发票价税合计相应为负）。条目池=同公司同对手、已审核未作废入库/采购退货、剩余可对账量>0 的条目，单内同币种；常规单禁勾零金额行（采购订单无样品类型，无"样品来源"禁用），赠送/样品单不限来源（兼任超收尾差核销通道）。状态机不对称：常规单 草稿→供应商已确认→已结单（确认可撤回（未关联发票前），已结单无独立作废入口、由发票作废/红冲退回确认态）；赠送/样品单 草稿→已结单→（已作废），结单审核即过账 借未开票应付(带对手)/贷收益类科目、零金额跳过分录。草稿不占量；消耗发生在生效时点（常规单确认时、赠送/样品单结单时逐行校验剩余可对账量并累加已对账数量，撤回/作废回滚）。编号挂编号规则（系统生成），两类共用一条系列；权限码 `purchase.reconciliation`；菜单在采购管理「交易」组，列表双 tab（对账条目/对账单）。术语切割：业务域「对账」并称**销售对账单**与**采购对账单**（入库与收票、发货与开票之间的勾稽单据），与银行流水勾稽的**银行对账记录**相切割。
- **供应商确认**（confirmed）：常规采购对账单的中间生效态——供应商线下认可账单后由内部人员手工翻入，是开入发票关联的前置闸门；数量消耗（已对账数量累加）在此时点发生，未关联发票前可撤回。
- **费用角色**（报销类型）：差旅费 / 办公费 / 业务招待费 / 交通费 / 其他费用五个科目角色，枚举写死（同往来角色先例），新增类别=加枚举值；不进应收应付报表，其科目分录不要求带对手。报销类单据上「选报销类型」即选费用角色——金额/费用科目=本公司挂该角色的唯一启用非汇总科目，缺挂或多挂则报错改手选；角色只作带科目的选择器，单据上不存角色值、只存科目。
- **其他应付款**（`other_payable`）：往来角色，员工报销挂账专用——费用报销发票审核贷记（带员工对手）、报销单审核借记核销；纳入净应付（见 ADR 2026-07-21 费用报销）。
- **费用报销发票**：增值税发票第四类型——方向开入、对手限员工、不关联任何对账单；选报销类型自动带出金额科目与往来科目（税额科目手选）；审核即完成含税支出挂账（借费用/税额、贷其他应付款-员工），不生成下游单据；被报销单挂票行引用（含草稿报销单）后不可作废/红冲，须先移除行或作废报销单。
- **报销单**（ExpenseReport，`acc_expense_report`）：对员工付款的核销单据——费用报销发票审核完成挂账（第一步）后，给员工打款是第二步。头=公司+员工+报销日期+过账日期+付款科目（贷方，本公司启用非汇总本币科目）+单号（挂编号规则，系统生成）+备注；状态机 草稿→已审核→（已作废），仅草稿可改可删，无反审核、无红冲；审核过账=挂票行借各发票往来科目（带员工对手，金额=各票价税合计）+无票行借费用科目、贷付款科目（Σ 全部行）；作废=分录标记作废+解除全部发票引用（发票回到「已审核未报销」，可被新报销单重新引用或正常作废/红冲）。权限码 `acc.expense_report`，菜单财务组发票旁。
- **挂票行**：报销单行之一，引用本公司该员工「已审核未报销」的费用报销发票；一票一单全额核销（v1 不支持部分付款），行金额=发票价税合计。
- **无票行**：报销单行之一，手填摘要+金额+报销类型（带费用科目），税额恒 0——五金店现金等非税支出通道；无票支出无挂账时点，审核时挂账与付款一步两清（借费用、贷付款科目）。
- **卡片模式**：SynieDataGrid 在视口 < 1024px（统一移动断点 lg 以下）时的移动端呈现形态——同一 GridMeta 驱动的卡片流替代表格（默认按列序映射标题/副标题/摘要，各页 `ColumnOverride.mobileRole` 精调；桌面公司首列等筛选用列在卡片上常 hide），筛选走底部 Sheet、翻页走「加载更多」；定位读为主+轻操作（浏览/搜索/筛选/详情/审批类行内动作），建单/编辑/批量/导入导出/打印回桌面，树形列表常驻平铺+搜索。机制收敛在 grid 组件内，业务页不另写移动视图（见 ADR 2026-07-29 移动端卡片模式）。
- **源行批量挑选**：子条目表「从上游单据行一次勾多行」的统一交互形态（组件 `synie-source-picker`）——子表工具栏按钮开弹窗，勾选候选源行、弹窗内逐行填数量（必填、大于零，场景给上限时超量即时拦截），确认即批量生成子表草稿行；其余字段（税率/仓位/损耗率等）不进弹窗，靠默认值带出、例外行落子表后用行表单补。防重复一律**池剔除**（已在单上的源行不进候选池，加量去编辑已有行），不做合并也不许重复行；候选池口径（剩余量、有效期、占用等）由各场景自定。首批接入：销售订单「从报价批量选择」（2026-08）；需求单「从销售订单选择」等既有批量入口逐步收敛到该组件。
- **简道云**（JDY）：本系统上线前的旧业务系统（低代码平台），2026-08 已完成主数据（供应商/客户/分类/物料/图纸）单向迁移，此后本系统为主库、简道云为只读快照；其新增数据的增量同步方法与表单/字段坐标见 [docs/部署/简道云数据迁移](部署/简道云数据迁移.md)。导入所用原文冻在本机 `data/jdy-source/`（gitignore），附件正本在 OSS `synie-erp`，重洗/补库存/补凭证约定见 [docs/部署/简道云原始快照](部署/简道云原始快照.md)。
