# 待办

## 概述

待办模块是横切的**状态驱动提醒**设施：对账单进入客户/供应商已确认后，系统自动为有权开票的人产生「请开票 / 请收票」提醒，直到关联发票审核结单（或对账撤回确认）后消失。服务财务与内勤，解决确认态到开票之间的可见性真空，不替代单据状态机，也不引入流程引擎。设计定案见 [ADR：待办设施](../系统架构/adr/2026-07-25-todo-facility.md)。

边界：第一期仅覆盖销项开票与进项收票两个镜像场景；无手工待办、指派、截止时间、优先级、催办或站外通知。

## 核心概念

- **待办**：从源单据状态推导的物化提醒，随确认出现、随结单/撤回关闭、随发票作废红冲复活；用户侧只有已读与个人忽略。见 [术语表](../术语表.md)。
- **开票待办 / 收票待办**：分别由常规销售/采购对账单确认触发；可见范围为「可见该公司 + 持发票创建权限」，超管全见。
- **个人忽略**：仅影响本人列表；源单状态变化产生新待办时自动复位，不会永久漏掉。

## 功能清单

### 产生与关闭

- **产生**：常规销售对账单客户确认 → 开票待办；常规采购对账单供应商确认 → 收票待办。赠送/样品单无确认态、不产生待办。
- **关闭**：关联发票审核结单 → 该对账单活跃待办关闭；对账单撤回确认 → 活跃待办关闭（消失）。
- **复活**：发票作废/红冲把对账单退回确认态 → **新建**一条活跃待办，原已关闭记录留历史。
- 同一对账单同一时刻至多一条活跃待办。待办与单据动作同事务，状态永不失同步。

### 可见性（权限圈人）

- 不设独立权限码、菜单无权限门槛。
- 列表与已读/忽略操作按当前用户过滤：公司授权范围内，且持发票创建权限；超管全见。
- 未读徽标计数为只读语义，只需发票查看权限（同样限公司授权范围内）；超管全见。
- 「草稿关联中」徽标：存在草稿态关联发票时派生展示，不落库、不提前关闭待办。

### 已读 / 忽略 / 历史

- 点开待办或跳转源单即标记已读；未读数 = 活跃且未忽略且未读。
- 个人忽略只从本人活跃列表清掉；复活或新待办时忽略自动失效。
- 已关闭待办进历史 tab，含关闭时点与触发来源（撤回确认 / 发票审核结单）。

### 铃铛与菜单

- 顶栏铃铛：未读数徽标 + 下拉最近几条 + 「查看全部」。
- 独立菜单「工作台 → 待办」：活跃 / 历史双 tab；行显示类型、对账单号、公司、金额、产生时间、已读态、草稿关联中、忽略操作。
- 点击跳转到对应销售/采购对账列表；进页面与获焦时拉取刷新，定时轮询兜底。

## 业务流程

常规销项：发货 → 对账确认 → **开票待办出现** → 建票关联（草稿关联中徽标）→ 发票审核结单 → **待办关闭**。票错作废/红冲 → 对账退回确认 → **待办复活**。进项镜像。
