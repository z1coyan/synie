# 系统管理

## 概述

系统管理模块为整个 ERP 提供账号与安全底座:用户与登录认证、组织(部门)维护、角色-权限分配、公司与部门维度的数据权限、操作审计、单据自动编号、文件与存储接入管理;全新部署的首次初始化由初始化向导完成(建首个超级管理员、首个公司)。服务对象是系统管理员(配置与运维)和全体用户(登录与被授权)。全体登录用户可自助管理**个人 API 密钥**,供外部程序(含 AI)以本人身份调用接口。边界:公司、货币、单位等主数据的维护在基础数据模块;用户自助修改密码、登录设备管理、密钥级权限缩小、管理员代管他人密钥、应用内 AI 对话均未提供。

## 核心概念

- **用户**:登录系统的账号,用户名全局唯一且不区分大小写;密码只存哈希,明文从不落库。**邮箱**可选、非空时全局唯一(忽略大小写),是 Logto 首登与系统用户的匹配键。
- **个人 API 密钥**:用户为自己签发的可撤销程序访问凭证,供外部 AI/脚本以本人身份调用接口;明文只显示一次,权限跟随用户此刻的授权。
- **超级管理员**:用户级旗标,绕过一切功能权限与数据权限检查;仅初始化向导设置,常态界面无入口。
- **角色**:一组权限授权的集合,可停用;停用的角色立即不再为其下用户贡献权限。用户通过「分配角色」获得权限,一人可多角色,权限取并集。**内置角色**随初始化向导种子,可正常分配给用户;仅 **admin**(管理员,持全域授权旗标)受系统保护——不可删、不可停用、授权只读;其余预置角色初始化后与普通角色同权(可改/可删/可维护授权)。当前预置两个:**admin** 与 **sales**(销售业务员,销售链单据完整权限+附件上传/查看/删除(不配附件管理菜单)+主数据只读(含物料分类、公司与部门))。
- **部门**:挂在公司下的组织树,一个用户至多属于一个部门。部门本身是主数据(编码由系统按编号规则生成、公司内唯一、创建后不可改,初始化预置 `B(D)-` + 4 位补零序号;可停用、可多级),同时是「本部门及以下」数据范围的取值来源（「本部门不含下级」已否决）。
- **权限点**:按「域.资源:动作」组织的操作能力(如「销售订单-审核」),由代码派生、不入库,因此权限点与系统功能永不漂移。授权按具体权限码逐条落库,**不支持通配**;内置 admin 角色持有的是「全域授权」旗标(覆盖全部权限码,新上线的权限点自动包含),该旗标只随初始化种子设置、界面无入口。
- **数据范围**:每条授权除权限码外还带一个数据范围(全部 / 本部门及以下 / 仅本人),决定该角色能碰到哪些行;公司边界始终另行叠加(见公司授权),不另设「本公司」行范围。范围对八动作共用。可授范围按资源开放:声明了部门维度的资源开放「本部门及以下」,声明了属主维度的资源开放「仅本人」,两者皆无的资源(如全局配置)恒为「全部」、界面不出现范围控件。「本部门不含下级」已否决;存量 leftover 行仍可读可再保存。记录级共享本轮不做。
- **菜单权限**(菜单白名单):角色级的菜单可见性配置,决定该角色用户在导航里能看到哪些菜单入口;纯呈现层,与权限点正交——菜单隐藏不等于禁止操作(直接访问网址仍由权限点判定),权限点也不影响菜单显示。角色不配置即不限制(全部菜单可见)。
- **公司授权**:用户级数据权限,决定能看到哪些公司的业务数据;显式授权、默认不可见(fail-closed),授权挂用户不挂角色。
- **审计日志**:数据变更(创建/更新/删除及审核、作废等业务动作)的字段级留痕,只增不改不删。
- **编号规则**:绑定单据类型的自动取号规则,内容为有序段(固定文本/记录字段/序号)的组合;每种单据至多一条启用规则。单据编号一律由系统按启用规则生成、不接受手填、创建后不可改;未配置启用规则时保存直接报错,可先停用旧规则再启用新规则（同资源同时只允许一条启用）。
- **打印模板**:绑定资源类型的单据版式 Excel 模板(.xlsx+占位符),同资源可多份、一份默认;打印=填充转 PDF 交浏览器,导出=填充后的 xlsx 下载。
- **存储接入点**:文件字节的存放位置(本地目录或对象存储),全局有一个默认接入点,新上传统一落默认点。

## 功能清单

### 初始化向导

全新部署(库中无用户)首次打开应用即进入初始化向导;已初始化的环境访问 /setup 会被重定向离开。

- 三步:创建首个管理员(用户名+自设口令,直接成为超级管理员并自动登录)→ 创建首个公司(编号/名称/简称/本位币,并按所选科目表模板一键初始化科目;三套模板均为当前单据、报销自动带出和应收应付报表预置完整且唯一的 12 个科目角色;向导已预置约 20 种常用货币供选本币,预置时全部停用,选定本币后仅本币启用,其余须事后在货币管理页手动启用)→ 选择首选语言(仅占位,界面翻译后续版本提供)。
- **起步方式**:**空白项目**只建底座;**示例数据**路径预填演示管理员与公司,完成时为首个公司写入覆盖全业务链的示例数据——客商/物料/员工等主数据、销售与采购全链单据(报价→订单→发货/入库/退货→对账→发票)、委外全链单据(委外 BOM/外协仓→委外订单→发料→入库→加工费对账)、库存出入库/调拨/盘点、工序/工艺模板/BOM,以及银行账户与流水、手工凭证、报销单、工资单,便于立刻走通主流程(以客户编号 `C01` 幂等,已种子则跳过)。
- 是否完成初始化以完成旗标为准(系统设置单行表记录完成时刻);存量环境迁移时自动回填为已完成、永不进向导;落旗后向导入口与其接口永久关闭。首用户、货币预置/选本币、完成动作共用数据库事务级 Setup 锁;并发创建首用户只会成功一次,首用户同时获得超级管理员与全公司旗标并直接返回 JWT。
- 向导分步幂等、可断线续做:中途关闭后重开,从第一个未完成步骤继续;已建过管理员则改走「登录后继续」。完成动作先写语言和幂等基础种子,再(可选)写入全业务链示例数据,最后才写完成旗标;示例失败不落完成旗标。

### 用户与登录认证

用户管理页维护系统账号。

- 新建用户时系统生成随机初始密码,**明文只在创建响应中显示一次**,需当场转交用户;此后任何人都无法查看密码,只能重置。
- 用户名创建后不可改;可编辑姓名、邮箱与所属部门;用户可删除。邮箱非必填,填写后须唯一;修改或清空邮箱会同步到登录账号侧(供 Logto 同邮箱关联)。
- **所属部门**至多一个、可留空。候选限定在该用户已授权公司下未停用的部门;若所选部门的公司不在该用户的公司授权范围内,保存被拒并提示「先授权该公司或先移除部门」——回收公司授权时同理拦截,不留「配了却永远看不到数据」的组合。无部门的用户在「本部门及以下」范围下看不到任何行。
- 重置密码由管理员操作,同样生成随机新密码且明文只显示一次;重置复用「编辑用户」的权限,不设独立权限点。用户本人无自助改密入口。
- 登录使用用户名+密码;失败统一提示「用户名或密码错误」,不区分用户不存在与密码错误。
- 若部署配置了 Logto OIDC,登录页额外提供「使用 Logto 登录」;首登按 Logto 返回的邮箱匹配**系统用户的邮箱字段**(未填或未匹配则拒绝建号),会话 cookie 与本地密码登录共用。管理员须在用户管理中维护与 Logto 一致的邮箱后,该用户才能完成 Logto 首登绑定。OAuth 回调地址为 `{当前访问 origin}/api/v1/auth/oauth2/callback/logto`,须在 Logto 应用 Redirect URIs 中原样登记每个入口(本地 dev 常见 `http://localhost:3000/...` 与局域网/Tailscale 的 `http://<ip>:3000/...`)。多入口时服务端通过 `BETTER_AUTH_ALLOWED_HOSTS` 信任这些 Host,未登记的 Origin 会被 403。OAuth 失败(邮箱未匹配系统用户、提供方错误等)回登录页并以 Toast 提示原因,不展示认证中间页。
- 登录防暴破:同一用户名+IP 在 5 分钟窗口内失败 10 次即被锁定至窗口结束,期间无论密码对错都拒绝;成功登录即清零计数。
- 登录态有效期 7 天,过期需重新登录。

### 个人 API 密钥

全体已登录用户可从用户菜单进入「API 密钥」页,为自己签发可撤销的程序访问凭证,供外部 AI 或脚本以本人身份调用现有 REST。不进菜单白名单、不新开权限点,角色菜单限制不影响此入口。

- 新建须填名称(1–64 字,如「Grok」),过期时间可选(默认不过期);每人最多同时保存 10 个。
- **明文只在创建响应中显示一次**,关闭后无法再查看,与用户初始密码先例相同;列表只展示名称、密钥提示前缀、创建/最后使用/过期时间。
- 调用方在请求头带 `Authorization: Bearer <密钥>`。密钥认证为该用户,功能权限、公司授权与行级范围全部跟随用户**此刻**的授权(角色变更即时生效,不把权限快照进密钥)。
- 列表/创建/撤销只接受浏览器会话或登录 JWT;**个人密钥本身不能管理密钥**,被盗后无法再签发新钥。
- 撤销立即失效(硬删除,历史靠审计)。改密、退出登录不吊销密钥——要停外部访问须本人撤销。删除用户时密钥一并作废。
- 创建与撤销留审计,明文与哈希永不入审计。无 scopes、无管理员查看/吊销他人密钥、无 MCP 专用入口(后续阶段)。

### 界面外观

全站壳层与业务页支持**外观模式**三选一:**白天**(强制浅色)、**黑夜**(强制深色)、**系统**(跟随操作系统色阶,系统变更时即时跟随)。默认未选过时为系统。

- 偏好仅保存在本机浏览器,不落用户表、不跨设备同步;同源多标签页切换后即时同步。
- 主入口:登录后用户菜单内的三选一控件;登录页与初始化向导右上角提供同款弱化入口。
- 启动幕布、左侧模块图标栏、登录/向导左栏品牌区等**品牌仪式面**保持玄蓝深色,不跟随外观;内容区、二级菜单、顶栏、表单与业务页跟随色阶。
- 列表打印走独立浅色打印窗,不受外观模式影响。

### 部门管理

部门管理页按公司维护组织树:页面顶部选择公司,下方是该公司的部门树(可逐级展开)。

- 部门有编码、名称、上级部门与启用状态;编码由系统按编号规则生成（公司内唯一、创建后不可改）。上级留空即公司下的一级部门,层级不限。
- 上级部门候选限定在**同一公司且未停用**的部门;不能选自身、也不能选自身的下级(防止把树接成环)。
- 移动部门(改上级)连同其整棵子树一起搬迁;受影响用户的「本部门及以下」范围在授权缓存刷新后(最长 30 秒)生效。
- 启停通过列表行操作切换(不在编辑表单里)。**停用只影响新挂接**:停用后不能再把用户挂到该部门,已挂在该部门的用户保持不变(便于先停用、再逐步调整人员);停用的部门也不能再作为新建部门的上级。
- 删除有两道守卫:存在下级部门、或仍有用户挂在该部门,都不允许删除,须先调整下级与人员。
- 只能看到已授权公司的部门;新增/编辑的目标公司同样必须在授权范围内(否则按「不存在」处理,不泄露其他公司的存在性)。
- 部门变更留审计(创建/编辑/删除均记录字段级明细)。

### 角色与权限配置

角色权限页维护角色及其授权,行内「权限与菜单」打开统一配置抽屉。抽屉内分「菜单可见性」「功能权限」两个页签;两区语义独立(菜单管看不看得到入口、权限点管做不做得了事),合并的只是容器,存储与门控不变。有未保存改动的页签带圆点标记。

- 角色有编码(唯一)、名称与启用状态;编码创建后不可改,启停通过列表行操作切换(不在编辑表单里)。停用角色即收回其全部权限贡献,无需逐用户调整。系统保护角色(admin)行只读:不可启停、不可删除,抽屉两区仅可查看;其余预置角色(如 sales)照常可启停、编辑与删除。
- **菜单可见性区**:按「模块 → 组 → 菜单项」三级展示真实菜单,勾选叶子菜单项即限定该角色只见这些入口;组与模块的复选框只是批量勾选快捷(半选态由子项推导),不落库。状态徽标明示「未配置(全部可见)/已限制 N 项」,一键清空即恢复全部可见。**空集合 = 未启用限制**——不勾任何项等于不限制,不存在「限制成什么都看不见」的状态。每个菜单项下方标注其**关联权限资源**(只读文本,如员工薪资 → 工资单 / 工资发放 / 员工借款;无专属资源的标「无专属权限」),点击资源名跳转到功能权限区对应资源行(自动切域、定位、高亮)——哪个菜单该配什么权限一眼可见。
- **功能权限区**:左侧为域导航(带已授权进度徽标),右侧为当前域的权限矩阵:每个资源一行、封闭八动作(查看/新增/编辑/审核/删除/作废/导出/打印)平铺为列,资源不具备的动作不可勾。行头、列头、域导航项均支持三态全选;顶部搜索可跨域过滤资源,命中结果按域分组平铺、可直接勾选。**数据范围**:每个已勾选的权限码旁带一个范围下拉(全部/本部门及以下/仅本人),可选项按该资源支持的维度开放(目录下发),无部门/属主声明的资源不出现范围控件(恒「全部」);新勾选的码默认「全部」,行头/列头/域全选只补勾未勾码,不改动已设范围。存量 leftover「本部门不含下级」回读时仍显示,再保存不钳成全部。矩阵只反映逐码授权行:内置 admin 的权限来自全域授权旗标,矩阵内因此显示为未勾(该角色本就只读,旗标不经界面维护)。矩阵的资源清单与中文名随权限目录由后端代码派生并下发。
- **保存**:底部单一保存按钮一次提交两区改动(菜单与权限各自幂等同步,顺序执行);一区失败时抽屉不关闭、提示点名失败区,成功区已生效,失败区保留编辑态可重试;关闭抽屉时任一区有未保存改动弹确认。权限保存为事务性同步:前端提交目标授权集合(权限码 + 数据范围),后端在事务内对比增删与范围变化,只同步当前权限目录内的具体码,目录外的陈旧码原样保留;授出目录不支持的范围会被后端拒绝并逐个点名。授权只逐码落库(全选亦展开为具体码)——新上线的权限点默认不授予任何角色(fail-closed),唯一例外是持全域授权旗标的内置 admin。
- **入口门控**:任一查看权限命中即见「权限与菜单」入口;无「角色权限-查看」权限的人功能权限区显示「无查看权限」占位,无「角色菜单-查看」权限的人菜单可见性区同样占位。编辑各自独立:功能权限需同时具备角色权限的新增与删除两种权限,菜单需「角色菜单-编辑」——「配功能权限」与「配菜单」可分人管理。
- 多角色叠加取并集:用户可见菜单是其所有启用角色白名单的并集,加角色只会加菜单;只有所有角色都未配置菜单时才全可见。整组勾光时该组与所属模块整个消失(不留空壳);模块的默认跳转页自动指向可见的第一个菜单项。菜单隐藏不拦网址直达,能做什么仍由权限点决定——菜单管入口整洁,权限点管操作边界。
- 菜单白名单逐角色独立存储,变更留审计;系统保护角色(admin)的菜单只读且恒不限制;其余预置角色(如 sales)的菜单可维护——sales 随初始化种子销售链菜单(老环境不补种子,维持全可见)。菜单项删除或改名后,白名单里的失效项不自动删除,面板提示「已失效 N 项」并可一键清理;新上线的菜单项对已限制的角色默认不可见,需管理员补勾开放。超级管理员的菜单不受白名单限制。
- 用户的角色分配与公司授权在用户管理中维护,权限上跟随用户管理(查看跟随「查看用户」,增删跟随「编辑/新建用户」),不设独立权限点。
- 数据权限(公司维度):用户只能看到被授权公司的业务数据,未授权即不可见;读取时无权数据静默不出现在结果中,写入越权则返回校验错误。跨公司管理人员有「全部公司」旗标覆盖(与超级管理员旗标一样无界面入口,仅内部设置)。共享主数据(物料、计量单位等)不分公司,全员可见。

### 操作日志

操作日志页提供全局审计查询;各记录详情页另有按该记录过滤的编辑记录。

- 留痕范围:数据的创建、更新、删除,以及审核、作废、重置密码等业务写动作;登录与读取不留痕。
- 每条日志记录:操作时间、资源、记录名称(记录被删后仍可显示)、操作类型与动作、操作人(冗余存名,人员删除后仍可显示)、字段级变更明细(旧值→新值)。
- 变更明细规则:创建记全部写入值;更新只记实际变化的字段,无实际变更不落日志;删除记删除前的完整快照,作为追溯与手工恢复依据。敏感字段(如密码哈希)一律不落值,标记为已过滤。
- 日志与业务动作同一事务:业务操作失败不会留下脏日志。
- 日志只增不改不删;需「审计日志-查看」权限方可查询。公司数据的日志按授权公司过滤(未授权不可见),全局数据的日志不受公司限制。
- 当前各业务模块的主要单据与主数据(凭证、发票、银行、工资、考勤、客户/供应商、用户角色等)均已接入审计。

### 单据编号规则

编号规则页维护自动取号规则,规则以「绑定单据类型 + 段组装」方式定义,无需书写模板语法。

- 规则内容是有序段列表,段有三种:固定文本、记录字段(本单据字段或其直接关联的字段,如公司编码)、序号。序号段必须恰好一个;位数 0~12,其中 0 表示不补零,1~12 为补零宽度。
- 字段段取值为空时省略该段(不报错),便于物料等「可选前缀」场景用一条规则覆盖多种形态。
- 日期类字段作段时必须选择格式(年/月/日的组合,如「年月」渲染为 202607);非日期字段不能设格式。
- 段可拖拽调整顺序;改序与改规则内容一样只影响此后取号。
- 每种单据至多一条启用规则,启用即生效;规则的绑定单据创建后不可改。
- 「按公司计数」开关(默认开):各公司各自独立计数;关闭则全局共用一组序号。
- 没有独立的重置周期配置:序号按「渲染后的段文本」计数,段里引用的日期一变(如跨月),序号自然从头计。
- 取号发生在单据保存时：编号一律由系统按启用规则生成，表单不可手填、接口传值报错（"编号由系统生成,不接受手填"），编号创建后不可改。取号并发安全，计数器自增随业务事务回滚释放、不因保存失败断号；已占用号码不回收（删除单据会留洞）。
- 计数器:规则下可查看各计数范围的当前序号,并可手工调整当前值(调整本身留审计);删除规则连同其计数器一起删除。
- 页面字段候选只展示后端编号目录允许的直接字段和一层关联字段；规则、字段目录和嵌套计数器均使用同一套列表/抽屉交互。
- 当前已接入自动编号的单据与主数据:会计凭证、增值税发票、承兑交易、费用报销、物料、员工、仓库、部门、销售订单/报价/发货/退货/对账、采购订单/报价/入库/退货/对账、委外发料/入库/退货、手工出入库/调拨/盘点、履约需求、生产工单、生产入库、BOM、工序、工艺模板等。
- 初始化预置规则:业务单据统一为「主模块字母(子模块字母)-业务日期YYYYMMDD-4 位序号」(如销售订单 `S(O)-20260722-0001`),按公司计数;物料为「分类编号+可选客户编号-不补零序号」(如 `F(P)77-1`);员工为 `H(E)-`+4 位序号;仓库 `B(W)-`、部门 `B(D)-` +4 位序号（按公司计数，随迁移预置——首张公司创建早于向导完成即需取号，其余规则随初始化向导完成时预置）。已有规则不覆盖。

### 打印模板

打印模板页维护单据版式模板,供单据的模板打印与模板导出使用;可挂模板的资源覆盖全部业务资源(字段清单按资源结构自动派生,新资源接入无需逐字段开发),打印/导出入口随各资源标准动作逐资源启用。

- 一份模板=名称+资源类型(如销售订单)+上传的 .xlsx 模板文件+备注;模板全局共享不分公司,同一资源可传多份,其中一份可标为默认(打印时预选、可临时换另一份)。
- 模板管理页、业务模板列表和字段清单由统一 REST 接口提供;字段目录自资源目录派生,覆盖已登记的全部业务资源。拥有该资源打印/导出/批量打印任一权限或「打印模板-查看」权限,即可读取该资源模板和字段清单;增删改仍按打印模板管理权限。
- 模板文件以 `sys_print_template`/`template` 唯一挂接授权下载;替换文件会同步换挂接,删除模板只删除挂接并保留文件本体,模板 CRUD 与默认切换均留字段级审计。
- 模板文件里用占位符取值,一律「关系.字段」路径式:单元格写 `${字段名}` 取单据头字段(如 `${order_no}`、`${gross_total}`),写 `${关联.字段}` 取关联字段一层(如 `${company.name}`、`${warehouse.code}`),带交易对手的单据用 `${party.name}` 取对手名称;可与普通文字混排;某一行写 `${关系.字段}` 且关系为子表(如订单 `${items.字段}`、BOM `${components.字段}`)即成为循环区模板行,输出时按子表行数逐行复制展开,`${关系._seq}` 给行序号,同一模板可有多个循环区顺序各占一段;枚举字段印出中文标签(如「已审核」),空值印空白;合计等用 Excel 公式自行书写。日期/数字的显示格式由单元格自身的 Excel 格式控制。可用字段以模板管理页提供的《字段清单》为准(主键、外键、时间戳等技术列不在其列)。
- 上传即校验:只接受 .xlsx;系统提取模板中全部占位符对照该资源字段清单,有未知名称、二层下钻或嵌套循环(子表的子表,如报价条目内套价格档)即拒绝保存并逐个点名,错模板不会活到打印时才暴露。旧版拍平键(如 `${company_name}`)不再合法,旧模板按校验提示改写为路径键后重新上传即可。
- 纸张大小、方向、页边距、打印区域等版式设置完全由 Excel 模板的页面设置决定,系统不另设字段、输出时严格按模板页面设置渲染、不自行添加页边距;上传时检测到未做页面设置会给出提示但不拦截。
- 模板可删除(打印是瞬时动作,删模板不影响任何历史单据);更新版式=重新上传替换文件,已输出过的文件不追溯。模板内容暂不支持图片(图纸、公司 Logo 等)。
- 单据侧入口:单据行内「打印」「导出 Excel」与列表勾选后的「批量打印」「批量导出 Excel」,均先弹模板选择(预选默认模板)。打印产出 PDF 由浏览器打开(预览/打印/另存皆用浏览器能力);导出产出填充后的 xlsx 直接下载。批量打印把多份单据版式合进一个 PDF 顺序输出,批量导出为一个 xlsx 内每张单据一个 sheet(以单号命名);单次批量上限 100 条。
- 无可用模板时,单据打印/导出 Excel 入口提示先到本页上传模板;列表工具栏的 CSV 导出是另一回事(导出列表列数据),不受影响。PDF 转换服务异常时打印报错,导出 Excel 不受影响。
- 打印/导出执行面由后端统一契约端点提供(模板+单据→PDF/xlsx 文件流);单据装配逐资源接入,当前已支持销售订单、生产工单与应收应付报表,未接入资源的打印/导出会给出明确提示。

### 文件管理

文件管理页查看系统内全部已上传文件;文件上传入口在业务单据的附件面板等各处,本页不提供上传。

- 文件内容不可变:只增只删,不存在编辑;单文件上限 50MB;列表展示文件名、存储接入、大小、类型、上传人、上传时间。
- 上传先写默认存储,再在同一数据库事务落文件元数据、可选业务挂接与审计;事务失败会补偿删除已写对象,不留下半成品。删除则先提交元数据与审计,再限时尽力清理对象;对象清理失败只告警并留待运维扫描,不把已提交的业务删除回滚成失败。
- 挂接宿主采用显式白名单;未知宿主类型一律拒绝挂接且不授予下载,不能靠拼表名绕过授权。公司型宿主在挂接上固化公司归属(全局型宿主不固化)。
- 可达性只有一条规则,附件列表、挂接、下载、删除共用:文件挂了业务宿主就随宿主——看得见宿主行(具备该宿主的查看权且在其公司范围内)才看得见文件,跨公司宿主视同不存在;没有任何挂接的裸文件按文件自身的数据范围判定(「附件-查看」授「仅本人」即只有上传人可碰,超级管理员不受限)。
- 报错口径:权限码不足报「无权限」;行级不可达(公司/宿主/非本人)一律报「不存在」,不泄露存在性。
- 删除有挂接保护:仍被业务单据引用的文件不可删,需先在业务单据中移除附件。
- 查看抽屉中可看到文件的挂接记录(挂在哪些业务记录、哪个槽位、挂接时间)。

### 存储接入

存储接入页管理文件字节的存放位置,支持本地目录(local)、S3 兼容对象存储(s3)与阿里云 OSS(oss)三种类型。

- 接入名全局唯一,且创建后不可改(已入库文件按接入名引用);存储类型创建后同样不可改。
- 按类型校验必填配置:本地存储必填根目录;S3/OSS 必填服务地址、Bucket 与访问密钥对。
- 全局默认接入点唯一,通过「设为默认」动作串行切换;并发切换后仍恰好一个默认点。新上传的文件统一落默认接入点,已存文件仍在原接入点、不受影响。
- 删除保护:内置接入点(向导完成时种子的本地存储)不可删;当前默认接入点不可删(需先切换默认);仍有文件存放的接入点不可删。
- 访问密钥只写不回读:任何界面与接口都不返回密钥值,列表与详情均不展示;创建对象存储时必填,编辑时省略或留空表示保留原值。

## 业务流程

- **组织搭建**:在部门管理页选公司 → 自上而下建部门树(先建一级,再逐级挂子部门)→ 用户管理里把人挂到部门 → 需要按部门看数据时,在角色「权限与菜单」抽屉的功能权限区为相应权限码选「本部门及以下」或「仅本人」数据范围。
- **新部署初始化**:迁移(顺带种子 CNY、内置 admin 角色与单行配置)→ 打开应用进入初始化向导(选空白或示例起步 → 建超管 → 建公司 → 选语言)→ 完成时幂等种子内置存储接入、编号规则、物料两级分类与机加工常用计量单位(示例路径另写客商/物料/报价)并落完成旗标,进入日常运行。空库无需再跑 seeds;开发复位到未 setup 用 `bun run db:reset`(仅本地/dev DSN)。
- **新用户开通**:管理员新建用户(可选填邮箱;获得一次性初始密码)→ 在用户抽屉中分配角色、授权公司、按需选所属部门(候选限已授权公司下未停用的部门)→ 用户凭用户名+初始密码登录;若启用 Logto,须邮箱与 Logto 账号一致后才能用 Logto 首登。未授权公司的用户登录后看不到任何公司业务数据。
- **权限调整**:角色权限矩阵保存后无需重新登录,该角色下所有用户在授权缓存刷新后(最长 30 秒)生效。
- **单据取号**:管理员建规则(选单据类型、组装段、启用)→ 用户开单时编号留空 → 保存时按规则自动取号并累计计数 → 需要时管理员在计数器中校正当前序号。
- **文件流转**:业务单据上传附件 → 文件落全局默认存储接入点并建立挂接 → 有权限者从业务侧下载/预览 → 业务侧移除挂接后,文件管理页方可删除文件。切换默认存储接入点只影响此后的新上传,存量文件仍从原接入点读取。
