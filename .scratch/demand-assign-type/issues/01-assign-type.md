# 01 — 单头指派类型与下发车间联动（含 dispatch 改派）

**What to build:** 计划员建履约需求单时单头必选**指派类型**（采购/生产/库存/关闭四值，委外归采购侧）：选「生产」时下发车间必填，选其余类型时下发车间必须为空（前端禁用清空）；草稿保存即必填、草稿内可改。审核后单头锁定，调整走「下发/改派」动作——可同时改指派类型与下发车间，过同一联动校验，权限码不变、留审计。非法组合（类型=生产但无车间、类型≠生产却带车间）在 API 层被明确拒绝，数据库层有 CHECK 兜底。指派类型不占量、不约束行级安排、类型=关闭不联动状态机。

**Blocked by:** None — can start immediately

**Status:** ready-for-human

- [x] 需求单头新增指派类型列（四值枚举，NOT NULL；迁移回填：已下发→生产、未下发→采购）
- [x] 数据库 CHECK：四值枚举 + 「类型=生产 ⟺ 下发车间非空」联动兜底
- [x] service 在创建/更新路径统一校验联动不变量；非法组合返回明确校验错误
- [x] dispatch 动作扩为「下发/改派」：指派类型与下发车间皆可空的合并语义，过同一联动校验；权限码不变；空负载无操作
- [x] meta 声明指派类型枚举字段（required）并派生权限/Grid/打印目录；dispatch 动作标签更新
- [x] 前端单头：指派类型选择器（必填），类型≠生产时下发车间禁用并清空，改派弹窗重写为「类型+车间」联动
- [x] 服务层 PG 集成测试覆盖：四值合法/非法、生产无车间拒、非生产带车间拒、草稿内改类型、审核后 dispatch 改派；meta 纯单测覆盖枚举与动作声明
