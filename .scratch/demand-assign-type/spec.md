## Problem Statement

履约需求单从「生产待办」演进为公司内部物料需求路由后，单头只有一个可空的「下发车间」，表达力停在「下给哪个车间」——计划员无法在单上声明这张需求单究竟交给谁消化（采购 / 车间 / 仓库，还是整单放弃），下发车间可空让「类型=生产但没下车间」这种半截状态合法存在。同时录入侧有几处长期不顺手：需求行的来源销售条目/来源生产工单在编辑态可以被改，给销售占用口径留了绕道；需求行快照不带图纸，车间/采购看行要回物料主数据翻图；需求行的需求日可空且没有批量维护手段，逐行手填重复劳动。

## Solution

单头引入必填的**指派类型**（采购 / 生产 / 库存 / 关闭四值，委外归采购侧）作为「这张单由谁消化」的路由声明：类型=生产时下发车间必填、其余类型下发车间必须为空；草稿保存即必填、草稿内可改，审核后随下发车间一并走 dispatch「下发/改派」动作。指派类型是纯意图层——不占量、不约束行级安排（行仍可混用五类安排）、类型=关闭不联动状态机；不做行级指派，混去向拆单。录入收口：来源销售条目与来源生产工单创建时定型、编辑只读，手工行不可事后补挂来源（换来源=删行重勾）；需求行快照复制物料图纸挂接、仅行内展示（工单图纸仍取物料主数据）；单头新增可空**需求日**作为新增行的默认值并提供显式「批量带入」刷到全部既有行（改头不追溯），行需求日改为草稿保存即必填。系统未上线无存量，直接重构。

## User Stories

1. As a 计划员, I want 建需求单时必选指派类型（采购/生产/库存/关闭）, so that 这张单由谁消化在创建时就声明清楚
2. As a 计划员, I want 类型=生产时下发车间必填, so that 不会出现「下给生产但没说哪个车间」的半截单
3. As a 计划员, I want 类型=采购/库存/关闭时下发车间必须为空, so that 单头路由语义不产生歧义组合
4. As a 计划员, I want 草稿内可自由改指派类型（车间跟随清空/要求）, so that 确认前的多轮修改都在草稿内完成
5. As a 计划员, I want 审核后通过「下发/改派」动作同时改指派类型与下发车间, so that 路由调整仍受独立权限码门控、留审计
6. As a 计划员, I want 类型=关闭只是路由标记、不强制行都走关闭安排, so that 意图与事实分层、不被状态机联动绑架
7. As a 计划员, I want 委外需求直接选类型=采购, so that 委外订单归采购侧执行的既有分层不被打破
8. As a 车间主任, I want 车间仍只按「下发到本部门」看到需求单, so that 指派类型落地不破坏既有部门数据范围
9. As a 计划员, I want 需求行的来源销售条目创建后不可改, so that 销售占用口径没有事后改挂的绕道
10. As a 计划员, I want 需求行的来源生产工单创建后不可改, so that 派生链路的可追溯性不被破坏
11. As a 计划员, I want 手工增的行不能事后补挂来源, so that 占用校验的触发条件不会被绕过
12. As a 计划员, I want 想换来源时删行重勾, so that 占用释放与建立的时序走正常链路
13. As a 车间主任, I want 需求行上直接看到图纸, so that 不用回物料主数据翻图
14. As a 计划员, I want 图纸随行快照冻结（挂接复制）, so that 行内展示口径与保存时点一致
15. As a 计划员, I want 删行/删单时行的图纸挂接一并清理, so that 不留孤儿挂接
16. As a 车间主任, I want 开工单时图纸仍取物料主数据当时的版本, so that 工单图纸口径维持现状（刻意取舍）
17. As a 计划员, I want 单头可填需求日、新增行自动带入, so that 同一天的行不用逐行手填
18. As a 计划员, I want 「批量带入」把单头需求日刷到全部既有行, so that 整单改交期一次到位
19. As a 计划员, I want 改单头需求日不动既有行（除非我点批量带入）, so that 不发生隐式级联
20. As a 计划员, I want 行需求日必填、保存即拦, so that 不会出现没有交期的需求行
21. As a 车间主任, I want 物料需求派生出的需求单自动带对指派类型（车间向=生产、采购向=采购）, so that 派生链路不破新校验
22. As a 任何用户, I want 非法组合（类型=生产但无车间等）在 API 层被明确拒绝, so that 绕过前端直调也守不住坏数据

## Implementation Decisions

- **单头指派类型（增）**：需求单头新增必填枚举列，四值 采购/生产/库存/关闭；与下发车间的联动不变量在 service 层校验，并以数据库 CHECK 兜底（四值枚举 + 「类型=生产 ⟺ 下发车间非空」）；迁移对既有开发库回填（已下发→生产、未下发→采购）。
- **dispatch 动作语义扩（改）**：原「下发车间」动作扩为「下发/改派」——负载改为指派类型与下发车间皆可空的合并语义，过同一联动校验；权限码不变；空负载等于无操作。
- **单头需求日（增）**：需求单头新增可空日期列；「批量带入」不新增端点——前端把头值刷进草稿行集合，随聚合草稿整体保存生效；改头本身不追溯（「改默认不追溯」惯例）。
- **行需求日必填（改）**：需求行需求日列迁移回填（空值取单头需求日、再退业务日期）后设 NOT NULL；service 在创建/更新保存时即拦（同物料/数量的保存时校验，非审核才拦）；派生行在工单无需求日时以派生日兜底。
- **来源只读（改）**：来源销售条目 meta 标只读（创建路径照常可写），更新路径 service 拒绝变更（同值重放放行，兼容整单草稿回传）；来源生产工单原本已只读，对齐即可；手工行不可补挂。
- **行图纸快照（增）**：需求行资源声明附件宿主（宿主白名单自 meta 派生），行创建/改物料/派生写入时复用既有「图纸挂接复制」助手（挂接复制、非字节复制）；删行、删单、工单作废级联删派生草稿三处清理行挂接；仅行内展示，工单图纸仍取物料主数据（刻意保持冻结链断开，见 ADR）。
- **派生链路回填（改）**：工单「生成物料需求」派生时按去向回填指派类型（车间向=生产、采购向=采购）。
- **不做行级指派**：路由粒度=单据，与审核/作废/编号生命周期粒度一致；混去向拆单（ADR 记录了被否决的行级路由方案及其代价）。

## Testing Decisions

- 好测试的标准：只测外部可观察行为（API 负载→响应/拒绝、DB 不变量、meta 派生契约），不测内部实现细节。
- 测试模块与接缝：服务层 PG 集成测试（manufacturing.integration 风格，含指派类型联动、dispatch 改派、需求日必填、来源拒改、图纸复制/重刷/删行删单清理）；meta 纯单测（枚举声明、必填/只读标记、附件宿主声明）；派生链路集成测试补指派类型回填断言；既有 dispatch/车间权限/e2e 夹具适配新必填字段。
- web 抽屉联动（类型↔车间禁用、批量带入按钮）不新增测试接缝，行为由 API 集成覆盖。

## Out of Scope

- 履约需求单的模块归置（是否迁出生产管理「计划」组、是否合并采购/库存/生产为供应链管理）——已明确挂起，菜单不动。
- 行级指派（每行各自指派类型+目标对象）及配套的行级数据范围裁剪——ADR 已否决。
- 工单图纸改取需求行快照——刻意维持取物料主数据。
- 类型=关闭与单据状态机/行安排的任何联动。
- 销售订单条目图纸挂接读侧不可达的疑似存量 bug（本次发现，另开工单处理）。

## Further Notes

- 系统未上线无生产存量，迁移回填规则只为开发库平滑过迁移，不构成业务口径。
- 需求超安排比例、已安排/已完成数量等投影口径不受本特性影响——指派类型不占量。
