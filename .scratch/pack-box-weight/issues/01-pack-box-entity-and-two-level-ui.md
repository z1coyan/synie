# 01 — 装箱箱实体落地与装箱 tab 箱/行两级重构

**What to build:** 发货单抽屉「装箱清单」tab 从平铺行改为箱/行两级：工具栏「添加箱子」建箱（箱号系统按单内自增整数生成、不可手改），箱内「添加物料」增装箱行，同箱多行按箱合并显示；删箱级联删除其装箱行。装箱行由行上自由文本 `box_no` 改为必挂装箱箱实体。既有行为全部回归不变：审核的「全有或全无」数量校验（按物料 Σ base 比对）、「从装箱清单获取」FIFO 分摊、物料快照五字段冻结、随单级联删除、审核后随单锁死、tab 行数徽标、权限随 `sales.delivery` 不新增权限码。系统未上线，直接 reset 重建，不做存量迁移。口径见 `CONTEXT.md`（装箱箱、装箱清单（行））与 ADR 2026-07-29。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 可在发货单草稿添加箱子，箱号单内自增（1、2、3…）生成，展示且不可编辑
- [ ] 可在箱内添加物料行，同箱多行合并显示箱级列；一物料可分挂多箱
- [ ] 删除箱时级联删除其装箱行，箱内有行时给出确认交互
- [ ] 装箱行不再出现手填箱号；物料候选口径（可发货订单条目池去重）、单位限默认/转换单位、`base_qty` 折算、快照冻结均保持
- [ ] 审核「全有或全无」数量校验各拒绝分支（漏装/不等/含发货外物料）行为不变
- [ ] 「从装箱清单获取」发货条目 FIFO 分摊行为不变
- [ ] 随单级联删除、审核后箱与行均锁死；不进收发货历史/列表 tab/CSV 导出
- [ ] 域服务层 Postgres 集成测试覆盖上述行为（trading/fulfillment 模块 *.postgres.test.ts 先例）
