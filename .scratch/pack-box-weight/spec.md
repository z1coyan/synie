# 装箱箱实体与重量口径（pack-box-weight）规格

Status: ready-for-agent

经 `/grill-with-docs` 逐问定案（2026-07-29）。术语唯一定义在根 `CONTEXT.md`（**装箱箱**、**装箱清单（行）**、**行净重**、**行净重推导**、**箱净重 / 箱毛重**，已随定案写入）；取舍记录见 [ADR 2026-07-29 装箱箱实体与重量口径](../../docs/adr/2026-07-29-pack-box-and-weight.md)。本规格改写既有 `.scratch/delivery-pack-list`（装箱清单 v1）的箱号口径——箱由行上自由文本升格为实体；系统未上线，直接 reset 重建，不做存量迁移。

## Problem Statement

- 销售发货绝大多数场景需要随货装箱单，而装箱单上**净重/毛重是与数量并列的刚需**（客户收货核对、货代订舱、报关都要）；当前装箱清单只有箱号＋物料＋数量，重量只能线下补，箱单在系统内凑不齐。
- 重量若全靠手填，同一产品每票发货重复劳动且易错；但若把单次过磅实测回写成物料换算系数，又会污染主数据（实测含包装、批次差、秤误差）。
- 现装箱清单的箱号是行上自由文本，UI 平铺行内手填同箱号来分组，「一箱多物料」的交互笨拙，且箱级信息（毛重）没有落点。

## Solution

- **箱升格为实体**：发货单下两级结构——装箱箱（系统自增箱号＋箱净重只读＋箱毛重手填＋重量单位）→ 装箱行（所属箱＋物料＋单位＋数量＋行净重＋行备注）。UI 改「添加箱子 → 箱内添加物料行」，同箱行合并显示。
- **行净重自动推导、实测可覆盖**：物料建有重量类单位转换行（如「1 件 = 2.5 kg」）时，行净重默认＝数量×换算；用户过磅后可手改实测值。数量变化即重算（总净重随数量必变），实测在数量定稿后录入。**任何情况下都不回写物料换算**。
- 重量全部可空、审核不拦；装箱清单的「全有或全无」数量校验口径不变。

## User Stories

1. 作为仓管，我希望在发货单草稿的装箱清单 tab 点「添加箱子」建箱，箱号系统按单内自增（1、2、3…）给出且不可改，以便箱号不再需要手填维护。
2. 作为仓管，我希望在箱内点「添加物料」增装箱行，同箱多行在表格中按箱合并显示，以便「一箱多物料」一眼可辨。
3. 作为仓管，我希望删除一只箱时其箱内行一并删除，以便重装时不用逐行清理。
4. 作为仓管，我希望同一物料可以分挂多只箱（每箱一行），以便反映尾数拆箱。
5. 作为仓管，我希望选了物料与数量后行净重自动按物料的重量换算系数带出总净重，以便常规产品不用过磅也有合理箱单重量。
6. 作为仓管，我希望行净重可以手改为实测值，以便与理论重量不符时以秤为准。
7. 作为仓管，我希望修改数量后行净重按系数自动重算（覆盖旧值），以便总净重始终与数量对得上；我理解实测手改应在数量定稿后录入。
8. 作为仓管，我希望物料没有重量换算系数时行净重留空由我手填，且后续改数量不动我填的值，以便无系数产品也能完成箱单。
9. 作为仓管，我希望物料有多条重量类转换行（kg、g 都建了）时系统不猜、默认空，以便不带出错误量级。
10. 作为仓管，我希望装箱行单位本身是重量类单位时直接按行换算得净重，以便按重量发货的物料同样自动。
11. 作为仓管，我希望行净重的单位不开放手改（随换算来源或 kg 基准），以便我不必关心单位一致性。
12. 作为仓管，我希望箱净重由系统按箱内行净重折算汇总、只读，以便不用自己加总；同箱行单位不同也能正确折算。
13. 作为仓管，我希望箱毛重手填、箱上重量单位可改（默认 kg 基准），以便整箱过磅后直接登记。
14. 作为销售内勤，我希望重量字段全部可空、审核不拦（也不拦「毛重 < 净重」），以便不需要箱单重量的发货照常走单。
15. 作为销售内勤，我希望实测重量只留在本行、系统不提示回写物料换算，以便主数据不被单次过磅污染（要建换算我去物料主数据维护）。
16. 作为销售内勤，我希望装箱行/箱落库随审核冻结，物料换算后改不回溯，以便历史箱单口径稳定。
17. 作为审核人，我希望装箱清单的数量「全有或全无」审核校验口径不变，以便既有核对纪律不受重量引入影响。
18. 作为销售内勤，我希望打印模板里装箱行循环区（`pack_lines`）平铺依旧、可取到箱级字段（`${pack_lines.box_gross_weight}` 等），另有箱循环区（`pack_boxes`）排箱汇总，以便按公司版式输出含净/毛重的箱单。
19. 作为系统管理员，我希望箱与重量不新增权限码、随 `sales.delivery` 授权，以便岗位授权矩阵不膨胀。

## Implementation Decisions

以下均为已定案口径（`/grill-with-docs` 产物）：

- **新表装箱箱**（`sal_delivery_pack_box`）：挂发货单；字段＝单内自增箱号（系统生成、不可手改、创建后锁定）＋箱毛重（可空数值）＋重量单位（引用重量类计量单位，默认该类型基准单位，可改）＋可空行备注级文本（如需）；箱净重**不落库**或落受控投影均可，语义恒为 Σ 箱内行净重按单位换算比例折算到箱单位（实现任选，对外只读）。随单级联删除；删箱级联其装箱行；审核后随单锁死。
- **装箱行改造**：`box_no` 自由文本列退出，改为必挂装箱箱；新增**行净重**（可空数值）＋**行净重单位**（引用重量类单位；取值规则：有推导来源随来源单位，无来源默认重量类基准单位；不开放手改）。数量 > 0、单位限默认/转换单位、`base_qty` 6 位折算、物料快照五字段等既有口径不变。
- **行净重推导**（草稿期填值辅助，服务端只存落库值、不重算）：行单位为重量类 → 直接按行换算折算；否则物料恰有一条重量类单位转换行 → 经它折算；物料有多条重量类转换行 → 默认空。有推导来源时，数量/单位/物料变化即**无条件重算覆盖**；无来源时这些变化不触碰手填值。UI 对手改后的重算不给弹窗（作业纪律：实测在数量定稿后录入）。
- **不回写**：不存在「保存时提示新增/修改物料换算」的任何交互；建/改重量换算只走物料主数据维护动线。
- **单位净重载体**：复用 `inv_material_unit` 单位转换（跨类型换算为现成能力），物料不加专设净重字段。重量类转换行同时可供按重量成交的交易单位使用，本期不为此做任何额外开发。
- **校验**：重量全部可空；审核不做「毛重 ≥ 净重」等重量硬校验；「全有或全无」数量校验口径不变（按物料 Σ base 比对）；「从装箱清单获取」发货条目逻辑不受影响。
- **生命周期/权限**：箱与行随单级联删除、审核锁死；不落库存/总账/投影；不进收发货历史、列表 tab 与 CSV 导出；不新增权限资源码，随 `sales.delivery` 各动作。
- **界面**：发货单抽屉「装箱清单」tab 改为箱/行两级——工具栏「添加箱子」，箱行（或箱分组头）展示箱号/箱净重（只读）/箱毛重/重量单位，箱内「添加物料」增行；同箱行合并显示箱级列；删箱需处理「箱内有行」的确认交互。查看/编辑/新建三态同构、tab 标签行数徽标口径随结构调整。
- **打印**：发货单 meta 保留 `pack_lines` 平铺 has_many（箱字段经装箱行 belongs_to 箱一层展开进入字段目录，如 `pack_lines.box_no`、`pack_lines.box_gross_weight`）；新增 `pack_boxes` has_many 循环区（箱号/箱净重/箱毛重/重量单位名）。打印引擎不改（不引入嵌套循环）。字段目录与上传校验随之更新。
- **精度**：重量数值建议 3 位小数（kg 口径到克），落库 numeric；展示格式归 Excel 模板。
- **模块落点**：TS 服务端 `server/` 交易域履约模块（trading/fulfillment）——箱/行模型、CRUD 路由随发货单、审核事务内校验；meta 注册 `pack_boxes` has_many 与装箱行 belongs_to 箱关联；前端发货单抽屉装箱 tab 重构。迁移直接改/重建相关表（未上线，reset 语义）。

## Testing Decisions

- **唯一主接缝：TS 域服务层 Postgres 集成测试**——真库 + fixtures，断言「动作之后事实表变成什么／动作被拒绝并报什么错」，不测内部实现。Prior art：`server/src/modules/trading/outsourced/outsourced.postgres.test.ts`、`reconciliation.postgres.test.ts`、`order/projection.postgres.test.ts`；本功能落 `fulfillment` 模块同型测试文件。
- 打印循环区行为走渲染引擎单测，prior art：`server/src/platform/printing/renderer.test.ts`（`pack_lines` 循环区用例平移到 `pack_boxes` 与 belongs_to 箱字段展开）。
- 鉴权继承（不新增权限码、随 `sales.delivery` 各动作）走 `server/test/iam-authz-matrix.test.ts` 先例。
- 不为装箱箱新增 HTTP 层接缝；前端交互（合并显示、钉住/重算）由实现者按既有前端测试习惯补，规格不强制。
- 测试重点：
  - 箱生命周期：添加箱子自增箱号不可改、删箱级联删行、随单级联删除、审核后锁死。
  - 行净重推导三分支：行单位即重量类直接折算；恰一条重量转换行折算正确；多条转换行默认空。
  - 行净重单位规则：随来源单位；无来源默认重量基准单位。
  - 箱净重聚合：多行同单位加总；异单位（kg/g）经换算比例正确折算到箱单位；箱单位改后折算跟随。
  - 重量可空：整票无重量照常保存审核；审核无重量硬校验。
  - 既有行为回归：全有或全无数量审核校验各拒绝分支不变；「从装箱清单获取」FIFO 分摊不受箱结构影响（按物料 Σ base 口径）。
  - 打印：`pack_lines` 循环区携带箱字段（belongs_to 一层展开）、`pack_boxes` 循环区展开与零行删除；模板上传对箱字段路径校验。
  - 快照冻结：行净重落库后改物料换算不回溯。

## Out of Scope

- 皮重/包装物重量建模（毛净差隐含为包装，永不建模的决策见 ADR）。
- 实测重量回写物料换算系数的任何交互（含「无换算时反推系数提示新建」）。
- 按重量成交的报价/开单动线专门开发（重量转换行天然可用，不额外做）。
- 打印引擎嵌套循环升级；箱级页眉页脚版式。
- 箱尺寸（长宽高/体积）、托盘/混托等更细的物流单元建模。
- 采购入库侧的对称装箱/重量功能（本期只做销售发货）。
- 存量数据迁移（未上线，reset 重建）。
