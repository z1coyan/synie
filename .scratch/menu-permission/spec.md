# Spec: 角色菜单权限（菜单白名单）

**Status:** done
**Feature slug:** `menu-permission`
**ADR:** [docs/adr/2026-08-01-role-menu-whitelist.md](../../docs/adr/2026-08-01-role-menu-whitelist.md)
**Domain terms:** 权限码、权限目录、标准动作、内置角色、超级管理员、公司授权（见 `CONTEXT.md`）
**Depends on:** IAM 角色/权限体系（已交付）、静态菜单配置（已交付）

---

## Problem Statement

系统菜单是前端静态配置，**所有登录用户看到全量菜单**（54 个菜单项），与角色、权限完全无关。车间工人面对着财务、人事、系统管理的整排入口，销售业务员看着生产与库存菜单——导航噪音大、新人上手不知道该点哪；「点进去没权限被拦」的割裂体验天天上演。管理员没有任何手段按角色裁剪导航，权限体系只管「能不能操作」，管不到「看不看得到入口」。

## Solution

给角色增加**菜单权限（菜单白名单）**配置能力：角色可配一份「可见菜单集合」，**空集合 = 未启用限制 = 维持现状全可见**；一旦配置，该角色用户只看得见白名单内的菜单项。用户可见菜单 = 其所有角色白名单的**并集**（所有角色都未配置时才全可见）。只配置叶子菜单项，组/模块可见性自动派生。

菜单权限是**纯导航呈现层**：不拦 URL 直达、不影响任何权限码判定，访问控制的唯一权威仍是权限码。配置入口为角色列表的独立「配置菜单」树形勾选 Sheet，与既有「配置权限」矩阵并列、互不相扰。

## User Stories

1. As a 系统管理员, I want 在角色列表对角色点「配置菜单」打开菜单树勾选 Sheet, so that 按角色裁剪导航入口
2. As a 系统管理员, I want 菜单树按「模块 → 组 → 菜单项」三级展示且与真实菜单一致, so that 勾选时所见即用户所得
3. As a 系统管理员, I want 只勾选叶子菜单项、父级复选框只是批量快捷（三态）, so that 配置结果无歧义
4. As a 系统管理员, I want Sheet 顶部明示「未配置（全部可见）/ 已限制 N 项」状态, so that 一眼看清该角色当前是否被裁剪
5. As a 系统管理员, I want 一键清空白名单恢复全部可见, so that 撤销限制不用逐项取消
6. As a 系统管理员, I want 保存时写入不存在的菜单 code 被拒绝并点名, so that 手滑/接口误调不产生脏数据
7. As a 系统管理员, I want 白名单里存在已失效菜单 code 时在 Sheet 看到「已失效 N 项」提示并可一键清理, so that 菜单演进后授权台账可收拾
8. As a 系统管理员, I want 内置角色（admin/sales）的菜单白名单只读, so that 与内置角色授权只读的先例一致
9. As a 系统管理员, I want 菜单白名单的变更留审计痕迹（旧值→新值）, so that 谁改了谁的导航可查
10. As a 系统管理员, I want 「配置菜单」入口与端点按独立的 `sys.role_menu` 权限码门控, so that 能与「配置功能权限」分人管理
11. As a 受限角色用户（如车间工人）, I want 登录后一级图标栏/二级面板/移动抽屉只显示我可见的菜单, so that 导航干净、不再看到无关入口
12. As a 受限角色用户, I want 我所有角色白名单的并集决定我能看到什么, so that 加角色只会加菜单、不意外也不打架
13. As a 受限角色用户, I want 整组被勾光时该组与所属模块整个消失, so that 不留空壳分组与空模块图标
14. As a 受限角色用户, I want 模块的默认跳转页指向我可见的第一个菜单项, so that 点模块图标不落进被隐藏的页面
15. As a 无任何菜单配置角色的用户, I want 菜单维持现状全量显示, so that 存量用户零感知、零迁移
16. As a 受限角色用户, I want 手敲被隐藏菜单的 URL 仍能打开页面且能干什么照旧由权限码决定, so that 菜单配置不伪装成安全边界、口径单一
17. As a 超级管理员, I want 菜单永远不受白名单限制, so that 与绕过一切权限检查的现状一致
18. As a 销售业务员（内置 sales 角色）, I want 全新部署开箱即只看到销售链相关菜单, so that 内置角色也有裁剪后的导航
19. As a 实施人员, I want 老环境升级后内置角色菜单维持全可见（迁移只建表不写行）, so that 升级不惊扰存量用户
20. As a 系统, I want 新增菜单项对已限制角色默认不可见, so that 新入口不对受限角色意外暴露（管理员显式补勾才开放）
21. As a 系统, I want 菜单 code 一旦发布不可改（改名=删旧增新）, so that 存量白名单不悄悄失效
22. As a 系统, I want 删除角色时其菜单白名单行一并清除, so that 不留孤儿数据
23. As a 系统, I want 前端菜单声明与后端菜单目录有契约测试对拍, so that 两侧漂移在 CI 即被拦下
24. As a 系统, I want `/auth/me` 直接下发当前用户的有效菜单码集合（空=不限制）, so that 前端无需自行多源拼装

## Implementation Decisions

### 语义规约（grill 十问定案）

- **菜单权限 = 菜单可见性**，纯导航呈现层；与资源权限码正交；**不是**数据行级权限（术语切割：`CONTEXT.md` 中「行级权限」保留给将来的记录级数据范围，本特性定名「菜单权限（菜单白名单）」）。
- **白名单 + 空集不启用**：角色存可见菜单集合，空 = 全可见；「限制成什么都不可见」这个状态不存在。
- **多角色并集**：有效可见集 = 所有启用角色白名单的并集；仅当所有角色均无白名单行时不限制。停用角色不参与并集（与权限码取数口径一致）。
- **只配叶子**：白名单只存菜单项 code；组/模块可见性由子项派生（有可见子项则父可见，全空则消失）。
- **不拦直达**：菜单隐藏不做路由拦截；页内按钮与 API 的权限码判定完全不受影响。
- **超管旁路**：`super_admin` 用户的有效菜单码集合恒为空（=不限制），服务端直接下发空数组，前端无需特判。

### 菜单 code 与目录

- 每个叶子菜单项获得稳定 code，约定 **`menu.<模块 key>.<路径末段>`**（`/` 末段取 `home`），如 `menu.scm.sales-orders`、`menu.finance.invoices`、`menu.dashboard.home`。code 发布后**不可改**（改名 = 删旧 + 增新）。
- 菜单事实源仍是前端静态声明（为每项补 code 字段）；后端维护一份**菜单目录**（模块→组→项的 code + 中文标签），作为 sync 校验基准与「已失效项」判定基准；两侧由**契约测试**对拍（叶子 code 集合互等、标签非空），防漂移。
- 后端菜单目录不是新的菜单事实源，不参与渲染、不下发树结构；配置 Sheet 的树直接取自前端菜单声明。

### 数据模型

- 新表 **`sys_role_menu`**：`id` uuid 主键；`role_id` 引用角色表；`menu_code` text；`(role_id, menu_code)` 唯一。形态对齐 `sys_role_permission`（不挂级联删除，删角色时同事务显式清除，同删角色清权限行先例）。
- 迁移只建表不写行（老环境内置角色维持全可见）；`sales` 内置角色的菜单白名单只随**初始化向导**种子（销售链相关菜单项），`admin` 恒空——与「内置角色只随初始化出现，老环境不强塞」先例一致。

### 后端

- IAM 服务新增：读取角色菜单白名单、整体同步角色菜单白名单（sync 语义对齐 `syncRolePermissions`——锁定角色行、校验目录内码（目录外拒绝并点名）、内置角色冲突、只增删差量、有变化才写审计（资源名 `sys_role_menu`，记录旧值→新值））；删角色同事务清白名单行。
- 角色路由新增：`GET /system/roles/:id/menus`、`PUT /system/roles/:id/menus`，权限门控 **`sys.role_menu:read` / `sys.role_menu:update`**。
- 资源注册新增 `sys.role_menu`（中文标签「角色菜单」，动作仅 read/update），随权限目录派生自动进入角色权限矩阵——与「菜单可见性不是权限码」不冲突：可见性本身不是码，**管理白名单的行为**是码。
- `/auth/me` 响应增挂 **`menuCodes: string[]`**：当前用户所有启用角色白名单的去重并集；超管恒空数组；空数组语义 = 不限制。

### 前端

- 菜单声明每项补 code；新增**白名单过滤纯函数**：输入菜单模块树 + 有效菜单码集合，输出裁剪树——空集合原样返回（零行为变化）；否则按白名单留叶子、剪空组空模块、模块默认跳转页重算为首个可见项路径。
- 应用外壳三处渲染（一级图标栏 / 二级面板 / 移动抽屉）统一走该派生，不在各渲染点各自过滤。
- 角色列表新增行操作「**配置菜单**」（按 `sys.role_menu:read` 门控，内置角色只读），打开独立**菜单配置 Sheet**：三级树勾选（叶子落库、父级三态仅快捷）、状态徽标（未配置=全部可见 / 已限制 N 项）、一键清空、已失效项提示区 + 一键清理；保存走整体同步。
- 会话权限类型同步扩展（`menuCodes` 字段），失败 fail-closed 口径不变。

## Testing Decisions

好测试的标准：只测外部行为（API 契约、下发集合、渲染结果），不断言内部结构；能用现有接缝不造新接缝。

- **接缝 1 — IAM 服务层 PG 集成测试**（对标 `iam.integration.test.ts`）：
  - 白名单读/sync 往返；sync 幂等（同集合同步无审计）
  - 目录外 code 拒绝且报错点名；内置角色 sync 抛冲突
  - 变更留审计（资源 `sys_role_menu`、旧值→新值）；删角色级联清行
  - 端点权限门控：无 `sys.role_menu:read/update` 被拒
- **接缝 2 — `/auth/me`**（对标 `server/test/auth.test.ts`）：
  - 多角色白名单并集去重；停用角色不参与；全部角色无行 → 空数组；超管恒空数组
- **接缝 3 — 前后端菜单目录契约测试**（唯一新接缝）：前端菜单声明叶子 code 集合 = 后端菜单目录叶子 code 集合；标签非空；code 符合命名约定
- **接缝 4 — 前端纯函数单测**（对标 `web/app/lib` 既有单测与权限矩阵纯函数层先例）：
  - 过滤派生：空集合原样返回；白名单留叶子、剪空组空模块；默认跳转页重算；组内部分可见时组与模块保留
  - 配置 Sheet 纯逻辑：父级三态推导、勾选父级=批量叶子、提交序列化只含叶子、已失效项识别（白名单有而目录无）
- **UI/浏览器层不强制**（前端为薄可视层，todo-facility 先例）。

## Out of Scope

- **数据行级权限**（记录级数据范围，如「只能看本人创建的单据」）——另一物种，将来单独立项
- 菜单隐藏对应路由的拦截/重定向（已定案不拦，访问控制权威保持权限码单一）
- 用户级菜单白名单（只挂角色；对照公司授权挂用户的先例，本期不做用户级覆盖）
- 组/模块级通配授权（整子树一行授权）
- 菜单的后端化管理 / 动态菜单（菜单仍是前端静态声明，后端目录仅供校验）
- 用户自助定制菜单（重排、收藏、隐藏个别项）
- 移动端菜单之外的呈现差异（卡片模式等现有行为不变）
