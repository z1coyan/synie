# Spec: 履约需求单与生产执行（工单 / 生产入库）

**Status:** ready-for-agent  
**Feature slug:** `fulfillment-demand-production`  
**Depends on:** 销售订单（已交付）、库存分录与仓库（已交付）、BOM/工序主数据（已交付，本规格执行层不依赖报工）

## Problem Statement

业务员录入销售订单后，靠纸条把图号和数量交给车间；车间黑盒作业，主任事后才登记哪款做好了。车间不应看见客户与销售单细节；有些销售靠外购/现货/委外满足、有些不进生产；参展样品等没有客户订单也要做。现有系统只有订单与 BOM 配方，没有「内部需求 → 自制执行 → 成品入账」链路，计划无法收敛待办，库存也接不上产出。

## Solution

引入中间层 **履约需求单**（计划工作台）：可从多张销售订单条目勾选纳入，也可手工建独立需求（无客户）。每行选定 **履约方式**（自制 / 外购 / 委外 / 库存）。第一期仅 **自制** 派生 **生产工单**（一需求行一张未作废工单，本质是未完成数量容器）；车间主任生成工单，仓管用 **生产入库单** 分次入库、削减未完成量（可配置超入比例，对齐采购超收/销售超发）。外购/委外/库存行由计划点完成即离开待办，不自动建采购/委外单。车间界面无客户字段；权限拆成需求单 / 工单 / 生产入库三套。

## User Stories

1. As a 计划员, I want 新建履约需求单草稿, so that 我可以先编排再确认
2. As a 计划员, I want 从已审核未关闭的销售订单条目中勾选多行（可跨多张订单）生成或追加到需求单, so that 一批相关需求集中处理
3. As a 计划员, I want 手工在需求单上增加无销售来源的行（如参展样品）, so that 没有客户订单也能安排生产或其它履约
4. As a 计划员, I want 需求行填写物料、数量、需求日与履约方式, so that 意图明确
5. As a 计划员, I want 有销售来源的行数量被硬校验不超过该订单条目可占用数量, so that 不会超卖式占用
6. As a 计划员, I want 看到某销售条目已被哪些需求行占用多少, so that 我知道还能纳多少
7. As a 计划员, I want 确认需求单后锁住关键口径, so that 下游按稳定需求执行
8. As a 计划员, I want 草稿需求单可改可删, so that 排错可纠
9. As a 计划员, I want 已确认且无未作废生产工单的需求单可作废, so that 整单作废有通道
10. As a 计划员, I want 存在未作废生产工单时禁止作废需求单, so that 不出现断链孤儿
11. As a 计划员, I want 关闭需求单表示不再继续安排, so that 待办能收敛
12. As a 计划员, I want 对无下游的已确认行改履约方式, so that 自制改外购等可调整
13. As a 计划员, I want 已有未作废工单的行不能直接改履约方式, so that 先处理工单再改意图
14. As a 计划员, I want 外购行一点「已完成」, so that 该行离开待办且不进车间
15. As a 计划员, I want 委外行一点「已完成」, so that 整批外协意图登记完毕（本期限登记）
16. As a 计划员, I want 库存行一点「已完成」, so that 现货供应的行离开待办
17. As a 计划员, I want 列表筛选待安排 / 已完成 / 按履约方式 / 按公司, so that 日常跟单
18. As a 计划员, I want 需求单与行带单号与备注, so that 沟通有据
19. As a 计划员, I want 需求单编号可留空自动取号或手填, so that 符合系统编号惯例
20. As a 车间主任, I want 从已确认、自制、尚无未作废工单的需求行生成生产工单, so that 一条需求对应一张执行容器
21. As a 车间主任, I want 同一需求行不能再生成第二张未作废工单, so that 1:1 清晰
22. As a 车间主任, I want 工单上看到物料、数量、需求日/交期、来源需求单号, so that 知道做什么
23. As a 车间主任, I want 工单上没有客户名称与销售单价, so that 客户信息不进车间
24. As a 车间主任, I want 工单未完成数量 = 工单数量 − 累计生产入库, so that 一眼看还剩多少
25. As a 车间主任, I want 无权限时看不到销售订单菜单与客户主数据, so that 权限隔离生效
26. As a 仓管, I want 新建生产入库草稿并挂生产工单, so that 成品能入账
27. As a 仓管, I want 入库行物料必须与工单物料一致, so that 不会入错料
28. As a 仓管, I want 分多次对同一工单入库, so that 分批完工可入
29. As a 仓管, I want 审核生产入库后库存增加, so that 账实数量可发货
30. As a 仓管, I want 审核后工单已入数量增加、未完成减少, so that 进度与库存一致
31. As a 仓管, I want 作废已审核生产入库并回滚库存与已入数量, so that 录错可纠（过负库存校验）
32. As a 仓管, I want 在设置的超入比例内允许累计入库超过工单数量, so that 与采购超收/销售超发习惯一致
33. As a 仓管, I want 超过超入上限时审核被拒绝, so that 乱入被拦住
34. As a 仓管, I want 超入比例为 0 时禁止超入, so that 默认最严
35. As a 系统, I want 累计已入 ≥ 工单数量时自动将工单标为已完工, so that 主任不必二次点完成
36. As a 系统, I want 工单完工后回写需求行已完成, so that 计划待办自动收敛
37. As a 系统, I want 生产入库审核写正向库存分录（来源类型指向生产入库）, so that 库存余额与分录流水可追溯
38. As a 系统, I want 第一期生产入库不过生产成本总账、只记数量, so that 与库存 v1 数量账一致
39. As a 管理员, I want 配置生产入库超入比例（0～100%）, so that 容差可调
40. As a 管理员, I want 履约需求单、生产工单、生产入库三套独立权限, so that 计划/车间/仓管分权
41. As a 管理员, I want 新资源进入权限目录与权限矩阵, so that 可授权
42. As a 管理员, I want 单据挂编号规则, so that 单号体系统一
43. As a 业务员, I want 销售订单审核后不必自动进生产, so that 不需要排产的单不会污染车间
44. As a 业务员, I want 从不被勾入需求的订单条目对生产侧不可见, so that 外购直发等路径不被逼建工单
45. As a 计划员, I want 一张销售条目拆成多条需求行（拆批）, so that 分批落实而工单仍 1:1 挂行
46. As a 计划员, I want 草稿与已确认需求都计入销售条目占用（未作废）, so that 两张草稿不能一起超占
47. As a 计划员, I want 作废需求单后释放其对销售条目的占用, so that 数量可再被纳入
48. As a 计划员, I want 仅已审核且未关闭的销售订单条目可被勾选, so that 无效承诺不能进需求
49. As a 仓管, I want 生产入库指定叶子仓库, so that 货落正确仓
50. As a 仓管, I want 仅草稿生产入库可改可删, so that 状态机与采购入库一致
51. As a 车间主任, I want 在无入库记录时可作废工单, so that 下错可撤（有已审核未作废入库则禁止作废）
52. As a 系统, I want 工单作废后需求行回到可再生成工单状态, so that 可重下
53. As a 计划员, I want 需求单头选择公司且行与下游同公司, so that 多公司数据隔离
54. As a 审计人员, I want 写操作进审计日志, so that 变更可追溯
55. As a 开发, I want 资源接 GraphQL list 分页、gridMeta、前端菜单与中文权限标签, so that 界面可操作
56. As a 开发, I want 新资源补 authz 矩阵世界夹具, so that CI 权限覆盖不红
57. As a 用户, I want 菜单在「生产」组看到需求单、生产工单、生产入库入口, so that 与 BOM 同组好找
58. As a 计划员, I want 从需求行跳转看来源销售订单（有销售权限时）, so that 对账交期；无权限则不可见
59. As a 仓管, I want 入库默认单位折算与采购入库一致（base 数量）, so that 库存分录单位口径统一
60. As a 系统管理员, I want 初始化/演示数据可选带一条最短生产链样例（可选，不阻塞主交付）, so that 演示可走通

## Implementation Decisions

### 领域与资源

- 在 **mfg 域** 新增三类业务单据（名称实现时可英文化，权限中文标签用领域名）：
  - **履约需求单** + **履约需求行**（行不设独立权限点：读写随需求单，同 BOM 子行/订单条目先例）
  - **生产工单**
  - **生产入库单** + **生产入库行**（行权限随入库单）
- 权限前缀建议：`mfg.demand`、`mfg.work_order`、`mfg.output`（生产入库）；标准动作 + 工作流：需求单 `confirm` / `close` / `void`；行 `complete`（外购/委外/库存）；工单 `void`（及必要时 `generate` 挂在需求行或工单 create）；入库 `audit` / `void`。
- 公司维度：三单均有 `company_id`，挂 `CompanyAccessible`；fail-closed 公司授权。
- 审计：可写资源接 `Audit.Fragment`；update/destroy `require_atomic? false`。
- 编号：三单 create 挂 `Numbering.AutoNumber`；初始化预置规则（文案实现自定，如 `M(D)-` / `M(W)-` / `M(R)-`）。
- GraphQL：`paginate_with: :offset`；登记 `grid_meta`；前端 `permission-labels` 与操作日志中文标签。
- 权限矩阵世界：`authz_matrix/world.ex` 为三资源补 builders / write_inputs / 可见性。

### 履约需求单

- 头字段：公司、单号、状态、备注、业务日期（可选，默认当天）。
- 状态机：**草稿 → 已确认 → 已关闭**；**作废** 为终止态。仅草稿可改可删；确认后头关键字段锁定；关闭不可逆（或仅已确认可关，实现选一，推荐已确认可关、关闭后不可再下工单/点完成）。
- 作废：仅当关联未作废生产工单数为 0；作废释放销售占用。
- 行字段：物料、单位（限默认/转换单位）、数量、折算 base 数量、需求日、履约方式（枚举：`make` 自制 / `buy` 外购 / `outsource` 委外 / `stock` 库存）、可选 `sales_order_item_id`、行状态、行备注；物料快照（编号/名称/规格等，对齐销采行快照惯例）。
- 行状态：
  - 外购/委外/库存：**待安排 → 已完成**（`complete` 动作）
  - 自制：**待安排 → 已安排**（已生成未作废工单）→ **已完成**（工单完工回写）
- 从销售纳入：条目池 = 同公司、订单已审核未关闭、剩余可占用 > 0；可跨销售订单；纳入时带出物料与建议数量（默认=剩余可占用，可改小）。
- **销售占用**：对未作废需求单上、有来源的行，Σ 行 base 数量 ≤ 订单条目订购 base；占用含草稿与已确认。可占用 = 订购 base − Σ 占用。不与已发数量混算（发货仍独立；第一期不做「已下达生产」投影列到销售条目，若实现期发现列表需要可加只读计算字段，非必须）。
- 确认后改履约方式：行无未作废工单且未完成时可改；已完成行不改。
- 拆批：同一销售条目多行需求即可；不在工单层拆。

### 生产工单

- 由动作从需求行生成（推荐：需求行工作流动作 `generate_work_order`，权限可用工单 `create` 复用）：前置 = 需求单已确认、行自制、行未完成、无未作废工单。
- 字段：公司、单号、物料（与行一致并快照）、数量（= 需求行数量，生成后不可改数量或仅草稿可改——推荐生成即进行中、数量锁定）、需求日/交期、来源需求行 id、状态、累计已入 base、未完成（计算或冗余投影）。
- **一需求行至多一张未作废工单**（DB 唯一或部分唯一约束 + 校验）。
- 状态：**进行中 → 已完工**；**作废**。无已审核未作废生产入库时可作废；作废后行回到待安排。
- 不存客户、不挂销售订单 id 于车间只读默认视图；计划侧可通过需求行看来源。
- **不做**工序、报工、工艺路线快照（第一期）。

### 生产入库单

- 对标采购入库状态机：**草稿 → 已审核 → 已作废**；仅草稿可改可删；无反审核。
- 头：公司、单号、入库日期、头仓（可空预填）、备注。
- 行：必挂生产工单、物料（= 工单物料）、单位/数量/base_qty、行仓（本公司启用叶子）、行备注、物料快照。
- 可一单多行挂不同工单（同公司）；同一工单可被多张入库单分次入。
- **审核**（同一事务）：
  - 校验超入：该工单累计已入（含本单）≤ 工单数量 × (1 + 生产入库超入比例)
  - 写正向库存分录（`voucher_type` 如 `mfg.output`），数量 = base_qty
  - 累加工单已入；若已入 ≥ 工单数量 → 工单已完工，需求行已完成
- **作废**：分录作废（过负库存校验）+ 回滚已入 + 若因此未完成 > 0 则工单回到进行中、需求行回到已安排（若仍有工单）。
- **不过总账**（第一期无生产成本科目设计）。
- 副产品、多物料产出：不做。

### 设置

- **生产入库超入比例**：小数 0～1，默认 0；语义同 `delivery_overship_ratio` / `receipt_overreceive_ratio`。
- 落点：**新建 `mfg_setting` 单行表**（种子一行、只读改不增删），权限 `mfg.setting`；界面「生产 → 设置」或供应链设置下生产 Tab 读该资源。不塞进 `sal_setting`（避免销售权限改生产容差）。
- 草稿入库不硬卡超入，**审核硬拦**。

### 库存分录

- 扩展数量账来源：生产入库审核写正、作废标记取消；余额与分录流水自然可见。
- 不引入 WIP 仓、不扣原料。

### 前端

- 路由挂在 `/_app/mfg/`：需求单、工单、生产入库、设置。
- 需求单：头 + 行编辑；「从销售订单选择」多选对话框（跨单）；行上履约方式与完成按钮；自制行「生成工单」。
- 工单：列表展示未完成数量；无客户列。
- 生产入库：对标采购入库表单简化版（无对手、无过账科目）。
- 菜单「生产」组追加入口；与 BOM/工序并列。

### 文档（交付时）

- 新建产品文档篇章（已实现行为）；更新 `CONTEXT.md` 仅当实现与定案有偏差时；ADR 已存在不重复造。

### 明确技术对齐

- 金额/单价：需求与工单与生产入库 **不涉及** 销售价税。
- 与 BOM：执行不强制有 BOM；有 BOM 也不自动扣料。
- 与外协标记：工艺路线外协标记本规格不读写。

## Testing Decisions

- **好测试标准**：只测外部行为——资源动作后的状态、数量投影、库存分录、校验错误文案级结果；不断言内部 change 模块名或私有函数结构。
- **主接缝（已确认）**：`synie_core` 下 mfg 域 **Ash 资源集成测试**（真库沙箱），对标 `purchase/receipt_test.exs`、`mfg/mfg_test.exs`。可拆为 2～3 个文件（需求单 / 工单 / 生产入库），仍属同一类 seam。
- **必覆盖场景**：
  - 需求单草稿→确认→关闭/作废；有未作废工单不可作废
  - 跨销售单勾选 + 手工无来源行
  - 销售占用硬校验（含两张草稿合计超占失败）
  - 四态履约：仅自制可生成工单；外购/委外/库存 complete
  - 一需求行第二张未作废工单被拒
  - 生产入库分次、审核分录正数、已入与未完成、作废回滚
  - 超入比例 0 与 >0；超上限审核失败
  - 满量/容差内超入后工单完工与需求行完成
  - 工单作废条件（有/无已审核入库）
- **设置**：在入库超入用例中读写 `mfg_setting`，不单开无业务的配置测。
- **不做（本规格）**：前端 e2e、GraphQL 契约单测、工序/APS、打印专项（接入后随全资源目录自然可用）。
- **Prior art**：`receipt_test.exs`（超收、分录、作废）、销售发货超发、现有 `mfg_test.exs` 夹具风格；权限靠 `authz_matrix` 完整性守卫覆盖新资源登记。

## Out of Scope

- 有限产能排产、机台日历、自动插单、APS
- 工序级报工、工艺纸条数字化、工单内工序进度
- 领料、按 BOM 自动扣料、在制仓、倒冲
- 外购/委外自动生成采购订单、采购申请、委外加工单及发料/收回/加工费
- 副产品入库、联产品成本
- 生产入库总账、工单成本、制造费用
- 销售订单条目上强制「需要生产」标记或物料自制属性主数据
- 需求单自动合并算法、MRP 净需求运算、齐套分析
- 跨公司调拨式生产、多工厂高级计划
- 本规格不修改 BOM 主数据模型（配方仍独立）
