## Problem Statement

履约需求单第一期只闭环了「自制」：外购/委外行只能登记意图、计划手工点完成，与采购订单、委外订单完全断链——采购员不知道需求池里有什么，计划员看不见下没下单、回没回货，需求单待办不可信。ADR 2026-07-24 明确把「外购/委外生成入口」留作纯增量，现予落地。

## Solution

采购侧拉：采购/委外订单编辑表单内「从需求单勾选」带入条目（条目挂来源需求行，可空）。需求行冗余两个受控投影——**已下单数量**（订单审核加、作废减，草稿不占）与**已收数量**（入库审核沿条目回溯加、作废减）；累计已收 ≥ 需求数量自动完成。新增全局**需求超下单比例**容差（默认 0）。销售占用口径同步改为「草稿不占、确认占量」。库存履约方式不动。

## User Stories

1. As a 采购员, I want 在采购订单编辑时从外购需求行池勾选带入条目, so that 不用对着纸条录单
2. As a 采购员, I want 委外订单只列委外需求行、普通订单只列外购需求行, so that 不会勾错履约方式
3. As a 采购员, I want 勾选池只列已确认未关闭、未完成、剩余可下单量>0、本公司的行, so that 池子干净
4. As a 采购员, I want 带入时数量默认=剩余可下单量且可改, so that 可分次下单
5. As a 采购员, I want 带入行的需求日落在条目上, so that 知道计划的承诺时间
6. As a 采购员, I want 手工行与带入行并存, so that 无需求的采购不受影响
7. As a 采购员, I want 带入后常规行照勾报价、零星行照手填价, so that 价格机制不变
8. As a 采购员, I want 委外带入后自己选 BOM 代入清单, so that 配方选择权在执行侧
9. As a 采购员, I want 勾选带入不需要需求单读权限, so that 权限边界不被穿透
10. As a 计划员, I want 需求行上看到已下单数量与已收数量, so that 分流与到货一眼可见
11. As a 计划员, I want 已下单未完成的行显示「已下单」徽标, so that 待办列表可直接扫
12. As a 计划员, I want 无下单量的行仍可手工点完成, so that 决定不执行的行有出口
13. As a 计划员, I want 已下单的行不能点完成、须等入库回写, so that 完成语义统一为实物闭环
14. As a 计划员, I want 有已审核未作废采购条目引用的行不可改履约方式、需求单不可作废, so that 不断链
15. As a 计划员, I want 草稿采购订单不锁我的需求单, so that 采购员的半成品不卡计划
16. As a 系统, I want 订单审核时复核需求行仍有效并校验超下单容差, so that 草稿期的变化在生效时点被拦住
17. As a 系统, I want 入库审核沿条目回写需求行已收、满量自动完成, so that 与生产入库回写对称
18. As a 系统, I want 订单作废/入库作废回滚对应投影, so that 纠错后数量一致
19. As a 管理员, I want 配置需求超下单比例（默认 0）, so that 起订量场景有受控出口
20. As a 系统, I want 销售占用改为确认才占量, so that 与已下单数量口径全系统统一

## Implementation Decisions

### 数据模型

- `pur_order_item` 加可空 `demand_line_id`（→ mfg 需求行）与可空 `demand_date`（日期）。
- 需求行加冗余投影列：`ordered_qty`（已下单数量）、`received_qty`（已收数量），均默认单位口径、默认 0。
- `sal_setting` 加 `demand_overorder_ratio`（小数 0～1，默认 0），供应链设置页采购 Tab 维护。

### 勾选带入（采购侧拉）

- 池查询挂 `purchase.order` 资源权限，返回带入所需最小字段（需求单号、行 id、物料、数量、需求日、剩余可下单量）；过滤：需求单已确认未关闭未作废 + 行未完成 + 剩余可下单量>0 + 公司一致 + 履约方式匹配单据委外标记（外购↔非委外单、委外↔委外单）。
- 带入只落物料、数量（默认剩余可下单量）、需求日、demand_line_id；报价引用/单价/税率走现有机制；委外配置不自动代入。
- 需求日不驱动任何逻辑、不校验早晚；手工行 demand_line_id/demand_date 皆空。

### 投影与校验

- **已下单数量**：订单审核时按行累加（含容差校验：来源行累计已下单（含本单）≤ 需求 base × (1 + ratio)，任一行不过整单拒），作废回滚；草稿不占不校验。
- 审核复核（仅挂需求行的行）：行存在、所属单已确认未作废未关闭、行未完成、履约方式匹配单据委外标记。
- 需求单作废/行改履约方式的「无未作废下游」校验扩展：含已审核未作废采购/委外订单条目（草稿引用不构成约束）。
- **已收数量**：采购入库/委外入库审核累加订单条目已收数量时，沿条目回溯需求行同步累加（同事务）；作废回滚；累计已收 ≥ 需求数量 → 行已完成（幂等，已完成行重复触发无副作用）。
- 点完成动作加前置：行已下单数量 = 0（库存行恒满足）。
- **销售占用口径改造**：需求单销售占用由「未作废（含草稿）」改为「已确认未作废」——确认时校验并占量、作废释放；存量数据无已确认单据语义变化，仅草稿行为变化。
- 需求行列表派生「已下单」徽标：ordered_qty > 0 且未完成（计算字段/派生展示，不落枚举）。

### 权限与登记

- 不新增权限资源；勾选池查询与带入挂 `purchase.order` 现有动作。需求行新列随需求单资源只读。
- authz 矩阵世界补：采购条目带 demand_line_id 的写输入、需求行投影列只读可见性。

## Testing Decisions

- **主接缝**：`synie_core` Ash 资源集成测试（真库沙箱），对标 `purchase/receipt_test.exs`、`mfg/mfg_test.exs`；只测外部行为（状态、投影、校验错误），不断言内部结构。
- **必覆盖场景**：
  - 勾选带入落字段（数量默认剩余可下单、需求日、来源引用）；履约方式不匹配被拒
  - 订单审核累加已下单、作废回滚；草稿不占量（两张草稿可同时挂同一行，审核时后者撞容差）
  - 超下单比例 0 与 >0；超上限审核失败
  - 审核复核：需求单已作废/已关闭/行已完成/方式不匹配 → 拒审
  - 有已审核订单条目引用的行：改履约方式被拒、需求单作废被拒；仅草稿引用则不挡
  - 入库分次回写已收、满量自动完成、入库作废回滚（已完成回退）
  - 点完成：无下单量可行、有下单量被拒
  - 销售占用：草稿不占、确认占量超占失败、作废释放
- **不做（本规格）**：前端 e2e、打印专项。

## Out of Scope

- 库存履约方式的任何联动（维持手工点完成）
- 需求行合并下单、一需求行限一张订单条目
- 委外 BOM/发料清单/副产物清单的自动代入
- 需求日驱动的交期预警、采购待办排序
- 采购申请/询价等更上游的计划单据
- MRP 净需求运算、齐套分析
