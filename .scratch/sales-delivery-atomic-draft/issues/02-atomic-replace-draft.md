# 02 — 完整快照替换已有销售发货草稿

**What to build:** 让用户编辑已有销售发货草稿时一次提交保存后的完整状态。系统锁定目标草稿，在一个事务内校验表头和全部子记录身份，计算并执行发货条目、装箱箱及嵌套装箱行的新增、修改和删除；请求中缺失的既有子记录视为删除。未知、重复或属于其他销售发货单的 ID 必须拒绝整单请求，任何失败都让数据库完整保持保存前状态。编辑抽屉不再计算差异、排序删除、逐行重试或维护临时箱 ID 映射。

**Blocked by:** 01 — 整单创建销售发货草稿

**Status:** resolved

- [x] 已有草稿通过独立的整单替换操作保存，路径中的销售发货单 ID 是唯一目标身份
- [x] 同一请求可以同时新增、修改和删除发货条目、装箱箱与箱内装箱行
- [x] 请求中缺失的既有发货条目、装箱箱和装箱行在保存后删除，缺失装箱箱的所属装箱行一并清理
- [x] 未改变的子记录保持原身份，新记录取得数据库 ID，响应返回替换后的权威完整草稿
- [x] 未知、跨单或同请求重复的发货条目、装箱箱、装箱行 ID 返回可识别的校验错误
- [x] 替换只允许草稿状态，并继续执行公司数据范围与销售发货修改权限
- [x] 任一校验或写入失败时，表头和所有子记录均保持替换前状态
- [x] 编辑抽屉只发一次整单替换请求，不再调用子资源独立写接口
- [x] 并发语义保持最后保存者覆盖，不新增修订号或乐观锁
- [x] 真实 HTTP 与 PostgreSQL 验收覆盖混合增改删、清空子表、身份攻击和事务回滚
