# 03 — 失败定位与“保存并审核”闭环

**What to build:** 让整单保存的失败结果与用户编辑的完整草稿一一对应。请求结构和领域校验错误都通过统一错误包络返回可索引到表头、发货条目、装箱箱或箱内装箱行的字段路径；抽屉保持打开并保留全部输入，在对应字段或表格行展示错误，同时只报告整单失败。“保存并审核”必须等待整单保存成功后再独立发起审核；保存失败时不审核，审核失败时保留刚保存的完整草稿并允许继续修改。

**Blocked by:** 02 — 完整快照替换已有销售发货草稿

**Status:** resolved

- [x] 请求结构错误和业务校验错误都能返回稳定的索引字段路径，至少覆盖表头、发货条目和嵌套装箱行
- [x] 前端能把字段路径映射到对应表单字段或表格行，并保留汇总错误提示
- [x] 保存失败时抽屉不关闭、完整本地草稿不丢失、查询缓存不被部分服务器状态覆盖
- [x] 保存失败只显示整单失败，不显示任何部分保存成功信息
- [x] “保存并审核”严格按整单保存成功后再审核的顺序发出两个请求
- [x] 整单保存失败时不会发出审核请求
- [x] 审核失败时数据库保留刚保存的完整草稿，抽屉允许用户修正后重新保存或审核
- [x] 浏览器端到端验收覆盖一次整单保存请求、两阶段保存审核、保存失败保留输入和审核失败保留草稿
- [x] 操作日志保持既有语义，不新增整单差异日志，也不把保存记作审核
