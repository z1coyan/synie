# 01 — 整单创建销售发货草稿

**What to build:** 让用户在新建销售发货抽屉中一次提交表头、发货条目、装箱箱及其装箱清单行，并得到一张完整持久化的草稿。整单创建必须通过一个权威写入口进入同一数据库事务；任一字段、引用或子记录失败时，数据库不得留下表头、部分明细、空箱、装箱行、附件挂接或操作日志。成功响应返回持久化后的完整草稿，使抽屉能取得数据库生成的 ID、箱号和派生字段，并继续支持后续审核动作。迁移期间旧写入口可暂时存在，但新建抽屉不得再逐项调用它们。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 新建销售发货采用完整嵌套草稿契约，发货条目与装箱行中的新记录无需数据库 ID
- [x] 表头、发货条目、装箱箱、装箱行、附件同步和既有操作日志全部在一个事务内完成
- [x] 成功响应包含完整持久化草稿以及所有数据库生成的子记录 ID、系统箱号和派生字段
- [x] 新建抽屉只发一次整单创建请求，不再创建表头后逐行保存子记录
- [x] 整单创建继续执行公司范围、销售发货创建权限和现有草稿保存校验
- [x] 任一发货条目或装箱行失败都会回滚表头、其他子记录、附件挂接和操作日志
- [x] 真实 HTTP 与 PostgreSQL 验收覆盖完整创建成功及中途失败零残留
- [x] 现有销售发货查询、读取、删除、审核与作废行为保持通过
