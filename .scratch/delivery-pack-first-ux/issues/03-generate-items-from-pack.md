# 03 — 「从装箱清单获取」：FIFO 分摊生成发货条目

**What to build:** 发货条目表格工具栏新增按钮**「从装箱清单获取」**，按规格 `.scratch/delivery-pack-first-ux/spec.md` 实现：

**核心：FIFO 分摊纯函数**（新文件如 `web/app/lib/delivery-pack-generate.ts` + colocated `bun test` 单测，prior art `amount.test.ts`）。输入：装箱行（物料/base 汇总）、候选条目池（含 `remainingBaseQty`、订单日期、订单号、行序、币种、单位、换算系数）、既有发货行、头默认仓。输出：生成行列表＋报告（三组，见下）。规则——

- **增量补齐（A）**：已有发货条目的物料整物料跳过；对不上（既有合计 ≠ 装箱汇总）进报告第③组仅提醒。
- **FIFO 分摊（b）**：候选按订单日期升序（同单按行 `idx`，条目 id 兜底）依次扣 `remainingBaseQty`，装满一条扣下一条，一物料可拆多行。
- **尾差只分不超**：超剩余部分不压末行，进报告第②组（物料、装箱量、已分量、余量）。
- **币种锁定**：既有行非空→以现有行币种过滤候选池；空→取本次全部候选中订单日期最早者币种定整单；异币种候选排除，受影响物料进报告第②组。
- **零候选**（池内无该物料）：进报告第②组。
- **生成行**：订单条目＝命中条目（写入 `orderItemsRef` 缓存使 `transformItem`/校验链路照常工作）；单位随订单条目；**数量＝分摊 base × 单位换算系数的精确值**（保证服务端 `base = qty ÷ factor` 重算后逐物料 Σ 条目 base ＝ Σ 装箱 base 分毫不差）；仓库＝头默认仓；`idx` 接续现有行。系数取自 `materialUnitClient`（`LiveBaseQtyField` 先例，注意默认单位 factor＝1 的情形）。

**交互**：

- 按钮位置：发货条目（「发货信息」tab）表格 toolbar；无装箱行时禁用（提示先去「装箱清单」tab 录入）；头默认仓库为空时点击 toast 拦截「请先填写默认仓库」一行不生成；查看模式/非草稿不显示或禁用（随表格 readOnly 口径）。
- 结果反馈两档：全干净（仅生成、无任何报告项）→ sonner「已从装箱清单生成 N 行发货条目」；有任何报告项 → 弹框三组列明：①已生成（物料→订单号→数量，拆行逐列）②未分配（尾差/零候选/币种不符，文案点名「审核前需人工处理」）③对不上但未改动（仅提醒）。
- 生成行写入本地 `items` state（普通草稿行，可改可删），由既有 `persistItems` 随单保存落库；不直接调任何后端新接口（后端零改动）。
