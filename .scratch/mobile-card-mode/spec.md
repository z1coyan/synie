# 移动端卡片模式（SynieDataGrid Card Mode）

Status: ready-for-agent

## Problem Statement

外勤业务员和管理者用手机访问 Synie ERP 时，所有列表页（销售订单、采购入库、库存余额等 30+ 资源）都是一张 `min-w-[720px]` 的桌面数据表格：需要反复横向滚动才能看到状态列，列头筛选按钮点按目标极小，行内操作菜单藏在屏幕右侧滚动区域之外，审批一张单据要在手机上捏合缩放、左右拖表格。移动端目前处于「技术上能打开、实际上不可用」的状态，手机上查单、审批这类高频轻场景无法完成。

## Solution

视口宽度小于 1024px（Tailwind lg 以下，含竖屏平板）时，SynieDataGrid 自动从表格切换为**卡片模式**：每条记录渲染为一张卡片（单号作标题、客户/名称作副标题、金额/状态/日期作摘要行），纵向滚动浏览；顶部保留搜索框，「筛选」和「排序」各收进一个按钮，点开为底部弹层；列表底部「加载更多」按钮追加下一页；点卡片打开详情抽屉（小屏下已天然全屏）；审批/确认/查看等行内动作保留在卡片上的 ⋯ 菜单里。建单、编辑、批量操作、导入导出、打印等重操作在移动端不出现，回桌面完成。整个机制收敛在 grid 组件内部，30+ 资源页面不改一行代码即同时获得移动端体验。

## User Stories

1. 作为外勤业务员，我想在手机上看到卡片式的销售订单列表（单号、客户、金额、状态一眼可读），以便不用横滚表格就能找到要查的单。
2. 作为管理者，我想在手机上按状态筛选列表（如只看「待审核」），以便快速圈出要我处理的单据。
3. 作为管理者，我想在手机上从卡片 ⋯ 菜单直接执行审批/确认类动作，以便不在电脑前也能推进流程。
4. 作为手机用户，我想点卡片打开全屏详情抽屉查看单据全貌，以便核对卡片摘要之外的字段。
5. 作为手机用户，我想用顶部搜索框按关键字搜列表，以便在大列表里快速定位记录。
6. 作为手机用户，我想用「排序」按钮选择排序列和方向，以便按日期倒序看最新单据。
7. 作为手机用户，我想看到已生效筛选以 Chips 形式列在列表上方且可逐个清除，以便知道当前列表口径。
8. 作为手机用户，我想点「加载更多」追加下一页并看到「已加载 N/共 M 条」，以便掌握浏览进度且已看内容不丢。
9. 作为手机用户，我想筛选/搜索/排序变更后列表重置回第一页重新加载，以便结果集始终与条件一致。
10. 作为手机用户，我不想在手机上看到新增/导入/导出/打印按钮，以便界面只保留手机上有意义的操作。
11. 作为手机用户，我不想在手机上看到勾选框和批量操作条，以便界面不为桌面重操作留残骸。
12. 作为页面开发者，我想卡片标题/副标题/摘要默认由列顺序推导（第 1 列标题、第 2 列副标题、第 3–5 列摘要），以便零配置获得可用的移动端列表。
13. 作为页面开发者，我想用 override 精调某列在卡片上的角色（标题/摘要/隐藏），以便个别资源的卡片呈现更贴合业务。
14. 作为页面开发者，我想用动作级 mobile 标记微调某动作在移动端的显隐，以便把特定动作（如行内打印）从手机上拿掉、或把特定批量动作（如批量审批）放上来。
15. 作为手机用户，我在浏览树形资源（物料分类）时想直接看到平铺节点并靠搜索定位，以便不在窄屏上玩层级缩进。
16. 作为手机用户，我想在筛选 sheet 里用与桌面一致的筛选控件（枚举下拉、数值区间、日期范围）逐列配置，以便筛选能力与桌面等价。
17. 作为手机用户，我想筛选按钮上显示已生效筛选数量徽标，以便不开弹层也知道有筛选在作用。
18. 作为手机用户，我想枚举值在卡片上以胶囊呈现、布尔以是/否呈现、日期为本地短格式，以便卡片与表格的信息口径一致。
19. 作为手机用户，我想有图片列/附件图片列的列表在卡片上看到缩略图并可点开全屏预览，以便手机上核对图纸/票据图片。
20. 作为手机用户，我在无权限访问某资源时想看到明确的「无权限访问」提示，以便知道该找管理员而非反复重试。
21. 作为手机用户，我在加载失败时想看到错误信息和重试按钮，以便网络抖动后能自行恢复。
22. 作为手机用户，我在空结果时想看到「暂无数据」提示，以便区分「没数据」和「坏了」。
23. 作为手机用户，我想从手机切到桌面（或旋转平板拖宽窗口）时列表形态随断点即时切换，且搜索/筛选/排序状态不丢，以便跨设备连续工作。
24. 作为桌面用户，我想桌面端表格体验完全不受卡片模式影响，以便现有工作流零回归。
25. 作为手机用户，我想 fk 字段在卡片上显示可读的关联标签（如客户名）而非 id，以便不点详情也能读懂记录。
26. 作为手机用户，我想选择器模式（弹窗选记录）在手机上同样以卡片呈现，以便手机上也能完成选择操作。
27. 作为维护者，我想卡片模式的决策逻辑（字段映射、加载更多、动作过滤、排序换算）有纯函数自检覆盖，以便回归时 CI 能拦住。
28. 作为手机用户，我想「加载更多」在已加载完全部数据后消失或禁用，以便明确知道到底了。
29. 作为手机用户，我想加载下一页失败时看到错误提示且已加载内容保留，以便重试不丢失浏览进度。

## Implementation Decisions

- **切换机制**：`useMediaQuery('(max-width: 1023px)')` hook 驱动渲染分支，断点对齐仓库统一的移动断点 `lg`（`web/AGENTS.md` 约定；实现期从原定 md 修正为 lg）。两形态（DataGrid / 卡片流）结构差异大，纯 CSS 显隐不可行；page/search/sort/filters 状态由组件统一持有，两形态共享，断点跨越时查询上下文不丢。
- **卡片字段映射（纯函数）**：输入 meta 列定义 + overrides，输出 `{ title, subtitle, summary[] }` 角色映射。默认约定：第 1 列=标题、第 2 列=副标题、第 3–5 列=摘要（不足则少，无第 2 列则无副标题）。`ColumnOverride` 新增 `mobileRole?: 'title' | 'subtitle' | 'summary' | 'hide'` 逃生口：显式指定优先于位置约定；指定了 title/subtitle 的列不参与摘要；`hide` 列不上卡片。
- **卡片渲染**：单元格内容复用现有 `defaultCell`（enum 胶囊、boolean 是/否、datetime 本地化、fk 标签链接），与表格口径一致；摘要行排列为「标签: 值」或纯值，enum/布尔直接胶囊。附件图片列有图时卡片左侧显示首图缩略图，点开全屏预览（复用现有 SyniePreview）。
- **工具栏（卡片模式）**：搜索框（复用现有草稿化搜索组件）+「筛选」按钮（带生效数量徽标）+「排序」按钮。hideSearch 时搜索框不渲染，筛选/排序按钮不受影响。
- **筛选 Sheet**：底部弹层，逐列（meta 中 filterable 列）配置条件，输入控件复用现有 filter-popover 的控件实现（按列类型分派：枚举下拉/数值区间/日期范围/fk 选择/文本）。「应用/清空」收口；已生效筛选 Chips 行复用现有实现，两形态共用。
- **排序 Select**：底部弹层或下拉，列出 sortable 列 + 方向（升/降），与现有三态排序状态互通——桌面点表头、手机用 Select，落到同一个 SortState；树形页面排序入口隐藏（同表格形态现状）。
- **加载更多**：卡片模式弃用数字分页器，改为底部「加载更多（N/共 M 条）」按钮；点击按 offset 拉下一页 append 到已有数据。search/filters/sort/fixedFilter 任一变更重置回第 1 页并清空已累积数据。已加载 ≥ 总数时按钮消失。追加请求失败 toast 报错、已加载数据保留、按钮可重试。加载更多状态迁移写成纯函数（输入当前累积/总数/查询变更事件，输出新累积与请求参数）。
- **动作面**：动作类型（BulkAction/RowAction/内建动作）新增 `mobile?: boolean`。卡片模式默认：toolbar 动作（新增/导入/导出/打印及自定义 toolbar 动作）隐藏、勾选与批量条关闭；行内 ⋯ 菜单完整保留。`mobile: true` 使某 toolbar/批量动作在移动端显示（如批量审批上手机）；`mobile: false` 使某行内动作在移动端隐藏（如行内打印）。默认策略与标记判定收敛为纯函数。
- **树形资源**：卡片模式下 `treeActive` 恒为 false——常驻平铺分页（追加式），找节点靠搜索；复用现有「筛选即平铺」回退路径，不新建机制。
- **详情抽屉**：不改代码——现有默认宽度类（小屏全屏、大屏 480px）已满足卡片模式配套查看；卡片点击行为 = 触发现有 onView 动线。页面未配 onView 时卡片不响应点击。
- **选择器模式（pick）**：卡片模式下同样生效——单选点卡片即选、多选卡片左上角勾选位；选择器场景的工具栏/动作面按现状（本就无批量条）。
- **图片列**：image override 与附件图片列在卡片摘要区以缩略图呈现，点击进全屏预览，行为与表格形态一致。
- **保持不动**：列头筛选按钮、数字分页器、ActionBar、列排序箭头均为桌面形态专属，卡片模式不渲染；查询层（client.query 参数形状、queryKey 结构）不因形态变化，仅卡片模式追加「累积页」维度。
- **同步文档**：落地时更新 ADR 2026-07-29（如实现偏离决策）与 `docs/产品文档/`（卡片模式为横切 UI 机制，归属篇目实现时定）；CONTEXT.md「卡片模式」词条已存在，如有语义偏移同步修订。

## Testing Decisions

- **唯一接缝：纯函数自检**。新增一个 card-mode 自检文件（import 即自执行断言、失败退出非零），注册进现有 `run-checks.ts` 汇总入口，随 `bun run check` 在 CI 运行。不新增浏览器 e2e、不引入组件渲染测试基建——浏览器套件已被仓库刻意冻结，复活成本远超收益。
- **好测试的标准**：只测纯函数的外部行为（给定列定义/动作清单/分页状态，断言输出角色映射/显隐结果/状态迁移），不触 React 渲染、不依赖 @heroui-pro（与现有 checks 文件同约束，可在无 Pro token 的 CI 环境运行）。
- **被测逻辑**：① 卡片字段映射（位置约定、mobileRole 优先级、hide、列数不足、显式 title 挤占摘要位）；② 加载更多状态迁移（append、查询变更重置、加载完毕、追加失败保留）；③ 动作移动端显隐（toolbar 默认隐藏、行内默认保留、mobile:true/false 翻转、批量条关闭）；④ 排序 Select 与 SortState 的双向换算（含取消排序）。
- **先行例**：`synie-data-grid` 现有 grid-checks.ts（nextSort/cellText/mergePick 纯函数断言）与 `run-checks.ts` 汇总模式，新文件完全照此形制。
- **渲染壳验证**：matchMedia 分支、Sheet 弹层、卡片排版等视觉面为哑代码，靠开发期移动视口（DevTools 375px）手动验证，不进自动化。

## Out of Scope

- `synie-editable-table`（建单/录入表格）的移动端适配——建单编辑回桌面。
- 扫码查物料（相机调起、条码识别）。
- PWA、离线缓存、推送、原生壳等独立移动端形态。
- 浏览器级移动端 e2e 基建（Playwright 浏览器套件维持冻结）。
- 横屏平板（≥1024px）专属布局——横屏平板走桌面表格形态，竖屏平板走卡片模式。
- 卡片流虚拟滚动——「加载更多」append 语义下首屏数据量可控，性能问题出现再说。
- 移动端建单/编辑的任何入口（含「手机上也能建简单单」的变体）。

## Further Notes

- 本规格是 ADR `docs/adr/2026-07-29-mobile-card-mode.md` 的执行面，决策树与被拒方案以 ADR 为准；实现中发现偏离 ADR 处须先回改 ADR 或补新 ADR。
- 卡片字段约定与页面 `columns` 顺序强耦合：页面调整列顺序会改变卡片标题/副标题归属，回归检查时应顺带过一眼移动端呈现。
- 详情抽屉在小屏全屏是既有行为，本特性不为抽屉新增任何代码；若后续抽屉在窄屏出现布局问题（表单栅格挤压），属抽屉自身的适配工单，不在本规格。
