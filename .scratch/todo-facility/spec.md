# Spec: 待办设施（对账→开票提醒）

**Status:** done
**Feature slug:** `todo-facility`
**ADR:** [docs/adr/2026-07-25-todo-facility.md](../../docs/adr/2026-07-25-todo-facility.md)
**Domain terms:** 销售对账单、采购对账单、对账类型、客户确认、供应商确认、已对账数量、发票、对手、权限码、工作流动作（见 `CONTEXT.md`）
**Depends on:** 销售/采购对账（已交付）、发票台账（已交付）

---

## Problem Statement

常规对账单翻入「客户已确认」（销项）/「供应商已确认」（进项）后，直到发票审核结单前是一段**无可见性的真空期**：财务人员不知道哪张单该开票了，靠口头/微信传递，容易漏开、迟开；多人协作时也不知道别人是否已经在开。系统没有任何待办/通知设施，状态已经变了、该动手的人却收不到信号。

## Solution

引入轻量**待办**设施：对账单进入确认态时自动产生开票待办，对「可见该公司 + 持发票创建权限」的用户可见；发票审核结单时待办自动关闭。待办是**从源单据状态推导的派生提醒**（物化存储），不引入流程引擎、无指派/截止/优先级/催办。第一期覆盖销项开票 + 进项收票两个镜像场景。用户在顶栏铃铛看到未读徽标，进待办菜单处理：点跳转源单据、标记已读、个人忽略（状态变化自动复位）。

## User Stories

1. As a 财务人员, I want 销售对账单客户确认后在我的待办里看到「请开票」, so that 不用等别人通知
2. As a 财务人员, I want 采购对账单供应商确认后看到「请收票」, so that 进项票及时入账
3. As a 财务人员, I want 只看到我有权限（可见该公司 + 能开发票）的待办, so that 列表不夹杂我管不了的事
4. As a 财务人员, I want 任一人开出关联发票并审核后待办对所有人消失, so that 不重复开票
5. As a 财务人员, I want 有人已建草稿发票关联时待办仍显示但带「草稿关联中」徽标, so that 我知道别撞车但待办不提前消失
6. As a 财务人员, I want 对账单被撤回确认后待办消失, so that 不误导我去开一张已撤回的票
7. As a 财务人员, I want 发票作废/红冲把对账单退回确认态时待办自动复活, so that 纠错后重新开票不被漏掉
8. As a 财务人员, I want 待办行显示类型/对账单号/对手/公司/金额/产生时间, so that 一眼判断优先级
9. As a 财务人员, I want 点待办跳转到对应对账单, so that 直接走开票流程
10. As a 财务人员, I want 顶栏铃铛显示未读数徽标, so that 挂着页面也能发现新待办
11. As a 财务人员, I want 铃铛下拉出最近几条待办, so that 不进页面就能快速处理
12. As a 财务人员, I want 独立待办菜单进完整列表（活跃 + 历史 tab）, so that 能翻全量和已关闭记录
13. As a 财务人员, I want 点开待办即标记已读, so that 未读徽标准确
14. As a 财务人员, I want 对某条待办点「忽略」只从我列表清掉, so that 我管不了的不占我视线
15. As a 财务人员, I want 忽略的待办在源单状态变化（撤回→重新确认）时自动复位, so that 不会永久漏掉
16. As a 财务人员, I want 已关闭的待办进历史可查, so that 能追溯哪天开的票
17. As a 财务人员, I want 别人确认对账单时我的铃铛即时亮（在线推送）, so that 不靠刷新
18. As a 财务人员, I want 离线后进页面拉取到完整待办, so that 推送丢了也有兜底
19. As a 系统, I want 待办随源单据同事务产生/关闭, so that 待办与单据状态永不失同步
20. As a 管理员, I want 待办不设独立权限码、不设独立菜单门槛, so that 不用额外配置授权
21. As a 系统, I want 待办不反向驱动单据状态、不做审批流, so that 与既有硬编码状态机正交

## Implementation Decisions

### 数据模型

- 新建**待办表**（`sys_todo`），物化存储、同事务写/关（同已发/已收/已对账数量投影先例）。字段：`id`、`type`（枚举：开票/收票）、`source_type`+`source_id`（多态引用源单据，同 GL poly-ref 先例，无真外键）、`company_id`、`party_type`+`party_id`（对手快照）、`amount`（对账单本币合计快照）、`status`（active/closed）、`created_at`/`closed_at`、`created_by`（触发动作的操作人）。
- 新建**待办用户痕迹表**（`sys_todo_state`），存个人交互：`(todo_id, user_id)` 唯一，字段 `read_at`、`dismissed_at`、以及**复位基准**（源单最近一次状态变化时点，用于忽略自动复位）。活跃待办默认无痕迹行；已读/忽略时 upsert。
- 两表均不落金额币种（取对账单本币合计单一快照，与报表聚合读本币口径一致）。

### 产生与关闭（生产者）

- **销项**：常规销售对账单 `confirm` 动作同事务写待办（type=开票）。**进项**：常规采购对账单 `confirm` 动作同事务写（type=收票）。赠送/样品单无确认态、不产生待办。
- **关闭**：发票审核关联对账单结单时，同事务把对应该对账单的活跃待办置 closed。
- **消失（撤回）**：对账单 `unconfirm`（撤回确认）同事务把活跃待办置 closed（不留 active 痕迹）。
- **复活**：发票作废/红冲把对账单退回确认态时，同事务新建一条 active 待办（与原已关闭待办并存，原记录留历史）。复活的待办对所有曾忽略它的用户**复位**（dismissed 痕迹按源单状态变化时点判定失效）。
- 一张对账单同一时刻至多一条 active 待办（部分唯一索引兜底）。

### 可见性（权限圈人）

- 待办不设独立权限资源码、菜单无权限门槛（先例：收发货历史 `scm_order_flow_item`）。
- 列表/徽标查询按当前用户过滤：可见该公司（公司授权）且持发票创建权限（`acc.vat_invoice:create` 或上级通配）。超管全见。
- 「草稿关联中」徽标：派生展示（查询该对账单是否存在草稿态关联发票），不落库、不进待办表（同「已下单」徽标先例）。

### 用户交互

- **已读**：点开待办详情/跳转即 upsert `read_at`；未读数=活跃且未忽略且未读。
- **个人忽略**：`dismiss` 动作 upsert `dismissed_at`；仅影响本人。源单状态变化（复活/新待办）时痕迹按复位基准失效。
- **跳转**：待办行带源单据路由，点击进对账单抽屉/详情。
- **历史**：closed 待办保留可查（历史 tab），含关闭时点与触发来源。

### 前端

- **顶栏用户区铃铛**（外观切换/用户菜单同区）：未读数徽标 + 下拉最近 N 条 + 「查看全部」入口。
- **独立待办菜单**：完整列表，活跃/历史双 tab；行内显示类型、对账单号、对手、公司、金额、产生时间、已读态、草稿关联中徽标、忽略操作。
- **刷新**：Phoenix PubSub 推送「戳」（type + company + 计数增量），在线前端收到后拉详情刷新徽标；进页面/点铃铛时拉取兜底。复用现有 `SynieWeb.PubSub` 与 Ash notifier 视图广播通道。

### 权限与登记

- 不新增权限资源码；待办读写走「圈人」派生逻辑。authz 矩阵补：待办列表/痕迹按圈人口径可见性断言。

## Testing Decisions

- **主接缝**：`synie_core` Ash 资源集成测试（真库沙箱），对标 `sales/reconciliation_test.exs`、`purchase/reconciliation_test.exs` 与 `demand-purchase-linkage` 的投影/回写测试；只测外部行为（待办产生/关闭/复活、状态、校验、权限过滤结果），不断言内部结构。
- **必覆盖场景**：
  - 销项确认 → 产生开票待办；进项确认 → 产生收票待办；赠送/样品单不产生
  - 发票审核结单 → 待办关闭；草稿发票关联 → 不关闭 + 草稿关联中徽标可见
  - 撤回确认 → 待办消失；发票作废/红冲退回确认 → 待办复活且忽略复位
  - 权限圈人：无发票创建权限/无公司授权的用户看不到对应待办；超管全见
  - 已读/未读计数；个人忽略只影响本人；忽略后复活自动复位
  - 历史：closed 待办可查
  - 同事务：对账单动作失败时待办不产生（原子性）
- **前端**：铃铛徽标与列表走组件/e2e，本规格不强制（前端为薄可视层，主逻辑在后端投影与查询）。

## Out of Scope

- 流程引擎 / BPMN / 审批链（ADR 已定案，待办≠流程）
- 手工待办（无源单据的纯文本待办，另一物种，将来单独立项）
- 对向发票待补科目、履约需求单确认等其他提醒场景（语义有分叉，排队二期）
- 待办的指派、截止时间、优先级、催办、评论
- 邮件/钉钉/微信等站外通知通道
- 待办的全文搜索与复杂筛选（第一期按时间倒序 + 类型/tab 过滤）
