# 04 — 待办查询 API 与用户痕迹

**What to build:** 让待办可被前端消费——提供待办列表（活跃/历史）、未读计数查询，按**权限圈人**过滤（可见该公司 + 持发票创建权限，超管全见），不设独立权限资源码、菜单无权限门槛（先例：收发货历史）。用户痕迹动作：**已读**（点开待办详情/跳转即 upsert read_at，未读数=活跃且未忽略且未读）；**个人忽略**（dismiss 动作 upsert dismissed_at，仅影响本人）；**忽略自动复位**（源单状态变化/待办复活时，按复位基准时点判定痕迹失效，用户重新看到）。历史 closed 待办可查（含关闭时点与触发来源）。演示：GraphQL 查询返回圈人后的待办列表与未读数；标记已读/忽略生效；对账单撤回→重新确认（复活）后曾被忽略的待办重新出现。
